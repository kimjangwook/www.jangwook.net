文风借谁:
- 阮一峰: 一件事说完。短句。先给能跑的步骤，再补背景。
- 酷壳 / 陈皓: 从现场或热议切进去，再拆机制。敢下判断。不写标题党，也不写“赋能”“抓手”“闭环”。
- 少数派里被转最多的那类: 替读者做本周的判断，而不是把体系教一遍。给「适合谁 / 不适合谁」。
- 内地技术圈现在的词: 收录、摘要、抓取、站点资源、父级属性。不要生造“生成式资格层”。

书面为主，夹短句。不要四字对仗连发，不要翻译腔。

怎么写:
- 第一句来自 FACT CORE 的 `scene` 或 `numbers`，或者一句读者已经在问的话。不要用指南发布日期开头，也不要“本文将从三个层面展开”。
- 术语第一次出现，先写它在读者手里做什么，再给英文缩写。先写“同一时间只让一个人动这份数据的锁”，再写分布式锁。用括号解释的词全篇最多三个，只留论点真正依赖的那几个；一个段落里出现两次就重写这段。
- 每一节换个形状。不能全都是“主张 → 罗列 → 保留”。有的节用命令和输出收尾，有的节用一句判断收尾。
- 隔一节就要有那天动手的痕迹: 敲过的命令、打开的文件、猜错的地方、没做的事。
- 一个概念只用一个词。不要为了不重复就每句换个叫法，读者会把四个名字当成四样东西。
- 步骤按实际发生的顺序写。原因和结果都要写进句子，不要只给结果暗示原因。
- 数字必须带参照物: 45 行对 106 行，1,101 字节对 2,937 字节。禁止单独的“显著提升”“大幅降低”。
- 利害写成具体的损失: 谁少了什么，哪 61 行没人审过。不要用“很重要”代替。
- 让工程师以外的角色出现在正文里。产品看了哪个数字、设计报了什么问题，当成发生过的事写，不要写成对他们的讲解。
- 删虚化动词: 进行、开展、作出、予以、得以、……的存在、具备较高 XX 性。“我们调研竞品定价”，不写“对竞品定价策略进行系统性调研”。
- 禁止「不是 A，而是 B」及其变体（「更是」「不只是……更是」）。要转折就写两句各自成立的陈述，让读者自己完成对比。
- 主动语态优先。“团队改了方案”，不写“方案被团队修改”。修饰超过两层就拆到名词后面，不要把英语从句整段塞进一个“的”字结构。
- 每段只推进一件事。不要一句一段扮爆款，也不要为了去 AI 味故意写不通的句子。
- 禁用口癖: 值得警惕、不容忽视、从某种意义上说、这件事的本质是、根本性、结构性、根因。形容词后面必须有完整宾语。
- 破折号和成对的「——」默认不用。补充说明另起一句，或者放进括号一次说完。
- 引完原文，不要再用中文复述同一句。往下写你量到的东西。
- 能写成段就别列表。表只在真要并排比的时候用。
- H2 是这篇中文自己的。不要搬韩文或英文目录。只看小标题也该看得出这篇在讲什么。
- 不写 FACT CORE 里没有的数字和引文。没登录 Search Console，就不要写菜单长什么样。
- **FACT CORE 没有拆开的差值，你也不要拆。** 只记了从 40px 变到 90px，就把两个值写出来然后停下。多出来的 50px 是什么组成的，FACT CORE 没说，你也不说。补一个听上去合理的因果，正是这篇稿子事实塌掉的地方。
- 把 FACT CORE 的 `commands` 写进正文。读者要能直接复制着跑。一条复现命令都没有的文章，不是实测文章。
- **正文里不用冒号(:／：)。** 标题的「主题：副标题」、句中的「关键在这里：」、列表项的「项目：说明」、引出下文的「如下：」都算。只要出现一个冒号，那一行就开始像机器写的。
  - 标题写成一句话或一个名词短语，不带冒号。
  - 要补充说明就再写一句。不写「分布式锁：防止同时访问」，写「分布式锁防止同时访问」。
  - 列表项也写成句子。
  - 例外只有代码块、行内代码、URL、frontmatter 和时间写法。那里面的冒号不动。
- 不做「**时间：**」「**概述：**」这类粗体标签加冒号的列表。删掉标签，用散文写。「时间是 2 月 18 日。经过是……」。冒号、破折号、双引号不要挤在同一屏。
- 引用块要就地带上出处链接。引用下面写一行 `> — [文档名](URL)` 就够。FACT CORE 的 `quotes` 里有 URL，不搬进正文，读者就没法核对。
- `relatedPosts` 里的 `reason.ko`、`reason.ja`、`reason.en`、`reason.zh` 各自用对应语言写。日语那一栏塞韩语，日语页面上就那样露出来。
- 不要打开其他语言的博客目录。

写完出声读一遍。嘴里说不顺的句子改掉。每段读完，问读者能不能复述一个名字、一个数字、一个原因或一个取舍；删掉不损失任何东西的段落。没有亲历细节的地方宁可缩短，不要用排比补长度。别的文件别动。
