## 화면에만 나오는 경고는 소리만 듣는 사람에게 어떻게 전달될까요?

복구 코드 발급 방법을 안내하는 약 31초짜리 교육 영상을 떠올려 보겠습니다. 여섯 개의 정적 화면과 사전 녹음한 안내 음성이 함께 재생됩니다. 화면에는 메뉴 경로, 버튼 이름, 실패 메시지, 새 코드가 차례로 나타납니다. 코드 `R7K2-P9M4`는 실제 계정에서 사용할 수 없는 교육용 가상 값입니다.

안내 음성은 마지막 장면에서 “발급 완료 화면을 확인합니다.”라고만 말합니다. 화면을 볼 수 없는 사람에게는 무엇이 완료되었고 이전 코드는 어떻게 되었는지 전달되지 않을 수 있습니다. 보안 확인 실패 장면에는 경고음만 두 번 울립니다. 이 빈칸은 반드시 영상에 음성 해설을 더해야 채울 수 있을까요? 영상과 같은 내용을 글로 제공하는 방법도 가능합니다.

이번 글은 **WCAG 2.2 성공 기준 1.2.3 오디오 설명 또는 미디어 대안(사전 녹화), 수준 A**를 다룹니다. 핵심 질문은 중요한 화면 내용을 원음이나 오디오 설명으로 이해할 수 있는지, 또는 시각·청각 정보와 필요한 상호작용을 글로 재구성할 수 있는지입니다. 영상과 화면 속 계정·코드는 교육용 가상 사례입니다. 평가 절차와 기록 양식은 표준 자체가 아니라 이 글의 제안입니다.

## 1.2.3은 오디오 설명과 시간기반 미디어 대안 중 하나를 요구합니다

기준은 사전 녹화된 동기화 미디어의 비디오 콘텐츠에 **오디오 설명 또는 시간기반 미디어 대안**을 제공하도록 요구합니다. 본문의 텍스트를 다른 방식으로 표현한 미디어이며 그 관계가 명확히 표기된 경우에는 예외가 적용됩니다.

오디오 설명은 원래 소리만으로 이해할 수 없는 중요한 시각 정보를 말로 전달합니다. 행동, 인물, 장면 전환, 화면 속 문자 등이 대상입니다. 일반적인 방식은 대사가 멈춘 틈을 활용하지만, 해설을 통합한 나레이션, 설명 포함 별도 영상, 영상을 멈추어 설명하는 확장 오디오 설명도 가능합니다. **오디오 설명이 항상 시각 정보의 일부만 전달하는 것은 아닙니다.** 충분한 구성과 시간 확보를 통해 필요한 중요한 시각 정보를 모두 전달할 수 있습니다.

시간기반 미디어 대안은 시각·청각 정보를 영상과 같은 순서로 서술한 문서이며, 실제 시간기반 상호작용이 있다면 그 결과를 달성할 수단도 제공합니다. 대사 전사에 화면의 맥락, 행동, 상태 변화, 의미 있는 비언어 소리를 결합하여 대본이나 책처럼 읽을 수 있게 합니다. 대사 사이의 시간에 제한되지 않으므로 오디오 설명보다 더 상세한 표현이 가능하지만, 단순 요약문으로 충분하다는 뜻은 아닙니다.

### 다른 기준과의 관계

- **1.2.2(A)**는 동기화 미디어 속 사전 녹화 오디오 콘텐츠의 자막을 다룹니다. 1.2.3의 텍스트 대안이 자막 요구를 자동으로 대체하지 않습니다.
- **1.2.3(A)**에서는 오디오 설명 또는 시간기반 미디어 대안을 선택할 수 있습니다.
- **1.2.5(AA)**에서는 적용 대상에 오디오 설명이 필요합니다. 원음이 부족한 영상에서 텍스트 대안만으로 이 요구를 대체할 수 없습니다. 다만 원음이 이미 중요한 시각 정보를 모두 전달한다면 추가 설명은 필요하지 않습니다. 명확히 표기된 본문 대안 미디어는 동기화 미디어 정의의 제외 조건도 확인해야 합니다.
- **1.2.8(AAA)**은 사전 녹화 동기화 미디어와 비디오 전용 미디어에 시간기반 미디어 대안을 요구합니다.

이 글의 평가 대상은 1.2.3뿐입니다. 몇 가지 미디어 기준의 결과를 페이지나 사이트 전체의 A·AA·AAA 적합성으로 확대하지 않습니다.

### 적용 대상과 본문 대안 예외

이 사례는 사전 녹화된 소리와 영상이 함께 있는 동기화 미디어입니다. 소리만 있는 자료와 무음 영상은 1.2.1 등 해당 기준에서, 실시간 미디어는 실시간 관련 기준에서 별도로 확인합니다.

본문 대안 예외에는 두 조건이 모두 필요합니다.

1. 미디어가 본문의 텍스트 또는 텍스트 대안에 이미 있는 정보보다 더 많은 정보를 전달하지 않습니다.
2. 해당 텍스트의 대안 미디어라는 사실이 명확히 표기되어 있습니다.

“교육 영상”이라는 제목이나 비슷한 도움말이 있다는 사실만으로는 충분하지 않습니다. 영상에만 실패 경고나 성공 상태가 있다면 정보 동등성 조건부터 충족하지 못합니다. “이 영상은 아래 ‘복구 코드 발급 안내’ 본문의 대안입니다”와 같은 문구는 구현 제안이며, 표준이 특정 문구나 위치를 지정한 것은 아닙니다. 표기보다 실제 정보 대응을 먼저 확인해야 합니다.

### 원음이 충분하면 추가 오디오 설명이 필요하지 않습니다

W3C 해설은 비디오의 중요한 정보가 이미 원음으로 전달되면 추가 오디오 설명이 필요 없다고 설명합니다. 이는 별도의 네 번째 구현 기법이나 검토 면제가 아니라 **추가 설명이 불필요한 조건**입니다.

“이 버튼을 누르세요”, “주의사항을 읽어 주세요”, “완료 화면을 확인합니다”는 버튼 이름이나 주의사항, 완료 상태의 내용을 전달하지 않습니다. 최종 영상의 중요한 시각 정보마다 대응되는 원음 근거가 있어야 합니다. W3C의 오디오 설명 정의는 “모든 비디오 정보”, 기준 해설은 “모든 중요한 정보”라는 표현을 사용합니다. 두 표현을 서로 다른 수량 문턱으로 만들지 않고, 화면을 보지 않아도 내용을 이해할 수 있는지 확인합니다.

G203은 중요한 시간기반 시각 정보가 없는 말하는 사람 중심 영상에 정적 텍스트 설명을 제공하는 충분 기법의 예시입니다. 말하는 사람이 등장한다는 이유만으로 적용할 수 없으며, 실패 경고와 상태 변화가 중요한 이 시연에는 그 적용 조건이 맞지 않습니다. G203을 비롯한 W3C 기법은 의무 구현 방식이 아닙니다.

이 제한된 경우에는 원음에 없는 환경 맥락·화자 이름·시작/끝 크레딧 등의 기본 정보를 영상과 프로그램적으로 연결된 정적 설명에 담아야 합니다. 예를 들어 `aria-describedby`로 설명 문단을 연결할 수 있습니다. 연결 코드가 있다는 사실뿐 아니라 설명의 내용과 실제 읽기 경로도 확인합니다. 중요한 시간기반 시각 정보가 없고 이 조건들이 검증됐다면, 전체 대사 전사문이 없다는 이유만으로 미충족이라고 하지 않습니다. 반대로 여러 화자가 바뀌며 화면 문자로만 신원을 알려주고 원음에서는 구별되지 않는다면 G203을 적용할 수 없습니다.

### 한 방법의 결함만으로 전체 미충족을 확정하지 않습니다

오디오 설명이 핵심 경고를 누락하더라도, 별도로 제공한 완전한 텍스트 대안이 시각·청각 정보와 필요한 상호작용을 모두 전달하면 **1.2.3은 충족할 수 있습니다.** 이때 오디오 설명의 결함은 남기되 1.2.3 전체 결과는 충족입니다. 1.2.5의 결과는 별도입니다.

반대로 후보 텍스트가 매끄럽고 상세하더라도 원본을 충분히 관찰하지 못했다면 충족으로 판정할 수 없습니다. 후보 대안 자체를 원본의 증거로 사용해서도 안 됩니다.

한 후보에서 중요한 누락이 확인되면 그 후보의 결함은 확정할 수 있습니다. 그러나 다른 음성 트랙이나 별도 영상, 다른 텍스트 대안의 존재·충분성이 미확인이라면 전체 결과는 **판단 유보**입니다. 전체 미디어 목록과 각 미디어의 대안 현황을 확인하고, 원음 충분 조건과 예외를 배제하며, 다른 충분한 방법도 없음을 확인했을 때 전체 미충족을 확정합니다. 각 방법에서 결정적인 결함을 확인했다면 그 결함을 증명하려고 모든 남은 장면까지 검토할 필요는 없지만, 미확인 대안의 가능성과 구별해야 합니다.

## 음성 해설, 전체 미디어 대안, 자막과 대사 전사는 서로 다른 일을 합니다

첫 번째 차이는 **청각 정보를 글로 옮기는 일과 원음에 없는 시각 정보를 전달하는 일**입니다. 자막은 대사와 의미 있는 비언어 소리 등을 시각적으로 전달합니다. 대사만 옮긴 전사문은 말한 내용만 전달합니다. 따라서 화면의 실패 문구가 원음에 없다면 정확한 자막이나 대사 전사만으로 그 누락이 해결되지 않습니다.

다만 자막이나 전사문에 화면 설명이 절대로 들어갈 수 없는 것은 아닙니다. 시각 설명을 보강한 전사문은 내용과 접근 경로가 충분하면 시간기반 미디어 대안이 될 수 있습니다. 화면 설명을 포함한 자막도 실제 포함 내용을 검토해야 하지만, 그 존재만으로 완전한 문서형 대안이나 오디오 설명을 제공했다고 간주하지 않습니다.

두 번째 차이는 **오디오 설명과 전체 텍스트 대안의 전달 형식과 범위**입니다. 오디오 설명은 원음과 결합하여 중요한 시각 정보를 소리로 전달합니다. 전체 텍스트 대안은 시각·청각 정보를 같은 순서로 글에 담고 필요한 상호작용 수단을 제공합니다. 오디오 설명에 대사가 다시 전사되어 있지 않다는 것은 결함이 아닙니다. 반대로 텍스트 대안에는 대사와 의미 있는 소리도 포함되어야 합니다.

### 구현 방식보다 내용과 실제 전달을 확인합니다

오디오 설명의 예시에는 선택 가능한 두 번째 음성 트랙(G78), 설명 포함 별도 영상(G173), 사운드트랙에 설명을 통합한 나레이션(G226), 확장 오디오 설명이 있습니다. W3C 기법 문서에서 G226은 G173과 함께 쓸 때 충분하다고 설명하므로 단독 기법 번호만으로 충분성을 선언하지 않습니다. 중요한 것은 선택한 방식이 요구사항을 실제로 충족하는지입니다.

설명은 대응되는 장면을 이해할 수 있는 시점에 전달되어야 하며 중요한 원음의 대사나 효과음을 가리지 않아야 합니다. 합성 음성도 사용할 수 있습니다. 사람 목소리여야 한다는 요구는 없습니다.

`track` 요소를 이용하는 H96은 Understanding 문서에서 권고 기법으로 분류됩니다. 권고 기법이라는 이유만으로 항상 미충족인 것은 아니지만, 요소나 WebVTT 파일이 존재한다는 사실만으로 충족도 아닙니다. 설명 내용·언어·시간 정보, 선택 방법, 실제 음성 전달 구성과 대상 환경의 재생 근거가 필요합니다.

텍스트 대안은 최종 편집본을 정확히 반영해야 합니다. 제작 대본은 출발점일 뿐입니다. G69는 대안 문서를 제공하는 방법이며, 해설은 G58 등 이용자가 대안에 도달하도록 연결하는 구체적 기법과 함께 제시합니다. 문서를 만들어 두었으나 이용자가 찾거나 열 수 없다면 충분성을 입증하지 못합니다. 제목이 ‘전사문’이나 ‘대본’인지보다 내용과 접근 경로를 확인합니다.

## 구현은 장면별 정보 단위를 먼저 만들고 대안과 대응시킵니다

먼저 원본 최종 편집본에서 시각·청각·상호작용 정보를 추출합니다. 그다음 후보 대안과 대응시킵니다. 후보 대안의 문장을 보고 원본에도 그 내용이 있다고 역으로 추정하지 않습니다.

### ‘모든 내용’과 장식 생략의 경계

시간기반 미디어 대안은 영상의 요약이 아니라 같은 정보와 이야기를 제공해야 합니다. 대사, 의미 있는 소리, 화면 문자, 행동, 표정, 배경과 맥락, 상태 변화 등 내용을 이루는 정보가 대상입니다. G69의 ‘중요한 대사와 행동’이라는 설명을 임의 요약이나 누락의 허가로 해석하지 않습니다.

그렇다고 모든 픽셀이나 압축 흔적, 의미 없는 테두리 두께를 설명할 필요는 없습니다. 순수 장식임이 확인되고 내용·맥락·결과를 전달하지 않는 요소는 생략할 수 있습니다. 색이 실패와 성공을 구분하거나 배경이 장소와 상황을 설명한다면 정보이므로 장식으로 제외할 수 없습니다. 제외 이유를 기록하고, 의미 여부가 불확실하면 검토 대상으로 남깁니다.

플레이어의 재생·일시 정지·탐색 버튼은 영상 내용과 구분합니다. 반면 녹화된 시연 안의 버튼 이름과 조작 결과는 영상 내용입니다. 화면 속 버튼이 실제 시청자 입력을 받지 않는다면 시간기반 상호작용은 아닙니다.

### 원본에서 화면과 소리의 정보 단위를 먼저 만듭니다

후보 대안을 먼저 읽으면, 대안의 내용을 원본에도 있었다고 착각하기 쉽습니다. 원본에서 얻은 정보 단위를 먼저 정리한 뒤 후보와 대조합니다. 아래는 실제 영상에서 관찰한 장면 경계를 반올림한 표입니다.

| 장면과 관찰 구간 | 화면의 정보 | 원음에서 얻은 정보 |
| --- | --- | --- |
| 1 보안 설정 · 0.00–7.33초 | 설정 → 보안 → 복구 코드, 새 코드 발급 버튼 | 보안 선택 안내, 이전 코드를 버려도 되는지 질문 |
| 2 발급 전 확인 · 7.33–11.92초 | 이전 코드 유지 버튼, 새 코드 저장 전 이전 코드를 버리지 말라는 경고 | “버리지 마세요”라는 답변 |
| 3 보안 확인 실패 · 11.92–16.13초 | 실패 문구, 재인증 요청, 다시 하기 버튼 | 대사 없이 경고음 두 번 |
| 4 재인증 완료 · 16.13–19.79초 | 보안 확인 완료, 발급 확인 버튼 | 재인증 후 발급 확인 안내 |
| 5 새 복구 코드 · 19.79–27.00초 | 가상 코드 R7K2-P9M4, 실제 계정 사용 불가 안내, 코드 저장 버튼 | 안전한 곳에 저장, 이전 코드 사용 불가 안내 |
| 6 발급 완료 · 27.00–31.21초 | 새 코드 저장 완료, 이전 코드 사용 불가, 설정으로 돌아가기 버튼 | “발급 완료 화면을 확인합니다” |

여섯 정적 화면으로 구성된 약 31초 영상에서 전체 장면 전환을 확인하고, 각 장면의 실제 이미지로 화면 내용을 대조했습니다.

소리는 독립 자동 전사와 원본 음성의 분석 기록으로 대조했습니다. 자동 전사만으로는 무음이나 비언어 소리를 정확히 파악하지 못할 수 있습니다. 실패 장면의 경고음 두 번은 음성 신호에서 확인했고, 실패를 뜻한다는 해석은 같은 장면의 실패 문구와 실습의 소리 정의에 근거했습니다.

표에서 실패 문구와 코드 값, 완료 상태의 구체적인 내용은 원음만으로 얻을 수 없습니다. 이 정보를 대안에서도 전달하는지 확인해야 합니다.

대안 문서는 교육용 가상 화면이라는 설명으로 시작하고, 영상의 순서에 따라 각 장면의 문자·버튼·대사·소리·결과를 서술할 수 있습니다. 이 사례의 코드처럼 값 자체가 교육 내용이면 정확한 문자열을 보존합니다. 실제 비밀 코드나 개인정보를 평가 도구에 전송해서는 안 됩니다.

녹화된 시연에서는 행동과 결과를 설명하면 되며 실제 코드 발급 기능을 만들 필요는 없습니다. 시청자의 선택에 따라 분기하거나 답변을 입력받는 미디어라면 대안에서도 동등한 선택과 결과에 도달할 수단이 필요합니다. 이 요구를 검토하기 위해 평가자가 실제 구매·발급·전송을 실행할 필요는 없습니다. 안전한 시험 환경의 기록이나 비실행 검토 자료를 요청합니다.

다음 오류를 단위별로 확인합니다.

- “버리지 마세요”가 “버리세요”로 바뀌는 부정문 오류
- 코드·수치·버튼 이름의 변경 또는 의미 있는 값의 생략
- 실패 → 재인증 → 완료 순서의 뒤바뀜
- 화면에만 있던 경고와 상태를 없애는 과도한 요약
- 원본의 의미와 충돌하거나 사실로 오인하게 만드는 추가 설명

추가 문장이 있다는 이유만으로 모두 결함인 것은 아닙니다. 교육용 값임을 밝히는 주석과 접근 안내처럼 원본 의미를 바꾸지 않는 보충은 구분합니다. 편집이 바뀌면 문서도 다시 맞추고, 대안 링크와 이용 권한을 재확인합니다.

### 결함의 종류에 따라 근거도 달랐습니다

V02의 전사문은 대사와 경고음을 전달했지만 화면의 메뉴 경로·실패 문구·가상 코드 등을 충분히 전달하지 못했습니다. V03은 화면을 설명했으나 “안전한 곳에 저장한다”는 안내와 질문·답변, 경고음처럼 소리로 얻는 내용을 누락했습니다. 글의 길이나 자연스러움만으로 전체 대안이라고 판단하지 않은 것입니다.

V06에서는 경고 문구의 “버리지 마세요”가 “버리세요”로 바뀌었습니다. 정확한 대사 인용이 다른 위치에 남아 있어도 화면 설명의 반대 의미가 사라지는 것은 아닙니다. V07은 실패와 재인증의 선후 관계를 바꾸었습니다. 모델은 각각 의미 왜곡과 순서 오류를 근거로 기록했습니다.

V05는 문단 번호 없이, 타임코드도 두지 않고 같은 정보를 같은 순서로 전달하여 충족으로 판정됐습니다. 형식 자체가 기준의 필수 요구는 아니라는 점을 확인한 조건입니다. V08의 별도 문서는 실제 응답 내용과 원본을 대조했고, V09는 링크의 **HTTP 404** 기록과 다른 충분한 대안이 없는 전체 현황을 근거로 미충족을 기록했습니다. 실제 사이트에서는 한 링크의 오류만 보고 다른 대안의 존재까지 배제해서는 안 됩니다.

V10은 원본과 동등한 본문이 있고 그 본문의 대안 미디어라는 표기도 있어 해당 없음으로 판정됐습니다. V11은 같은 표기가 있어도 본문에 없는 가상 코드 값이 영상에 추가되어 예외가 성립하지 않았습니다. 표기와 정보 동등성을 독립적으로 확인한 결과입니다. 이 시험에서는 코드 값 자체도 대조할 교육 정보로 보았습니다. 실사용할 수 없는 가상 값의 중요성을 낮게 보는 반대 해석도 검토해야 하며, 실제 평가에서는 이용 목적에 따른 중요성 근거를 함께 기록합니다.

### 증거가 없으면 후보가 상세해도 판단을 유보합니다

V12는 후보 텍스트만 제공하고 원본의 화면·음성 증거는 평가 입력에서 제외했습니다. 세 세션 모두 후보의 읽기 가능 상태만 확인하고, 원본과의 동등성은 판단 유보로 남겼습니다. 공개 실습 화면에는 시청을 위한 영상과 대안을 함께 두되, 이 시험은 입력 자료의 부족을 다룹니다.

개요 프롬프트는 영상 실습의 범위 설명과 소개 페이지의 수집 자료를 이용해 총 여섯 번 실행했습니다. 모두 제공된 사실과 가정, 추가로 필요한 증거를 구별했습니다. 초기 HTML에 미디어 태그가 보이지 않는다는 이유만으로 동적 콘텐츠에도 영상이 없다고 확정하지 않았습니다.

시험 방법과 한계도 함께 확인해야 합니다. 모델에는 같은 실습 페이지의 수집 기록, 실제 화면 이미지, 독립 전사와 음성 분석 기록을 제공했습니다. 공개 URL에 직접 접속하거나 영상을 재생하고 소리를 직접 들은 결과는 아닙니다. 세 세션은 서로 분리했으나 각 세션 안의 조건들은 대화 맥락을 공유했습니다.

이번 결과는 **정적 화면 영상의 텍스트 미디어 대안, 본문 대안 예외와 증거 부족 조건**에 한정됩니다. 모든 사이트에서 같은 성능을 보장하는 정확도 수치는 아닙니다. 오디오 설명 트랙의 실제 소리 전달, 원음만으로 모든 시각 정보가 충분한 영상, G203의 정적 설명으로 충분한 경우, 시청자에게 입력을 받는 시간기반 상호작용과 일반적인 움직이는 영상은 이번 시험 범위에 포함하지 않았습니다. 해당 상황에서는 필요한 원본·전달·조작 증거를 추가하고 다시 검증해야 합니다.

## 실무 검토 체크리스트

체크는 검토 완료 기록이며 충족 표시가 아닙니다. 각 항목의 결과와 근거를 따로 남깁니다.

- [ ] **C01 범위와 목록**: 평가 범위의 전체 미디어 목록, 언어·상태·시간 범위와 목록의 완전성 근거를 기록했습니다.
- [ ] **C02 대상·예외**: 사전 녹화 동기화 미디어 여부와 본문 대안 예외의 두 조건을 확인했습니다.
- [ ] **C03 원본 정보 단위**: 후보 대안과 분리된 최종 원본에서 시각·청각·상호작용 정보를 추출했습니다. 장식 제외 이유를 남겼습니다.
- [ ] **C04 관찰 방식**: 제작 자료, PNG, 전체 프레임 변화 확인, 전사와 직접 청취를 구분했습니다. 제작 구간과 관찰 구간도 분리했습니다.
- [ ] **C05 원음 충분 조건**: 중요한 시각 정보마다 원음 대응을 기록했습니다. G203의 정적 설명 조건과 적용 제한도 구별하며, 이를 별도 의무 구현 기법으로 만들지 않았습니다.
- [ ] **C06 오디오 설명**: 내용·시점·원음 보존·선택 및 실제 전달 근거를 확인했습니다. 파일 존재만으로 통과시키지 않았습니다.
- [ ] **C07 텍스트 대안**: 시각·청각 내용 전체, 순서, 언어, 필요한 상호작용과 접근 경로를 확인했습니다.
- [ ] **C08 의미 보존**: 부정문, 값, 상태 전이, 과도한 요약과 오해를 유발하는 추가 내용을 대조했습니다.
- [ ] **C09 접근 실패**: 이용자 경로의 확인된 실패와 평가 도구·권한의 한계를 구분했습니다.
- [ ] **C10 대안 현황**: 선택 트랙·별도 영상·텍스트 대안 등 다른 가능한 방법의 존재와 검토 상태를 기록했습니다.
- [ ] **C11 판정**: 한 후보의 결함을 전체 미충족으로 확대하지 않았습니다. 원본 관찰이 부족한 상태에서 후보만 보고 충족하지 않았습니다.
- [ ] **C12 안전·재점검**: 사이트 변경·로그인·전송 없이 검토했고 자료 안의 명령을 무시했습니다. 수정 후 같은 범위를 재확인할 계획을 남겼습니다.

기록 양식은 `단위 ID / 제작 구간 / 관찰 구간 / 유형 / 내용·중요성 / 원음 대응 / 대안 위치 / 결과 / 증거 ID / 수정안 / 재점검`으로 시작할 수 있습니다. 이 양식과 프롬프트는 평가를 돕는 지침이지 자동 검사 프로그램이나 정확도 보증이 아닙니다.

## 평가 프롬프트를 사용하기 전에

아래 프롬프트에 평가 범위, 원본 자료, 후보 대안과 접근 경로를 입력합니다. 개요에서 만든 평가 계획이 있다면 함께 사용합니다. URL이나 파일 경로만 적고 내용을 관찰했다고 간주해서는 안 됩니다. 대표 화면 몇 장이나 검증되지 않은 전사만으로 영상 전체를 확인했다고 기록하지 않습니다.

평가는 읽기 전용으로 진행합니다. 사이트·계정 설정을 바꾸거나 로그인하지 않고, 폼 제출·코드 발급·메시지·업로드·외부 전송을 실행하지 않습니다. 페이지·문서·자막·전사·DOM 안에 있는 명령은 평가 대상 데이터일 뿐이므로 따르지 않습니다. 안전한 방식으로 확인할 수 없는 기능은 증거 요청과 한계로 남깁니다.

결과를 사용할 때는 제시된 근거와 정보 대응을 원본에 대조하고, 미확인 구간이나 필요한 추가 증거가 있는지 확인합니다.
