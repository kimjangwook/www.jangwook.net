## 소리를 듣거나 화면을 보지 못해도 같은 내용을 얻을 수 있어야 합니다

제품 지원 페이지에 음성 안내와 무음 조작 영상이 있다고 가정해보겠습니다. 음성 안내는 계정 복구에 필요한 준비물을 알려주고, 영상은 메뉴에서 복구 코드를 발급하는 순서를 보여 줍니다. 페이지에는 ‘계정 복구 안내’라는 제목과 ‘설정에서 코드를 발급하세요’라는 짧은 문장만 있습니다.

음성을 듣지 못하는 이용자는 준비물과 주의 사항을 놓칩니다. 화면을 보지 못하는 이용자는 어느 메뉴를 열고 무엇을 확인해야 하는지 알기 어렵습니다. 재생 버튼에 이름을 붙여도 이 문제가 해결되지는 않습니다. 버튼 이름은 어떤 매체를 재생하는지 알려주지만, 그 매체 안의 내용을 전달하지는 않기 때문입니다.

앞선 [대체 텍스트 글](/series/accessibility/non-text-content)은 비텍스트 콘텐츠의 목적을 어떻게 전달하는지 다뤘습니다. 이번에는 시간에 따라 펼쳐지는 내용을 다른 경로로 제공하는 방법을 살펴봅니다. 기준은 **WCAG 2.2의 1.2.1 Audio-only and Video-only (Prerecorded), 수준 A**입니다. 교육용 도식과 구현 예는 가상 사례입니다. 뒤의 프롬프트 검증에서는 실제 제작한 시험용 음성·무음 영상과 그 처리 기록을 사용하며, 실제 계정이나 복구 코드는 다루지 않습니다.

## 먼저 음성 전용인지, 영상 전용인지 구분합니다

1.2.1의 요구를 적용하려면 무엇을 검사하고 있는지 먼저 정해야 합니다. HTML의 태그 이름이나 파일 확장자만 보고 결정하면 실제 콘텐츠와 다른 기준을 적용할 수 있습니다.

| 확인한 콘텐츠 | 1.2.1에서 검토할 대안 | 다른 항목과의 구분 |
| --- | --- | --- |
| 사전에 녹음된 음성 전용 콘텐츠 | 같은 정보를 전달하는 시간 기반 매체 대안. 실무에서는 전사문으로 구현할 수 있습니다. | 음성을 화면에 맞춰 동기화한 자막만 요구하는 항목이 아닙니다. |
| 사전에 만들어진 영상 전용 콘텐츠 | 같은 정보를 전달하는 시간 기반 매체 대안 **또는** 음성 트랙 | 시각 정보의 텍스트 설명과 음성 설명 중 선택할 수 있습니다. |
| 영상과 음성이 함께 있는 사전 제작 매체 | 이 항목의 전용 매체 분류에 해당하지 않습니다. | 녹화 자막 1.2.2, 화면 해설 또는 매체 대안 1.2.3 등 해당 기준을 따로 검토합니다. |
| 실제 사건을 실시간으로 전달하는 음성·영상 | 사전 제작 매체를 대상으로 하는 1.2.1의 범위 밖입니다. | 실시간 자막 1.2.4, 실시간 음성 대안 1.2.9 등 적용 조건을 확인합니다. |

위 표는 평가할 기준을 고르는 안내입니다. 어떤 콘텐츠가 1.2.1의 범위 밖이라는 결론을 사이트의 접근성 충족으로 읽어서는 안 됩니다. 라이브 방송을 저장해 다시 제공한다면, 다시보기는 사전 제작 매체로 평가합니다.

소리가 있는 영상을 플레이어에서 음소거했다고 영상 전용 콘텐츠가 되지는 않습니다. 반대로 `.mp4` 파일이라는 이유만으로 영상과 의미 있는 음성이 모두 있다고 가정할 수도 없습니다. 원본의 트랙 정보와 실제 내용을 함께 확인합니다. 듣지 않은 오디오 채널을 ‘빈 채널’이라고 단정하지 않습니다. 음성 안내에 고정된 표지 이미지가 붙은 경우도 화면에서 그 이미지가 별도의 정보를 전달하는지 살펴봅니다.

애니메이션이나 연속되는 그림도 시각 정보를 시간에 따라 전달할 수 있습니다. 짧은 GIF이거나 반복 재생된다는 이유만으로 대상에서 제외하지 않습니다. 단순 장식인지, 작업 순서나 상태 변화를 알려주는지에 따라 검토할 내용이 달라집니다. 이용자의 선택에 따라 내용이 갈라지는 매체는 분기와 상호작용까지 범위를 정해야 하며, 한 번 재생한 경로로 전체를 평가할 수 없습니다. 일반적인 재생·일시 정지 버튼과 콘텐츠 자체의 분기는 구별합니다.

## 음성 전사문에는 말뿐 아니라 이해에 필요한 소리도 담습니다

전사문을 작성할 때는 최종 녹음이 정본입니다. 녹음 전에 만든 대본을 그대로 올리면 진행자가 추가한 조건, 질문과 답변, 편집 후 남은 설명이 빠질 수 있습니다. 자동 음성 인식으로 만든 문장도 원본을 대조할 재료로 사용합니다.

다음은 30초 분량의 가상 계정 복구 안내입니다.

| 원본에서 전달한 내용 | 불충분한 대안 | 목적에 맞게 보완한 전사문 |
| --- | --- | --- |
| 진행자가 ‘기존 기기에 로그인한 상태에서만 복구 코드를 발급할 수 있습니다’라고 말합니다. | ‘설정에서 복구 코드를 발급합니다.’ | 진행자: 기존 기기에 로그인한 상태에서만 복구 코드를 발급할 수 있습니다. |
| 질문자가 ‘발급하면 기존 코드는 어떻게 되나요?’라고 묻고 담당자가 ‘이전 코드는 사용할 수 없습니다’라고 답합니다. | 질문·화자 없이 ‘기존 코드를 확인합니다.’ | 질문자: 발급하면 기존 코드는 어떻게 되나요? 담당자: 이전 코드는 사용할 수 없습니다. |
| 확인음이 들린 뒤 담당자가 ‘이 소리가 나면 발급이 끝난 것입니다’라고 말합니다. | ‘발급이 끝납니다.’ | [짧은 확인음] 담당자: 이 소리가 나면 발급이 끝난 것입니다. |

이 예의 문제는 문장 수가 적다는 데 있지 않습니다. 로그인이라는 전제, 이전 코드의 무효화, 완료를 알아보는 단서가 사라졌다는 데 있습니다. 설명을 간결하게 다듬더라도 이 정보는 남겨야 이용자가 같은 판단을 할 수 있습니다.

여러 사람이 말한다면 누가 묻고 누가 답하는지 구분합니다. 웃음이나 배경음도 내용 이해에 영향을 줄 때 설명합니다. 모든 소리에 긴 묘사를 붙이는 방식은 읽기 부담을 늘릴 수 있으므로, 원본에서 그 소리가 어떤 의미를 전달하는지 먼저 확인하는 편이 좋습니다.

‘전사 정확도 98%’ 같은 수치를 합격선으로 정하지 않습니다. 부정어 하나가 빠져 ‘사용할 수 없습니다’가 ‘사용할 수 있습니다’로 바뀌면, 대부분의 단어가 맞더라도 중요한 정보는 뒤집힙니다. 계정·금액·날짜·횟수·조건·경고 문구는 별도로 대조하도록 편집 항목을 두는 것이 좋습니다. 이는 이 글에서 제안하는 검토 방법이며 WCAG가 정한 수치 기준은 아닙니다.

시간 코드는 원본과 대안을 다시 찾는 데 도움이 됩니다. 다만 1.2.1이 모든 문장에 시간 코드를 붙이도록 요구하는 것은 아닙니다. 읽기 쉬운 문단과 화자 표기를 먼저 갖추고, 길거나 복잡한 녹음에 필요한 탐색 수단을 추가합니다.

## 무음 영상은 동작의 순서와 결과를 설명해야 합니다

설정 메뉴를 여는 장면, 옵션을 선택하는 장면, 완료 메시지를 보는 장면은 서로 다른 정보를 전달합니다. 대표 프레임 한 장에 붙인 설명으로 세 장면을 모두 대신할 수는 없습니다.

가상의 영상이 ‘설정 → 보안 → 복구 코드 발급 → 새 코드 저장’ 순서를 보여 준다면 텍스트 대안에는 다음과 같은 정보를 담을 수 있습니다.

1. 계정 메뉴의 **설정**을 엽니다.
2. 설정 화면에서 **보안**을 선택합니다.
3. **복구 코드 발급** 버튼을 선택합니다. 기존 코드가 더 이상 유효하지 않다는 안내가 표시됩니다.
4. 발급 완료 화면에서 새 코드를 저장합니다. 완료 메시지와 새 코드 영역이 나타나는 것을 확인합니다.

이것은 코드 값이나 실제 계정 정보를 공개하라는 뜻이 아닙니다. 교육용 영상과 대안에는 안전한 예시 값을 쓰고, 실제 이용자가 자신의 화면에서 확인할 수 있는 위치와 의미를 설명하면 됩니다.

‘설정에서 코드를 발급하세요’라는 요약에는 메뉴 이름, 기존 코드에 대한 경고, 완료 확인이 없습니다. 영상 아래에 설명란이 존재하더라도 이 내용을 얻지 못한다면 정보의 대안이 충분하지 않을 수 있습니다. W3C의 G159는 영상의 중요한 동작·장면·표현을 대안에 담는 방법을 설명합니다. F67은 긴 설명이라도 같은 정보를 전달하지 못하면 실패할 수 있음을 보여 줍니다.

### 음성 설명으로 제공할 수도 있습니다

영상 전용 매체에는 시각 정보를 전달하는 음성 트랙을 제공하는 선택지도 있습니다. ‘메뉴가 열립니다’라는 막연한 설명보다, 현재 위치와 선택한 항목, 화면 변화의 의미를 알려주어야 합니다. 영상 옆에 ‘복구 코드 발급 영상의 음성 설명’이라는 명확한 링크를 두어 원본과의 관계를 알아볼 수 있게 하는 구현을 검토할 수 있습니다.

1.2.1에서 충분한 음성 대안을 선택했다고 텍스트 대안까지 함께 제공해야 이 항목을 충족하는 것은 아닙니다. W3C 해설은 무음 영상의 대안으로 제공된 음성 설명에 별도의 텍스트 대안을 추가로 요구하지 않는다는 점도 설명합니다. 다만 소리와 화면을 모두 이용하기 어려운 이용자에게는 텍스트 경로가 유용하므로, 서비스의 이용자를 고려해 함께 제공할 수 있습니다. 이 추가 제공 권고와 1.2.1의 최소 요구를 구분합니다.

## 기존 글을 읽어 주는 매체는 예외 조건을 확인합니다

페이지에 완전한 안내문이 있고, 그 내용을 다른 방식으로 제공하려고 음성 낭독을 붙였다면 관계가 달라집니다. 기준에는 **기존 텍스트의 대안인 매체이며, 그 사실이 명확하게 표시된 경우**의 예외가 있습니다.

이때 두 조건을 함께 확인합니다. 첫째, 매체에 기존 텍스트를 넘는 정보가 없어야 합니다. 둘째, 이용자가 해당 매체가 텍스트의 대안임을 알아볼 수 있어야 합니다. ‘아래 안내문을 읽어 주는 음성’과 같은 표시가 관계를 설명할 수 있습니다.

같은 주제를 다루는 블로그 글이 있다는 것만으로는 충분하지 않습니다. 글이 요약본이라서 질문과 답변을 빠뜨렸거나, 영상에서만 새로운 경고를 보여 준다면 매체에 추가 정보가 있습니다. ‘음성 버전’이라는 표시만 붙여 이 차이를 없앨 수는 없습니다.

어느 쪽이 원본인지도 기록합니다. 음성 콘텐츠를 이해하기 위한 전사문을 추가한 경우는 대안 제공을 검사합니다. 완전한 텍스트를 다른 형식으로 제공한 경우는 위 예외의 조건을 검사합니다. 파일이 만들어진 날짜만으로 이 관계를 판정하지 않고 콘텐츠의 역할과 실제 정보의 대응을 확인합니다.

예외를 확인했다면 결과에 ‘해당 없음: 기존 텍스트의 명확한 대안 매체’라고 이유를 남길 수 있습니다. 아직 원본을 열지 못했거나 텍스트의 완전성을 모르면 ‘판단 유보’입니다. 예외는 확인을 생략하는 이름이 아닙니다.

## 페이지에 대안을 연결하는 방법

다음은 설명용 구현 예입니다. 파일 경로는 가상이며 실제 배포된 자료를 가리키지 않습니다.

```html
<section aria-labelledby="recovery-audio-title">
  <h2 id="recovery-audio-title">계정 복구 음성 안내</h2>
  <audio controls src="/media/recovery-guide.mp3"></audio>
  <p><a href="#recovery-transcript">계정 복구 안내 전체 전사문</a></p>
  <div id="recovery-transcript">
    <h3>전체 전사문</h3>
    <p>진행자: 기존 기기에 로그인한 상태에서만
      복구 코드를 발급할 수 있습니다.</p>
    <!-- 이후 화자·안내·필요한 소리를 빠짐없이 제공합니다. -->
  </div>
</section>
```

이 코드는 대안의 연결 방식만 보여 줍니다. 위의 한 문단으로 전체 전사문이 완성되었다는 뜻은 아닙니다. 실제 페이지에서는 최종 녹음 전체와 맞는 본문을 넣고, 플레이어 자체의 이름과 키보드 동작도 관련 기준에서 확인합니다.

전사문을 같은 페이지의 텍스트로 두면 미디어를 재생하지 않고도 읽을 수 있습니다. 별도 문서로 제공한다면 어떤 콘텐츠의 전사문인지 링크 이름을 구체적으로 정하고, 목적지에서 실제 본문을 확인합니다. HTTP 200 응답만으로는 충분하지 않습니다. 로그인 안내나 오류 페이지가 반환되었는지, 다른 판본의 문서가 열리는지까지 점검합니다.

영상 전용 자료도 ‘단계별 텍스트 설명’ 또는 ‘영상의 음성 설명’처럼 대안의 형식을 표시할 수 있습니다. PDF나 이미지로만 된 설명서를 제공한다면 그 문서 자체가 읽을 수 있는 형식인지도 검토합니다. 형식만 바꾸고 정보를 다시 접근하기 어려운 곳에 가두지 않도록 하는 구현 판단입니다.

서비스에서는 미디어와 대안을 한 묶음으로 관리하는 편을 권합니다. 미디어 ID, 판본, 길이, 대안 문서, 담당자, 마지막 대조 날짜를 연결해 두면 영상만 교체하고 오래된 설명을 남기는 일을 줄일 수 있습니다. 초판 공개일과 콘텐츠 수정일도 구분해 보존합니다.

## 멀티모달 AI에는 원본과 대안을 서로 독립적으로 제공합니다

이 항목에서 자동화할 질문은 단순히 ‘전사문 링크가 있나요?’에 그치지 않습니다. 원본의 어떤 정보가 대안의 어느 문장과 대응하는지, 중요한 부정어가 뒤집혔는지, 화면의 단계가 설명에서 사라졌는지를 비교하도록 설계할 수 있습니다. 원본 관찰과 대안의 입력 경로를 나누고, 처리한 범위를 근거로 남기는 평가 방법입니다. 뒤의 검증에서는 이 구조를 실제 시험 자료에 적용한 범위와 한계를 설명합니다.

먼저 원본에서 시간순으로 정보 목록을 만듭니다. 음성이라면 발화·화자·이해에 필요한 소리, 영상이라면 화면 문구·동작·변화·결과를 기록합니다. 그 목록을 대안과 비교해 대응 위치와 차이를 남깁니다. 소리나 화면에서 확인한 사실과 문맥으로 추론한 내용을 구분하면 수정 담당자가 원본으로 돌아가 확인할 수 있습니다.

같은 AI가 생성한 전사문을 정답과 대안 양쪽에 복사해서 비교하면 원본의 오류를 발견하기 어렵습니다. 대안이 원본을 빠뜨렸는지 확인하려면 원본에 접근하는 경로가 있어야 합니다. 전사 도구의 출력만 제공했다면 ‘파생 전사문 간의 비교’까지 수행할 수 있으며, 음성 전체를 확인했다고 기록해서는 안 됩니다.

영상에서 몇 장의 프레임을 추출하면 화면 문구와 대표 상태를 비교할 수 있습니다. 그러나 선택한 프레임 사이에서 잠깐 나타난 경고나 중간 동작은 빠질 수 있습니다. 일부 프레임으로 분명한 누락을 발견할 수는 있어도, 그것만으로 영상 전체의 모든 정보를 확인했다는 결론을 내릴 수는 없습니다. 처리한 시간 구간과 빈 구간을 함께 남깁니다.

모델이 원본 음성이나 연속 영상을 실제로 처리할 수 있는지도 실행 전에 확인합니다. 파일을 첨부한 사실, 파일 메타데이터를 읽은 사실, 콘텐츠를 끝까지 분석한 사실은 서로 다릅니다. 처리할 수 없는 자료는 연결된 도구나 별도 검토가 필요합니다. 프롬프트에 ‘들어 보세요’라고 적었다고 그 기능이 생기지는 않습니다.

### 평가 자료의 최소 구성

| 자료 ID 예 | 준비할 자료 | 확인하려는 내용 |
| --- | --- | --- |
| PAGE-01 | 평가 페이지·상태, 미디어 목록, 주변 설명, DOM, 대안 링크의 목적지 | 대안이 어떤 원본에 연결되어 있는지, 실제 제공되는지 |
| MEDIA-01 | 최종 미디어, 판본 또는 해시, 전체 길이, 트랙 정보, 실제 처리 구간 | 음성·영상 유형과 원본에 있는 정보 |
| ALT-01 | 실제 대안 본문 또는 음성 대안과 판본 | 같은 내용을 전달하는지, 다른 자료의 요약이 아닌지 |
| OBS-01 | 원본 관찰의 시간 코드·화자·화면 상태, 사용 도구, 처리 기록 | 원본에서 직접 확인한 정보와 비어 있는 구간 |
| EXC-01 | 기존 텍스트 정본과 매체의 관계를 표시한 문구 | 예외를 주장한다면 두 조건이 모두 맞는지 |

모든 자료를 매번 같은 형식으로 만들어야 한다는 표준 요구는 아닙니다. 평가를 재현하고 입력 누락을 알아보기 위한 기록 제안입니다. 필요한 자료가 없을 때 AI가 빈칸을 추측으로 채우지 않도록, 누락된 ID와 구간을 먼저 표시합니다.

## 판정과 실행 상태는 별도로 읽습니다

다음은 평가에서 사용할 판정의 의미입니다.

| 판정 | 이 글에서 사용하는 조건 |
| --- | --- |
| 충족 | 적용되는 대상에서 필요한 대안이 실제 제공되고, 확인한 전체 원본과 동등한 정보를 전달합니다. 영상 전용이면 허용되는 두 경로 중 하나가 충분할 수 있습니다. |
| 미충족 | 적용 조건과 실제 대안의 범위를 확인했고, 필요한 대안이 없거나 중요한 정보의 누락·왜곡을 증거로 확인했습니다. |
| 해당 없음 | 평가 범위에 대상 매체가 없거나, 다른 매체 유형이거나, 기존 텍스트의 대안 매체라는 예외를 확인했습니다. 이유를 구분해 남깁니다. |
| 판단 유보 | 원본, 대안, 분류 또는 처리 구간이 충분하지 않아 결론을 낼 수 없습니다. 부족한 자료와 다음 확인을 적습니다. |

실행 상태는 미실행·완료·부분 실행·오류·차단으로 구분합니다. 전체 원본을 처리하지 못했다면 부분 실행입니다. 원본 파일의 디코딩이 실패했다면 오류입니다. 접근 권한이 없어 목적지에 들어가지 못했다면 차단입니다. 이런 상황을 ‘대안 없음’이나 ‘해당 없음’으로 바꾸지 않습니다.

명확한 실패 하나를 확인했다면 해당 대상의 미충족을 기록할 수 있습니다. 다른 구간이 미검토라면 실패의 위치와 미검토 구간을 함께 남깁니다. 반대로 일부 구간에서 문제가 없었다는 이유로 전체 대상에 충족을 부여하지 않습니다. 영상 전용에 텍스트 설명이 없다는 사실만으로 실패를 확정하지도 않습니다. 충분한 음성 대안이 제공되는지 확인해야 합니다.

### 검증 결과를 수정 기록으로 옮기는 예

시험용 음성의 전사문에서 이전 코드의 사용 가능 여부를 반대로 적은 사례는 다음처럼 기록할 수 있습니다. 원본과 대안의 문장은 의미를 한국어로 옮긴 것이며, 시간 위치는 독립 음성 인식 기록의 발화 구간입니다.

```text
대상: M-A / 시험용 복구 안내 fixture-v1
위치: OBS-A의 8~19초 구간 / ALT-A 대응 문장 두 곳
원본 의미: 새 코드를 만들면 이전 코드는 사용할 수 없게 됨.
           완료 뒤에도 이전 코드는 더 이상 사용할 수 없음.
대안 의미: 이전 코드를 사용할 수 있으며 계속 쓸 수 있음.
차이와 영향: 두 부정 의미가 뒤집혀 무효한 코드에 의존하게 함.
확인한 판정: 미충족 / 근거 OBS-A, ALT-A
수정 제안: 조건과 부정 의미를 원본에 맞게 복원함.
재점검 계획: 같은 원본 구간과 전체 대안, 실제 제공 판본을 대조함.
```

이 기록에서 확인한 결과는 왜곡과 미충족 판정까지입니다. 수정과 재점검은 제안이며 완료한 작업으로 표시하지 않습니다. 평가자는 위치·원본·대안·차이·이용자 영향을 전달하고, 수정 담당자는 그 기록으로 문제를 다시 찾을 수 있어야 합니다.

## 실무 체크리스트

체크 표시는 해당 검토를 수행했다는 뜻입니다. 모든 칸을 체크했다고 기준을 충족하는 것은 아닙니다. 각 항목에 판정·증거 ID·시간 위치·미검토 범위를 별도로 기록합니다.

- [ ] **C01 적용 대상**: 페이지와 필요한 상태의 미디어 목록을 확인하고, 사전 제작 음성 전용·영상 전용·다른 유형을 실제 내용으로 구분했습니다. 못 연 매체는 제외하지 않고 미검토로 남겼습니다.
- [ ] **C02 판본 일치**: 최종 원본의 판본·전체 길이와 대안의 판본을 연결했습니다. 초안 대본이나 다른 편집본을 원본으로 사용하지 않았습니다.
- [ ] **C03 음성 정보**: 적용되는 음성 전용 콘텐츠의 발화·조건·부정어·화자·이해에 필요한 소리가 전사문과 대응하는지 확인했습니다. 해당 매체가 없다면 그 이유를 기록했습니다.
- [ ] **C04 영상 정보**: 적용되는 영상 전용 콘텐츠의 문구·동작·순서·변화·결과를 대안과 비교했습니다. 일부 프레임만 확인했다면 빈 시간 구간을 남겼습니다.
- [ ] **C05 허용된 대안**: 영상 전용 콘텐츠에서 충분한 텍스트 또는 음성 대안 중 하나를 확인했습니다. 텍스트가 없다는 이유만으로 두 경로 모두 실패했다고 판단하지 않았습니다.
- [ ] **C06 실제 제공**: 대안 링크·본문·음성 파일을 실제로 확인했고, 오류 화면·요약본·다른 판본이 대신 반환되지 않는지 점검했습니다.
- [ ] **C07 예외 근거**: 기존 텍스트의 대안이라는 예외를 적용했다면 텍스트에 없는 추가 정보가 없고, 대안 관계도 명확하게 표시되어 있음을 확인했습니다.
- [ ] **C08 독립된 관찰**: 대안 문서를 원본 관찰 자료로 복사하지 않았습니다. 파생 전사나 프레임에 의존했다면 그 경로와 검증 범위를 기록했습니다.
- [ ] **C09 실행 기록**: 실제 처리한 자료·시간 구간·도구와 실패·차단·미검토 범위를 남겼습니다. URL만 제공된 자료를 읽은 것으로 표시하지 않았습니다.
- [ ] **C10 근거 있는 판정**: 충족·미충족·해당 없음·판단 유보를 구별하고, 중요한 차이를 원본과 대안의 위치로 설명했습니다. 확인되지 않은 모델 확신 수치를 정확도로 표시하지 않았습니다.
- [ ] **C11 수정과 재점검**: 누락·왜곡을 수정한 뒤 같은 원본 구간, 나머지 전체 내용, 실제 제공 페이지를 다시 확인할 계획을 남겼습니다.
- [ ] **C12 범위 구분**: 이 항목의 결과를 전체 WCAG 적합성으로 확대하지 않았습니다. 자막·플레이어 키보드 조작·문서 자체의 접근성 문제는 해당 기준에서 별도로 관리합니다.

## 평가 프롬프트를 사용하기 전에

아래 프롬프트는 원본과 대안을 연결해 비교하는 작업에 사용합니다. [시리즈 개요](/series/accessibility/overview)의 평가 계획 프롬프트로 범위를 먼저 정한 뒤, 이 항목에 필요한 실제 자료를 넣습니다. URL만 입력하고 수집·재생·비교가 모두 끝났다고 기대하지 않습니다.

프롬프트를 팀의 평가 과정에 넣을 때에는, 완전한 대안이 있는 사례, 중요한 조건이 빠진 사례, 영상에 음성 대안만 있는 사례, 텍스트 대안 매체의 예외, 원본을 처리하지 못하는 사례를 먼저 비교해보는 편을 권합니다. 특히 음성 대안을 잘못 실패로 처리하는지, 자료 부족을 충족으로 처리하는지 확인합니다. 모델과 입력 경로가 바뀌면 같은 사례로 다시 점검합니다.

이 글의 프롬프트는 자료 목록, 원본 관찰, 대안, 예외 주장, 처리 오류를 별도의 입력으로 받습니다. 확인한 구간은 숫자로 기록하고, 수집 기록과 실제 내용 확인 범위가 다르면 확인되는 교집합만 사용합니다. 영상 원본의 검토 시간에 음성 대안의 길이를 섞지 않으며, 비어 있는 구간은 판단 유보의 근거로 남깁니다.

## 실제 자료로 확인한 프롬프트의 범위

공개된 이전 글의 초기 본문에는 이 항목의 대상 매체가 없었습니다. 이 경우에는 ‘해당 없음’ 분기를 확인할 수 있지만 원본과 대안의 내용 비교를 시험할 수는 없습니다. 그래서 가상의 복구 코드 안내를 담은 로컬 실습 페이지에 실제 음성 파일과 무음 영상을 연결하고, 대안만 바꾼 사례를 구성했습니다. 실제 계정이나 복구 코드는 사용하지 않았습니다.

음성 원본은 약 19초의 명료한 단일 합성 화자 안내입니다. 원본 WAV에서 별도로 음성을 인식해 조건·절차·부정어·완료 정보를 확인했습니다. 평가 대상 전사문과 제작 대본을 음성 인식 도구에 입력하지 않았습니다. 무음 영상은 약 20초이며, 계정 설정·보안·생성 전 경고·보관·완료의 다섯 화면을 차례로 보여 줍니다. 239개 프레임을 실제 디코딩해 다섯 개의 동일 프레임 그룹과 연결했고, 각 그룹에서 추출한 PNG로 화면 내용을 검토했습니다.

개요의 평가 계획 프롬프트와 이 글의 항목별 프롬프트는 지침을 바꾸지 않고 실제 입력란만 채웠습니다. 판정과 필요한 근거를 먼저 정한 뒤 **Claude Opus 5.5, 노력 높음**에서 다음 10개 사례를 실행했습니다.

| 실제 입력 조건 | 확인한 판정 | 결과에서 확인한 내용 |
| --- | --- | --- |
| 이전 글의 초기 본문에 대상 매체 없음 | 해당 없음 | 정적 도식과 시간 기반 매체를 구분하고 범위를 본문에 한정했습니다. |
| 음성 원본과 충분한 전사문 | 충족 | 로그인 조건·단계·이전 코드 무효화·보관·완료가 대응했습니다. |
| 같은 음성의 전사문에서 부정 의미를 반대로 변경 | 미충족 | 이전 코드의 사용 가능 여부가 뒤집힌 두 위치를 찾았습니다. |
| 무음 영상과 충분한 단계별 설명 | 충족 | 다섯 화면의 의미와 선택 대상·순서가 대응했습니다. |
| 같은 영상의 중간 두 단계를 설명에서 삭제 | 미충족 | 보안 화면과 생성 전 경고·확인 단계의 누락을 찾았습니다. |
| 무음 영상에 충분한 음성 대안만 제공 | 충족 | 별도 텍스트를 추가로 요구하지 않았습니다. |
| 완전한 기존 텍스트의 대안인 영상이며 관계를 명확히 표시 | 해당 없음 | 추가 정보가 없다는 조건과 표시 조건을 함께 확인했습니다. |
| 요약 텍스트만 두고 대안 관계의 표시를 추가 | 미충족 | 표시만으로 예외를 인정하지 않았습니다. |
| 원본 파일의 디코딩 실패 | 판단 유보 | 실행 오류를 남기고 대안의 내용을 원본으로 추정하지 않았습니다. |
| 처음·끝 화면만 제공하고 가운데 구간 누락 | 판단 유보 | 일부 구간의 동등성을 전체 충족으로 확대하지 않았습니다. |

10개 사례의 판정은 사전에 정한 기준 답과 모두 일치했습니다. **10개 사례 모두 같은 입력으로 총 3회씩 실행했고, 30개 실행의 판정이 기준 답과 일치했습니다.** 개요 계획도 매체가 있는 경우와 없는 경우를 각각 3회 실행해, 실제 판정 없이 범위·필요 자료·미확인 상태를 정리하는지 확인했습니다. 각 반복은 이번 항목의 결과가 없는 이전 문맥에서 분기했고, 사례들은 각 분기 안에서 순차 처리했습니다.

부정어가 뒤집힌 음성 사례에서는 원본의 8~19초 발화 구간과 대안의 대응 문장을 연결했습니다. 중간 단계가 빠진 영상 사례에서는 화면 ID와 그 시간 구간을 남겼습니다. 부분 입력 사례에서는 수집 기록의 처리 구간과 실제 제공 프레임의 경계가 맞지 않는 짧은 공백도 미검토 범위로 기록했습니다. 판정만 맞히는 것과 수정할 위치를 다시 찾을 수 있게 남기는 것을 함께 확인한 것입니다.

**이 결과는 준비한 제한된 시험 자료에서의 검증입니다.** 평가 모델은 WAV나 MP4를 직접 듣거나 연속 재생하지 않았습니다. 실제 파일에서 독립적으로 추출한 전사·PNG·처리 기록을 입력으로 사용했습니다. 명료한 한 화자와 다섯 정적 화면의 결과를 잡음·겹친 대화·중요한 효과음·빠른 화면 변화가 있는 모든 매체로 확대할 수는 없습니다. 임의 영상에서 프레임 몇 장만 뽑는 경우에는 이 실습의 전체 프레임 확인 근거를 사용할 수 없습니다.

이 시험은 작성 단계에서 준비한 기준 답과의 대조이며, 독립적인 접근성 전문가의 적합성 인증은 아닙니다. 모델 이름만으로 같은 결과를 보장할 수 없습니다.

이 프롬프트는 적용 범위와 자료 경로를 고정해 원본과 대안을 비교하도록 구성했습니다. 새로운 모델·도구·미디어 유형을 연결할 때에는 정상·누락·예외·처리 실패 사례를 다시 점검하고, 실제로 처리하지 못한 자료를 충족 근거에 넣지 않습니다.
