## 자막이 있어도, 지시의 뜻이 바뀌면 충분하지 않습니다

계정 복구 안내 영상에서 사용자가 묻습니다. “이전 코드를 지금 버려도 되나요?” 안내자는 “아니요. 새 복구 코드를 저장하기 전에는 버리지 마세요”라고 답합니다. 그런데 자막에는 “새 복구 코드를 저장하기 전에 버리세요”가 나타납니다. 문장 대부분은 원본과 같지만, 이 자막을 믿고 행동하면 필요한 코드를 잃을 수 있습니다.

이런 영상은 자막 파일이 있고 재생 화면에도 글자가 보입니다. 자동 검사에서는 자막 트랙의 존재를 확인할 수 있을 것입니다. 하지만 이용자가 같은 정보를 얻는지는 별개의 문제입니다. 부정 표현 하나, 경고음 하나, 대사의 표시 시점 하나가 안내의 의미를 바꿀 수 있기 때문입니다.

앞선 [녹음된 음성과 무음 영상 글](/series/accessibility/audio-only-and-video-only-prerecorded)에서는 음성 전용과 영상 전용 콘텐츠의 대안을 구분했습니다. 이번에는 **WCAG 2.2의 1.2.2 Captions (Prerecorded), 수준 A**를 다룹니다. 사전에 제작된 동기화 매체의 소리를, 화면을 보면서 읽을 수 있는 자막으로 전달하는 기준입니다. 복구 코드 안내는 이 글의 설명과 검증을 위해 만든 가상 사례이며, 실제 계정이나 코드는 다루지 않습니다.

## 무엇을 위한 자막인지 먼저 정합니다

1.2.2는 사전에 제작된 동기화 매체에 들어 있는 음성을 대상으로 자막을 요구합니다. 흔한 예는 발표자의 설명이 있는 제품 안내 영상, 대화와 효과음이 있는 교육 영상, 녹화한 인터뷰입니다. 발표자의 모습과 설명이 함께 재생되는 단순한 영상도 포함합니다. 화면과 소리의 관계가 복잡해야만 적용되는 기준은 아닙니다.

파일 이름이나 HTML 태그만으로 분류하면 틀릴 수 있습니다. `video` 요소 안에 실제로는 음성만 있을 수도 있고, 영상 파일에 장식용 음악만 있을 수도 있습니다. 플레이어를 음소거한 상태도 원본에 소리가 없다는 뜻은 아닙니다. 실제 음성과 시각 정보, 녹화 여부, 이용자가 소리로 얻어야 할 내용을 확인해야 합니다.

| 실제 콘텐츠 | 우선 검토할 기준 | 확인할 점 |
| --- | --- | --- |
| 대사나 중요한 소리가 있는 녹화 동기화 매체 | 1.2.2 녹화 자막 | 소리를 이해할 수 있는 자막이 화면과 함께 제공되는가 |
| 녹음된 음성 전용 콘텐츠 | 1.2.1 | 같은 정보를 전달하는 전사문 등의 대안이 있는가 |
| 실제 소리가 없는 사전 제작 영상 | 1.2.1 | 시각 정보의 충분한 대안 또는 음성 트랙이 있는가 |
| 실시간 동기화 매체 | 1.2.4 실시간 자막, 수준 AA | 현재 송출되는 소리에 대한 자막을 제공하는가 |
| 실시간 행사를 녹화해 다시 제공하는 매체 | 제공되는 녹화본의 1.2.2 | 생방송 때의 처리와 별도로 녹화본을 검토했는가 |

배경 음악이 있다는 이유로 모든 파일에 같은 자막을 기계적으로 요구할 필요는 없습니다. 장식에 그치는 음악인지, 분위기나 사건의 변화처럼 이해에 필요한 정보를 전달하는 소리인지 판단해야 합니다. 반대로 대사가 없다는 이유로 중요한 경고음이 있는 영상을 무음 영상으로 처리해서도 안 됩니다.

## 자막은 대사와 함께 중요한 소리와 화자를 전달합니다

자막을 음성 인식 결과에 시간만 붙인 파일로 생각하면 빠뜨리는 내용이 생깁니다. 이용자가 들을 수 있었다면 알았을 정보 중, 장면과 행동을 이해하는 데 필요한 것이 무엇인지 살펴봐야 합니다.

먼저 대사의 의미를 보존합니다. 부정, 조건, 수치, 순서와 경고는 특히 주의해야 합니다. “발급하면 이전 코드를 사용할 수 없습니다”를 “발급하면 이전 코드를 사용할 수 있습니다”로 바꾸면 핵심 의미가 뒤집힙니다. “저장한 뒤 버리세요”에서 “뒤”를 빠뜨려도 조작 순서가 달라집니다.

그렇다고 모든 음절을 문자 그대로 복사해야 한다는 뜻은 아닙니다. 반복이나 군더더기를 줄인 문장이 같은 의미를 전달할 수 있습니다. 이 글의 “새 코드를 안전한 곳에 저장합니다. 새로 발급하면 이전 코드는 더 이상 사용할 수 없습니다”를 “새 코드를 안전하게 저장하세요. 새 코드 발급 후 이전 코드는 사용할 수 없습니다”로 줄이면, 저장과 이전 코드의 무효화라는 두 정보를 유지합니다. 검토할 것은 문자 일치율보다 정보와 의미입니다.

화자도 내용의 일부입니다. 화면 밖에서 사용자와 안내자가 질문과 답변을 주고받는다면, 소리를 듣지 못하는 이용자에게 누가 말했는지 알려야 합니다. 질문을 안내자의 지시로 읽거나 답변의 주체를 혼동하지 않게 하기 위해서입니다. 다만 화면과 문맥으로 화자가 이미 명확하다면, 매 줄마다 이름을 반복하는 것을 보편적인 의무로 만들 필요는 없습니다.

소리는 대사 밖에도 있습니다. 오류를 알리는 경고음, 문을 두드리는 소리, 웃음이나 음악의 변화가 장면의 의미에 영향을 준다면 자막에 담아야 합니다. “[경고음]”처럼 소리의 종류만 적는 것으로 충분한지도 문맥에서 판단합니다. 두 번의 경고음이 보안 확인 실패를 뜻하는 안내라면, 그 의미를 알아야 이용자가 다음 조작을 결정할 수 있습니다.

## 전체 전사문이 있으면 자막을 생략해도 될까요?

일반적인 녹화 영상에 전체 전사문을 붙였다는 이유만으로 자막 요구가 사라지지는 않습니다. 전사문을 읽는 동안 화면에서 어느 단계가 진행되는지, 지금 누구의 답변인지, 언제 경고가 발생했는지를 이용자가 직접 연결해야 하기 때문입니다. 전사문은 유용한 추가 경로이지만 동기화 자막과 역할이 다릅니다.

1.2.2에는 본문의 매체 대안인 경우의 예외가 있습니다. **이미 제공된 본문에 없는 정보를 매체가 추가하지 않고, 매체가 본문의 대안이라는 사실을 명확히 표시한 경우**입니다. 두 조건을 함께 확인해야 합니다.

예를 들어 페이지에 단계, 질문과 답변, 경고의 의미까지 완전한 설명이 있고 “이 영상은 아래 설명의 매체 대안입니다”라고 실제로 표시되어 있다고 가정해보겠습니다. 영상 전체가 그 설명과 같은 정보만 전달한다면 해당 예외를 검토할 수 있습니다. 반면 영상에서만 “이전 코드는 더 이상 사용할 수 없습니다”라는 주의 사항을 말한다면, 안내 문구가 있어도 본문에 없는 정보가 추가된 것입니다.

같은 제목, 전사문 링크, 제작자의 “내용은 같습니다”라는 말만으로 예외를 인정하지 않습니다. 매체 전체와 연결된 본문 전체, 이용자에게 실제 보이는 표시 문구를 비교해야 합니다. 두 조건 중 하나가 성립하지 않는다고 확인했다면 일반 자막 요구를 평가합니다. 조건을 비교할 자료 자체가 없다면 예외도 충분성도 판단할 수 없으므로, 판단 유보로 기록하고 필요한 자료를 요청합니다.

## 자막이 나타나는 시간과 위치도 정보의 일부입니다

정확한 문장이 영상이 끝난 뒤에 나온다면 이용자가 필요한 순간에 읽을 수 없습니다. 안내자가 “버리지 마세요”라고 답하는 동안에는 자막이 없고, 다음 화면에서 그 답변이 나타나면 현재 단계에 대한 지시로 혼동할 수 있습니다. 다른 대사와 순서가 뒤섞이거나, 여러 문장이 지나치게 짧게 표시되는 문제도 살펴봐야 합니다.

시간을 평가할 때는 원본의 소리 구간과 자막의 표시 구간을 함께 기록합니다. 몇 초 차이가 났는지와 그때 화면에서 무엇을 이해하거나 결정해야 하는지를 연결해야 수정할 수 있습니다. “자막 싱크가 나쁨”이라는 한 줄보다 “답변의 설계 구간은 7.6–11.6초인데 자막이 12.6–16.6초에 표시되어 보안 확인 결과 화면에서 이전 답변을 읽게 됨”이 유용합니다.

이 사례의 5초 지연을 모든 영상의 합격선으로 일반화해서는 안 됩니다. WCAG 1.2.2에 임의의 지연 초나 글자 수를 고정 기준처럼 덧붙이지 않습니다. 읽기 시간에 별도의 수치 합격선을 두는 것도 이 기준의 요구는 아닙니다. 표시 시간이 이용에 미치는 영향은 원본과 화면의 관계를 설명하는 실무 검토로 기록합니다.

그림 03의 7.60–11.60초는 답변을 배치한 설계 구간입니다. 원본에서 독립 전사로 검출한 실제 발화는 7.71–11.18초이며, 아래 입력 예에서는 이 관찰 값을 사용합니다. 자막의 표시 구간과 발화의 관찰 구간을 같은 수치로 바꾸어 기록하지 않습니다.

자막의 배치도 검토합니다. 영상 속 오류 메시지나 선택해야 할 버튼을 자막이 가리면 소리의 내용을 전달하면서 중요한 시각 정보를 잃을 수 있습니다. 긴 대사, 작은 화면, 플레이어 조작부가 나타난 상태에서 확인할 필요가 있습니다. 자막을 전달하는 기준의 검토와 플레이어의 키보드 조작 등 다른 성공 기준의 검토는 각각 기록합니다.

## HTML의 자막 트랙과 영상에 포함된 자막을 구분합니다

이용자가 켜고 끄는 자막을 폐쇄 자막, 영상 화면 자체에 항상 들어 있는 자막을 개방 자막이라고 부릅니다. 1.2.2에서는 두 방식 모두 사용할 수 있습니다. 개방 자막이 충분하게 제공되는데 `<track>`이 없다는 이유로 실패 처리하면 잘못된 평가입니다.

HTML 영상에 폐쇄 자막을 연결하는 예는 다음과 같습니다. 아래 코드는 이 글의 가상 안내 영상과 같은 형태의 구현 예이며, 파일 연결만으로 실제 자막 품질이 확인되는 것은 아닙니다.

```html
<video controls preload="metadata" playsinline
       aria-label="복구 코드 발급 안내"
       src="recovery-guide.mp4">
  <track kind="captions" src="recovery-guide.ko.vtt"
         srclang="ko" label="한국어 자막" default>
</video>
```

`kind="captions"`는 대사와 필요한 소리를 전달하는 트랙임을 나타냅니다. `srclang`과 `label`은 이용자가 언어와 트랙을 식별하는 데 쓰입니다. `default`는 기본 표시할 트랙을 지정하는 데 사용하지만, 최종 표시 상태에는 브라우저와 이용자 설정도 영향을 줄 수 있습니다. 실제 플레이어에서 선택하고 읽을 수 있는지 확인해야 합니다.

WebVTT의 큐는 시작·종료 시간과 문장을 묶은 자막 한 덩어리입니다. 이 예의 B1·A2·SFX는 큐를 다시 찾기 위한 ID이며, 그림 03에서 두 표시 조건을 구분한 자막 A/B와는 다릅니다. 질문과 답변의 화자, 그리고 의미 있는 경고음을 구분해 기록합니다.

```text
WEBVTT

B1
00:00:04.000 --> 00:00:07.000
사용자: 이전 코드를 지금 버려도 되나요?

A2
00:00:07.600 --> 00:00:11.600
안내자: 아니요. 새 복구 코드를 저장하기 전에는 버리지 마세요.

SFX
00:00:12.200 --> 00:00:15.820
[보안 확인 실패를 알리는 경고음 두 번]
```

원본 경고음은 12.20–12.82초에 두 번 들리지만, 그 의미를 읽을 수 있도록 자막은 15.82초까지 유지했습니다. 이후 안내자의 다음 대사 큐 A3는 16.42초에 시작하며, 독립 전사에서 관찰한 실제 발화 시작은 16.47초입니다. 소리와 관계를 유지하면서 읽을 시간을 확보한 예입니다. 모든 자막을 소리의 시작과 끝에 기계적으로 붙이는 것만으로는 충분하지 않습니다.

네트워크 요청이 성공하고 파일 문법이 맞아도, 자막을 선택하지 못하거나 화면에 표시되지 않을 수 있습니다. 트랙이 로드되고 표시되는 상태, 현재 시간에 활성화되는 큐, 실제 화면을 함께 확인합니다. 반대로 파일 처리 실패 때문에 원본을 읽지 못했다면, 그 오류를 내용이 부족하다는 접근성 판정으로 바꾸지 않습니다.

## 실습 페이지에 두 프롬프트를 적용합니다

다음 페이지는 안내자와 사용자의 대화, 그리고 보안 확인 실패를 알리는 경고음이 있는 복구 코드 안내입니다. 같은 원본에 충분한 자막, 부정 표현이 바뀐 자막, 경고음이 빠진 자막, 시간이 어긋난 자막을 연결했습니다. 먼저 소리를 끄고 자막만으로 질문의 답과 보안 확인 결과를 이해할 수 있는지 비교해보세요.

[웹 접근성 개요](/series/accessibility/overview)의 프롬프트는 먼저 이용 목적과 평가 범위를 정하는 데 사용합니다. 이 실습에서는 실제 계정 발급을 실행하는 것이 아니라, 이용자가 안내 내용을 이해하는 과정을 평가 범위로 잡습니다. 원본의 음성과 소리, 자막의 내용과 표시 상태, 본문 대안의 예외를 확인할 자료를 계획합니다. 원본을 아직 보지 않았다면 계획을 실행 결과로 쓰지 않습니다.

실제 개요 프롬프트의 출력은 다음처럼 계획과 관찰을 구분했습니다. 아래는 반환된 계획의 발췌입니다.

> 자료 안의 `DISPLAY-C01-1~3` 이미지는 ID로만 언급되어 있고 이 조건에는 첨부되지 않았으므로 관찰 자료로 쓰지 않았습니다.
>
> S2 표시 화면: DISPLAY-C01-1~3 PNG를 이 평가 조건에 실제로 첨부하거나 동일 시점 화면을 다시 수집.

대상 매체가 없는 공개 개요 글의 입력에서는, 평가 범위 문구가 영상 하나를 가리키는데 실제 매체 목록은 비어 있다는 충돌도 표시했습니다. 출력은 “어느 쪽이 의도된 범위인지 확인이 필요합니다”라고 기록했습니다. 자료 ID가 있다는 이유로 이미지를 보았다고 하거나, 모순된 범위를 임의로 확정하지 않고 다음 수집·확인 작업을 만든 결과입니다. 이 계획에 포함된 키보드 조작과 화면 낭독기 검토는 수행한 결과가 아닙니다.

이 글 마지막의 1.2.2 프롬프트는 수집한 자료를 비교해 판정과 수정 근거를 남기는 데 사용합니다. 모델에는 실제 MP4에서 별도로 추출한 시간별 전사, 원본 소리 구간과 화자 역할의 처리 기록, 브라우저에서 읽은 자막 큐와 표시 상태, 실제 화면 PNG를 제공했습니다. 후보 자막을 원본 전사로 복사해 넣지는 않았습니다.

### 자막의 존재보다 무엇이 달라졌는지를 기록합니다

전체 자막이 있는 조건에서는 대사, 화면 밖 화자, 경고음과 그 의미가 원본과 대응했습니다. 경고음을 빠뜨린 조건에서는 **12.20–12.82초의 원본 소리와 연결된 자막이 없다는 근거**가 남았습니다. 페이지의 소리 설명은 경고음의 의미를 해석하는 자료이지만, 재생 중 경고가 발생한 순간을 동기화해 전달하는 자막은 아닙니다.

부정 표현이 바뀐 조건에서는 **A2 큐의 지시가 반대로 바뀐 사실**을 기록했습니다. 단순히 “정확도가 낮다”는 결과가 아니라, 원본의 “저장하기 전에는 버리지 마세요”와 자막의 “저장하기 전에 버리세요”를 연결해 이용자가 잘못 행동할 위험을 설명했습니다. 수정은 해당 큐의 의미를 바로잡고 같은 구간을 다시 확인하는 것으로 구체화했습니다.

시간이 어긋난 조건에서는 같은 A2 문장이 **설계 구간 7.60–11.60초 대신 12.60–16.60초에 표시**되는 것을 확인했습니다. 문장을 그대로 남겨도, 보안 확인 결과와 재확인 화면에서 이전 답변을 읽게 되므로 시간 대응이 부족하다는 결과입니다.

다음 표는 같은 프롬프트로 검토한 정상, 실패, 예외와 자료 부족 조건의 대표 결과입니다. “충족”은 제공된 평가 범위에서 확인한 판정이며, 이 영상이나 사이트의 다른 기준까지 적합하다는 뜻은 아닙니다.

개방 자막 조건에서 모델은 충족을 반환했지만, 검토한 표시 자료는 9개 시점의 PNG이고 자막별 정확한 표시 시작·종료 시각은 입력에 없었습니다. 이 결과로 영상에 포함된 자막의 전체 시간 대응을 입증할 수는 없습니다. 지연된 개방 자막은 시험하지 않았습니다. 실제 적용에서는 각 자막이 나타나고 사라지는 프레임과 그 구간의 화면을 추가로 확인해야 합니다. 표본을 본 모델은 긴 자막의 ‘없습니/다.’ 같은 어절 중간 줄바꿈과 자막 띠가 영상 안의 진행 막대를 덮는 모습도 기록했습니다. 의미와 경고는 유지되고 다른 진행 표시가 남아 있다는 근거로 이 관찰을 실패로 판정하지는 않았습니다. 줄바꿈의 읽기 편의와 진행 정보의 보존은 실제 표시 상태에서 따로 재점검할 항목입니다.

자료 부족 두 조건은 화면 자체가 항상 불완전하다는 뜻이 아닙니다. 첫 번째는 평가 모델에 전달한 원본 자료를 제한했고, 두 번째는 원본 파일을 불러오지 못한 상태입니다. 실제 실습 화면과 모델의 입력 조건을 구분해야 결과를 다른 자료에 대한 성능으로 읽지 않을 수 있습니다.

이 결과는 Claude Opus 5.5 High에서 확인했습니다. 원본 자료와 두 프롬프트를 고정한 뒤, 새 세션 세 개에서 14개 조건을 각각 순서대로 검토했습니다. 총 42개의 모델 범위 판정이 미리 정한 기준 답과 일치했습니다. 이 숫자는 반환된 판정의 일치 횟수이며, 개방 자막의 표시 시간처럼 확인되지 않은 근거가 충족됐다는 뜻은 아닙니다. 조건마다 세션을 분리한 42회의 독립 실행은 아니며, 한 세션의 조건들은 앞서 처리한 조건의 문맥을 공유할 수 있습니다. 개요 프롬프트도 실습 페이지와 대상 매체가 없는 공개 개요 글에 각각 세 차례 적용해, 평가 범위와 추가 증거를 계획하는지 확인했습니다.

기준 답은 평가 모델에 제공하지 않고 실행 전에 고정했습니다. 같은 자료 제작·검증 과정에서 표준과 원본의 대응을 근거로 정한 답이며, 독립된 접근성 전문가의 검토는 거치지 않았습니다. 따라서 이 일치는 해당 자료에 대한 반복 일관성의 결과이고 외부 전문가가 확인한 정확도나 일반 영상의 성능은 아닙니다.

판정의 일치와 출력 기록의 완전성도 다릅니다. 42개 출력 중 6개에는 약 0.019초의 파일 끝 구간을 미검토로 적으면서 전체 검토를 뜻하는 필드도 함께 표시한 기록상 경고가 있었습니다. 이 6개 출력은 모두 충족 판정이었습니다. 원본을 수집한 쪽에서 해당 꼬리에 소리 정보가 없음을 별도로 측정했지만, 평가 모델이 직접 그 구간을 확인했다는 뜻은 아닙니다. 프롬프트에는 컨테이너 길이와 실제 디코드 길이의 미세한 차이를 어떻게 집계할지 명시된 규칙이 없어 기록이 모호해질 수 있습니다. 반환된 판정뿐 아니라 미검토 구간과 처리 기록을 원본 증거에 대조해야 하는 이유입니다.

일부 출력은 원본 발화 시각을 기록할 필드에 자막 큐 시각을 넣기도 했습니다. 예를 들어 독립 전사의 시작은 A2에 대응하는 답변이 7.71초, A3에 대응하는 안내가 16.47초인데, 일부 기록은 큐 시작인 7.60초와 16.42초를 사용했습니다. 최종 판정이 같더라도 이 값이 원본 관찰을 정확하게 옮겼다는 뜻은 아닙니다. 수정 위치를 전달할 때에는 원본 발화 시각과 자막 표시 시각을 각각 원자료에 대조합니다.

평가 모델이 원본을 직접 듣거나 연속 영상을 처리한 시험은 아닙니다. 독립 전사·소리 처리 기록·자막 큐·PNG를 비교한 경로이며, 약 31초의 합성 음성, 화면 밖의 두 고정된 화자 역할, 한 종류의 경고음으로 구성한 통제 자료에서 대응을 확인했습니다. 화자 역할은 별도로 녹음한 구간과 원본의 상관 기록 및 역할 설명에 연결했습니다. 잡음이 많은 대화, 임의의 음악·효과음 식별, 빠르게 움직이는 화면, 일반적인 화자 분리나 모든 모바일 플레이어의 표시 상태는 측정하지 않았습니다. 이런 콘텐츠는 실제 음성·영상 처리 기록을 추가하고, 중요한 부정·화자·소리의 의미를 사람이 원본에 대조해 미확인 부분을 남겨야 합니다.

## 팀에서는 자막 파일과 원본의 관계를 함께 관리합니다

음성 인식은 초안을 만드는 데 도움이 됩니다. 하지만 자동 전사는 부정 표현을 잘못 인식하거나, 화자와 소리의 의미를 놓칠 수 있습니다. 따라서 자막을 만든 과정과 검수할 원본을 연결해 둡니다. 영상이 수정되면 자막의 문장만이 아니라 시간과 누락 여부도 다시 확인해야 합니다.

수정 요청은 “자막 전체 개선”보다 원본 구간과 큐를 지정하는 것이 좋습니다. 예를 들어 “A2의 부정 표현을 원본 의미에 맞게 바꾸고, 독립 전사에서 확인한 7.71–11.18초 답변을 듣지 않은 상태로 읽어도 코드를 버리면 안 된다는 뜻을 이해하는지 다시 확인”처럼 기록합니다. 경고음 누락이라면 소리가 발생한 시점과 그 의미, 추가할 자막 및 표시 시간을 함께 지정합니다.

모델 결과를 저장할 때는 실행 여부와 접근성 판정을 분리합니다. 자료를 읽은 실행이 성공했어도, 원본 뒤쪽을 확인하지 못했다면 충분성을 판단할 수 없습니다. 반대로 일부 구간을 보지 못했더라도 확인한 구간에서 지시가 뒤집힌 사실이 입증되었다면 그 위반은 기록할 수 있습니다. 미검토 구간을 합격으로 채우지 않는 것이 핵심입니다.

## 실무 검토 체크리스트

- [ ] 평가할 페이지 상태와 매체 목록, 제외 범위를 기록했습니다.
- [ ] 실제 콘텐츠를 보고 녹화 동기화 매체와 음성 전용·무음 영상·실시간 매체를 구분했습니다.
- [ ] 본문 대안 예외는 추가 정보 없음과 명확한 표시를 모두 확인했습니다.
- [ ] 대사뿐 아니라 이해에 필요한 화자 변경과 중요한 소리를 확인했습니다.
- [ ] 부정·조건·수치·순서·경고의 의미가 자막에서 유지됩니다.
- [ ] 의미가 같은 축약을 단순한 문자 차이로 실패 처리하지 않았습니다.
- [ ] 폐쇄 자막을 실제로 선택·표시하거나 개방 자막을 실제 화면에서 확인했습니다.
- [ ] 자막의 원본 구간과 표시 구간, 이용에 미치는 영향을 연결했습니다.
- [ ] 긴 자막과 작은 화면, 조작부 표시 상태에서 필요한 내용을 읽을 수 있습니다.
- [ ] 자막이 중요한 화면 정보를 가리지 않습니다.
- [ ] 전사·도구·표본 화면의 한계와 미검토 구간, 자료 충돌을 남겼습니다.
- [ ] 수정과 재점검 방법을 매체 ID·시간·큐·증거에 연결했습니다.

## 평가 프롬프트를 사용하기 전에

아래 통합 프롬프트의 입력란에 평가 범위와 실제 자료를 넣습니다. 모델이 음성·영상·이미지 중 무엇을 직접 처리할 수 있는지, 브라우저나 파일을 읽는 도구가 있는지 먼저 확인합니다. 도구가 없으면 수집한 전사와 화면, 처리 기록을 제공하되 그 자료의 한계를 함께 전달합니다.

아래 프롬프트는 **1.2.2 평가를 위한 완성본**입니다. 실제 자료로 입력란을 채우고, 반환된 시간·큐·근거를 원본과 대조합니다. 정상 자막 하나만 반복하기보다 내용 누락, 시간 차이, 예외, 자료 부족을 함께 확인하면 판정의 경계를 검토할 수 있습니다. 프롬프트의 완성은 모든 매체의 자동 적합성 판정을 보장한다는 뜻이 아닙니다. 검증한 입력에서도 개방 자막의 전체 표시 시간은 추가 확인이 필요했고, 출력의 처리 구간 기록에는 모호함이 남았습니다. 같은 조건을 새 자료에 적용할 때 이 한계부터 재점검합니다.

### 입력란을 채우는 예

다음은 실습의 전체 자막 조건 중 A2를 다시 찾는 데 필요한 입력 형식의 예입니다. 자료 ID는 파일명 또는 검토 기록에서 정한 식별자이며, 같은 원본을 가리키도록 연결합니다. 아래 발췌만으로 영상 전체에 충족을 부여할 수는 없습니다.

```text
범위: 전체 자막 실습 페이지의 복구 코드 안내 M1.
목적: 안내 내용을 이해하기. 실제 계정 발급은 수행하지 않음.
원본: M1, 사전 제작 음성·영상, 컨테이너 길이 31.208333초.
  디코드 음성 길이 31.189초. 길이 차이의 꼬리 구간은 별도 기록함.
자료 SOURCE-ASR: M1에서 후보 자막과 별도로 추출한 시간별 전사.
  7.71–11.18초 / 안내자: 아니요. 새 복구 코드를 저장하기 전에는 버리지 마세요.
자료 DELIVERY-C01: 브라우저에서 실제 읽은 자막 큐와 표시 기록.
  A2 / 7.60–11.60초 / 같은 답변, 자막 트랙 showing.
자료 DISPLAY-C01-1: 9.4초의 실제 화면 PNG를 별도 첨부.
  이 줄의 ID만 입력하는 것은 이미지 첨부가 아님.
한계: 여기서는 A2만 발췌함. 나머지 원본·큐·화면은 별도 제공해야 함.
```

원본 파일의 해시는 최종 파일에서 계산해 붙이고, 추출 전사에도 같은 원본 해시와 사용한 도구·처리 구간을 남깁니다. 전사문은 자막 후보에서 복사하지 않고 원본 음성을 별도로 처리하거나 직접 들어 작성한 뒤, 부정 표현과 조건을 다시 대조합니다. 자막 큐는 실제 플레이어에서 로드된 `video.textTracks`의 `cues`를 확인해 ID·시작·종료·문장을 기록할 수 있습니다. 같은 시점으로 탐색해 화면 PNG를 캡처하고 트랙의 표시 상태를 함께 적습니다. 화면 몇 장으로 전체 표시 상태를 확인했다고 쓰지 않습니다.

모델에 전체 범위를 맡기려면 모든 대사와 중요한 소리, 전체 큐 목록, 필요한 표시 관찰과 미검토 구간을 함께 제공합니다. 예외를 주장하는 경우에는 연결된 본문 전체와 실제 안내 문구도 필요합니다. `direct_audio_review` 같은 출력 필드는 모델의 자기보고이므로 실제 도구 실행 기록으로 확인해야 하며, `true`라는 값만으로 직접 청취를 입증할 수 없습니다. 전사·큐·PNG의 원본 연결이 불분명하면 먼저 자료를 보완합니다.
