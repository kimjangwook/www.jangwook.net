## 각각의 기준을 하나의 작업 과정으로 연결하기

이 시리즈에서 개요와 86개의 성공 기준을 살펴봤습니다. 마지막 단계에서는 개별 평가의 입력과 결과를 연결하겠습니다. 통합 시스템의 목표는 웹사이트의 중요한 이용 흐름을 확인하고, 항목별 판단의 근거를 유지한 채 개선과 재점검으로 이어가는 것입니다.

저는 먼저 대상 범위와 완료 조건을 정하겠습니다. 어떤 페이지와 상태를 점검했고 어떤 작업을 완료했는지 설명할 수 있어야 합니다. 점검 결과가 많아도 주요 과정의 중간 상태를 빠뜨리면 이용자의 장벽을 놓칠 수 있습니다.

## 서비스의 평가 구조

첫 단계는 범위 정의입니다. URL, 로그인 상태, 대표 이용 과정, 브라우저와 입력 방식, 목표 WCAG 버전·수준을 정합니다. 페이지별 성공 기준뿐 아니라 완전한 과정과 보조 기술 지원도 고려해 평가 범위를 설명합니다.

두 번째는 증거 수집입니다. 브라우저 에이전트가 화면, DOM, 접근성 트리, 포커스·포인터 기록을 같은 상태 ID에 연결합니다. 음성과 영상이 필요한 기준에는 처리 가능한 매체와 시간 코드를 함께 준비합니다. 수집 실패는 평가 결과에서 숨기지 않습니다.

세 번째는 평가 모듈 실행입니다. 기준별 프롬프트에 필요한 자료만 전달하고, 계산 가능한 조건은 측정 도구로 확인합니다. 멀티모달 모델의 의미 판단과 규칙 검사 결과를 결합하되 서로 다른 결과는 근거를 비교할 검토 항목으로 남깁니다.

네 번째는 결과 정리입니다. 같은 요소에서 나온 문제를 기준별 근거를 유지하며 연결하고, 이용자 영향·핵심 흐름·반복 범위로 우선순위를 정합니다. 확인한 범위와 미실행·판단 유보를 함께 전달합니다.

다섯 번째는 개선과 재검증입니다. 제안한 수정의 범위와 책임을 정하고 같은 조건으로 실행합니다. 변화 이력에는 해결된 항목, 여전히 남은 문제, 새롭게 발생한 문제를 모두 기록합니다.

## 실제 서비스로 만들 때의 역할 분담

오케스트레이터는 범위·수집·평가·검토·재점검을 조율합니다. 수집 모듈은 브라우저 실행과 자료 저장을 맡고, 평가 모듈은 기준별 입력 계약과 구조화된 결과를 사용합니다. 보고 모듈은 원본 증거로 돌아갈 수 있는 링크와 개선 순서를 제공합니다.

사용자에게는 URL과 점검할 흐름을 입력하고 진행과 결과를 확인하는 간단한 화면을 제공합니다. 내부에서는 실행 ID, 재시도, 비용, 모델·프롬프트 버전, 오류를 관리해야 합니다. 실패한 실행을 새로운 성공 결과로 덮어쓰지 않겠습니다.

## 평가 성능을 업데이트하는 기준

모델을 바꾸거나 프롬프트를 수정할 때에는 같은 정상·실패·경계 사례로 다시 평가하세요. 적용 여부 판단, 문제 탐지, 근거의 정확성, 오탐과 누락, 반복 일관성, 소요 시간과 비용을 구분합니다. 평균 수치만 보여주기보다 어떤 항목과 입력 조건에서 달라졌는지 설명하는 자료가 필요합니다.

이 실험의 결과는 글과 프롬프트와 서비스 설정에 함께 반영합니다. 모든 기준을 매번 같은 방식으로 실행하기보다 목표 범위와 필요한 상태에 맞는 모듈을 선택하고 그 선택 이유를 기록하겠습니다.

## 학습 자료와 서비스의 연결

개별 글에서는 기준과 프롬프트를 공개합니다. 모음집은 전체 프롬프트, 준비할 자료, 실행 순서, 결과 해석을 하나의 자료로 제공합니다. 방문자가 폼에 이메일을 입력하면 내부 DB에 시리즈 자료 신청과 전달 상태를 기록하고 해당 주소로 모음집을 전달합니다.

자료 신청과 업데이트 구독은 분리합니다. 구독을 선택한 사람에게는 이메일 확인 이후 해당 시리즈의 변경 소식을 제공할 수 있습니다. 관심 시리즈와 요청 이력이 서비스 수요를 파악하는 단서가 되지만, 신청 자체를 유료 구매 의사로 단정하지 않습니다.

유료 서비스는 자료 수집·평가 실행·결과 정리·변경 후 반복 점검의 작업을 대신 수행하는 가치를 제공합니다. 단건 진단, 지속 점검, 개선 컨설팅은 범위와 전달물을 구체적으로 정한 뒤 제공하겠습니다.

## 현재 만들어진 것과 다음 제품 단계

현재 로컬 웹사이트에는 시리즈와 프롬프트 라이브러리, 자료 신청, D1 리드 저장, 메일 생성·자료 전달 경로, 서비스 소개 구조가 구현되어 있습니다. 글과 프롬프트는 검토 초안입니다. 실제 멀티모달 진단 실행 엔진, 가격·결제·고객 서비스는 후속 제품 단계입니다.

이 글의 최종 공개본에서는 검증한 서비스의 실제 사용 화면과 제공 범위, 실행 결과를 소개해야 합니다. 현재 단계에서 서비스를 완성했다고 서술하지 않습니다. 사용자가 쉽게 적용할 수 있도록 어떤 작업을 제품으로 묶었는지 실제 구현 근거와 함께 설명할 계획입니다.
