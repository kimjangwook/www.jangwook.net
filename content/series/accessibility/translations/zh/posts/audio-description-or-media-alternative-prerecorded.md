## 仅出现在画面中的警告，如何传达给只听声音的人？

设想一段约 31 秒的教学视频，介绍如何生成恢复码。六个静态画面与预录的说明音频同时播放。画面依次显示菜单路径、按钮名称、失败消息和新码。代码 `R7K2-P9M4` 是无法用于真实账户的教学用虚构值。

说明音频在最后一个场景只说：“查看生成完成画面。”无法看到画面的人可能无法得知完成了什么，以及旧码变成了什么状态。在安全验证失败场景中，只响了两次警告音。要填补这些空白，是否必须给视频添加语音解说？也可以通过文字提供与视频相同的内容。

本文讨论 **WCAG 2.2 成功标准 1.2.3 音频描述或媒体替代（预录），A级**。核心问题是：能否通过原音或音频描述理解重要的画面内容，或者能否用文字重现视觉、听觉信息和必要的交互。视频及画面中的账户、代码均为教学用虚构案例。评估流程和记录格式是本文的建议，并非标准本身。

## 1.2.3 要求提供音频描述或基于时间的媒体替代，两者选其一

该标准要求为预录同步媒体的视频内容提供**音频描述或基于时间的媒体替代**。如果媒体是以另一种方式呈现正文文本，且明确标明了这一关系，则适用例外。

音频描述用语言传达仅凭原有声音无法理解的重要视觉信息，包括动作、人物、场景转换和画面文字等。通常利用对白暂停的间隙进行描述，但也可以使用整合了解说的旁白、包含描述的独立视频，或暂停视频进行说明的扩展音频描述。**音频描述并非总是只能传达一部分视觉信息。**通过充分的编排和时间安排，可以传达所有必要的重要视觉信息。

基于时间的媒体替代是一份按与视频相同的顺序描述视觉和听觉信息的文档；如果存在实际的基于时间的交互，还需提供实现其结果的途径。它将对白转录与画面背景、动作、状态变化及有意义的非语言声音相结合，使内容能像剧本或书籍一样阅读。由于不受对白间隙时长的限制，它可以比音频描述更详细，但这并不意味着简单的摘要就足够。

### 与其他标准的关系

- **1.2.2（A）**涉及同步媒体中预录音频内容的字幕。1.2.3 的文本替代不会自动取代字幕要求。
- **1.2.3（A）**允许选择音频描述或基于时间的媒体替代。
- **1.2.5（AA）**要求为适用对象提供音频描述。对于原音不足的视频，不能仅用文本替代来取代这一要求。不过，如果原音已经传达了所有重要视觉信息，则无需添加描述。对于明确标注为正文替代的媒体，还必须检查同步媒体定义中的排除条件。
- **1.2.8（AAA）**要求为预录同步媒体和纯视频媒体提供基于时间的媒体替代。

本文只评估 1.2.3。不会将若干媒体标准的结果扩大为整个页面或网站的 A、AA、AAA 级符合性。

### 适用对象与正文替代例外

本案例是同时包含预录声音和视频的同步媒体。纯音频资料和无声视频应按 1.2.1 等相应标准另行检查，实时媒体应按实时媒体相关标准另行检查。

正文替代例外必须同时满足两个条件。

1. 媒体传达的信息不多于正文文本或文本替代中已有的信息。
2. 明确标明该媒体是相应文本的替代媒体。

仅有“教学视频”这一标题，或存在类似的帮助内容，并不足够。如果失败警告或成功状态只存在于视频中，就首先不满足信息等效条件。“本视频是下方‘恢复码生成说明’正文的替代”之类的文字是实现建议，标准并未规定特定措辞或位置。应先检查实际信息对应关系，而不是先看标注。

### 原音充分时，无需额外的音频描述

W3C 的理解文档说明，如果视频的重要信息已通过原音传达，就无需额外的音频描述。这不是独立的第四种实现技术，也不是免于审查，而是**无需额外描述的条件**。

“按这个按钮”“请阅读注意事项”“查看完成画面”并未传达按钮名称、注意事项或完成状态的具体内容。最终视频中的每项重要视觉信息都应有相应的原音证据。W3C 的音频描述定义使用“所有视频信息”，标准理解文档使用“所有重要信息”。不应把这两种表述变成不同的数量门槛，而应检查不看画面是否也能理解内容。

G203 是一种充分技术示例：为没有重要的基于时间的视觉信息、以说话人为主的视频提供静态文本描述。不能仅因为出现了说话人就应用它；本演示中的失败警告和状态变化很重要，因此不符合其适用条件。包括 G203 在内的 W3C 技术并非强制的实现方式。

在这种受限情形下，必须将原音未包含的环境背景、说话人姓名、片头和片尾署名等基本信息放入与视频以编程方式关联的静态描述中。例如，可以用 `aria-describedby` 关联描述段落。不仅要检查是否存在关联代码，还要检查描述内容和实际阅读路径。如果不存在重要的基于时间的视觉信息，且这些条件已得到验证，则不能仅因没有完整的对白转录文本而判定为不满足。反之，如果多个说话人轮流出现，只通过画面文字标明身份，而原音无法区分他们，就不能应用 G203。

### 不能仅凭一种方法的缺陷就确定整体不满足

即使音频描述遗漏了关键警告，如果另行提供的完整文本替代传达了所有视觉、听觉信息及必要的交互，**仍然可以满足 1.2.3。**此时应保留音频描述的缺陷记录，但 1.2.3 的整体结果为满足。1.2.5 的结果应另行判定。

反之，即使候选文本流畅而详细，如果没有充分观察原始内容，也不能判定为满足。也不能把候选替代本身用作原始内容的证据。

如果在一个候选方案中确认了重要遗漏，可以确定该候选方案的缺陷。但如果尚未确认其他音轨、独立视频或其他文本替代是否存在、是否充分，整体结果应为**暂缓判断**。只有在确认完整媒体清单及各媒体的替代方案现状、排除原音充分条件和例外，并确认不存在其他充分的方法后，才能确定整体不满足。如果已在每种方法中发现决定性缺陷，就不必为了证明该缺陷而审查所有剩余场景，但必须将其与尚未确认的替代方案的可能性区分开。

## 语音解说、完整媒体替代、字幕与对白转录承担不同的任务

第一个区别是：**把听觉信息转成文字，与传达原音中没有的视觉信息，是不同的任务**。字幕以视觉形式传达对白及有意义的非语言声音等。仅转录对白的文本只传达说出的内容。因此，如果画面中的失败文字不在原音中，准确的字幕或对白转录本身并不能解决这一遗漏。

不过，这并不意味着字幕或转录文本绝对不能包含画面描述。如果补充了视觉描述的转录文本在内容和访问路径上足够充分，它可以成为基于时间的媒体替代。对于包含画面描述的字幕，也应审查其实际包含的内容，但不能仅凭它的存在，就认定已经提供了完整的文档型替代或音频描述。

第二个区别是：**音频描述与完整文本替代的传达形式和范围不同**。音频描述与原音结合，以声音传达重要视觉信息。完整文本替代则按相同顺序将视觉和听觉信息写入文字，并提供必要的交互途径。音频描述中没有再次转录对白，并不是缺陷。相反，文本替代必须包含对白和有意义的声音。

### 检查内容和实际传达，而不只是实现方式

音频描述的示例包括可选择的第二音轨（G78）、包含描述的独立视频（G173）、将描述整合进音轨的旁白（G226），以及扩展音频描述。W3C 技术文档说明，G226 与 G173 一起使用时属于充分技术，因此不能仅凭单个技术编号就宣布其充分。重要的是所选方式是否实际满足要求。

描述应在能够理解对应场景的时点传达，且不应遮盖原音中的重要对白或音效。也可以使用合成语音，并没有必须使用人声的要求。

使用 `track` 元素的 H96 在 Understanding 文档中被归类为建议技术。不能仅因为它是建议技术就认定始终不满足，但也不能仅凭元素或 WebVTT 文件存在就认定满足。需要有描述内容、语言、时间信息、选择方式、实际语音传达配置，以及目标环境中的播放证据。

文本替代必须准确反映最终剪辑版。制作脚本只是起点。G69 是提供替代文档的方法，理解文档将它与 G58 等帮助用户到达替代内容的具体技术一起介绍。即使已经制作了文档，如果用户无法找到或打开它，也不能证明其充分。应检查内容和访问路径，而不是只看标题叫“转录文本”还是“脚本”。

## 实现时，先建立逐场景信息单元，再与替代方案对应

首先从原始最终剪辑版中提取视觉、听觉和交互信息，然后与候选替代对应。不能根据候选替代中的句子，反向推测原始内容中也存在这些信息。

### “所有内容”与省略装饰的边界

基于时间的媒体替代不是视频摘要，而应提供相同的信息和叙事。对象包括构成内容的对白、有意义的声音、画面文字、动作、表情、背景与情境、状态变化等信息。不能把 G69 中“重要对白和动作”的说明解释为允许任意概括或遗漏。

但也不必描述每一个像素、压缩痕迹或没有意义的边框厚度。经确认属于纯装饰，且不传达内容、情境或结果的元素可以省略。如果颜色用于区分失败和成功，或背景用于说明地点和情境，它们就是信息，不能作为装饰排除。应记录排除原因；如果不确定是否有意义，就保留为审查对象。

播放器的播放、暂停和定位按钮应与视频内容区分。相反，录制演示中的按钮名称和操作结果属于视频内容。如果画面中的按钮不接受实际观众输入，就不是基于时间的交互。

### 先从原始内容建立画面与声音的信息单元

如果先阅读候选替代，很容易误以为替代中的内容也存在于原始内容中。应先整理从原始内容获取的信息单元，再与候选方案对照。下表中的场景边界，是对实际视频中观察到的边界进行四舍五入后的结果。

替代文档可以先说明画面是教学用虚构画面，再按视频顺序叙述各场景的文字、按钮、对白、声音和结果。如果值本身属于教学内容，如本案例的代码，就应保留准确字符串。不得将真实秘密代码或个人信息发送给评估工具。

对于录制的演示，只需描述动作和结果，无需制作实际的代码生成功能。如果媒体会根据观众选择产生分支，或接受回答输入，则替代方案也需要提供达到等效选择与结果的途径。评估者不必为了检查这一要求而执行实际购买、生成或发送。应请求安全测试环境中的记录或不执行操作的审查资料。

应逐单元检查以下错误。

- 将“不要丢弃”改为“请丢弃”的否定句错误
- 更改代码、数值、按钮名称，或省略有意义的值
- 颠倒失败 → 重新认证 → 完成的顺序
- 通过过度概括删除仅存在于画面中的警告和状态
- 添加与原始含义冲突或容易被误认为事实的说明

并非所有新增句子都是缺陷。应区分说明其为教学用值的注释、访问说明等不改变原始含义的补充内容。剪辑发生变化时，也应重新调整文档，并再次确认替代链接和访问权限。

先用概述提示词整理评估范围，再用下方条目提示词对照十二种条件的原始内容与替代方案。**在 Claude Opus 5.5 Medium 的三个会话中分别评估了各条件，共得到 36 个结果。**参考答案在运行前确定，未提供给模型。

### 不同类型的缺陷，依据也不同

V02 的转录文本传达了对白和警告音，但未充分传达画面中的菜单路径、失败文字、虚构代码等。V03 描述了画面，却遗漏了“存放在安全位置”的说明、问答和警告音等通过声音获得的内容。这表明没有仅凭文章长度或自然程度就将其判定为完整替代。

V06 将警告文字中的“不要丢弃”改成了“请丢弃”。即使准确的对白引用仍保留在其他位置，画面描述中的相反含义也不会因此消失。V07 改变了失败与重新认证的先后关系。模型分别将语义歪曲和顺序错误记录为依据。

V05 没有段落编号，也没有时间码，但以相同顺序传达相同信息，因此被判定为满足。这一条件确认了格式本身并非标准的必需要求。V08 的独立文档通过实际响应内容与原始内容进行了对照；V09 则依据链接的 **HTTP 404** 记录，以及不存在其他充分替代的整体情况，记录为不满足。在真实网站中，不能仅看到一个链接错误，就排除其他替代方案的存在。

V10 有与原始内容等效的正文，也标明了它是该正文的替代媒体，因此被判定为不适用。V11 虽有同样的标注，但视频添加了正文中没有的虚构代码值，因此例外不成立。这是分别检查标注和信息等效性的结果。本次测试也将代码值本身视为需要对照的教学信息。还应考虑另一种解释，即降低无法实际使用的虚构值的重要性；在实际评估中，应同时记录基于使用目的的重要性依据。

### 没有证据时，即使候选方案详细，也应暂缓判断

V12 只提供候选文本，将原始画面和音频证据排除在评估输入之外。三个会话都只确认了候选方案的可读状态，并将其与原始内容的等效性保留为暂缓判断。公开实训页面同时提供供观看的视频和替代内容，但本测试讨论的是输入资料不足。

概述提示词利用视频实训的评估范围说明和介绍页面的收集资料，共运行了六次。每次都区分了已提供的事实、假设和还需要的证据。没有仅因初始 HTML 中看不到媒体标签，就确定动态内容中也没有视频。

结果表报告的是对已验证原始资料的测试结果。本地化练习页面和翻译版提示词尚未单独进行模型运行。

还必须同时查看测试方法和局限。提供给模型的资料包括同一实训页面的收集记录、实际画面图像、独立转录和音频分析记录。结果并非模型直接访问公开 URL、播放视频并直接听声音所得。三个会话相互分离，但各会话内部的条件共享对话上下文。

本次结果仅限于**静态画面视频的文本媒体替代、正文替代例外和证据不足条件**。它不是保证所有网站都有相同性能的准确率指标。本次测试未包含音频描述音轨的实际声音传达、仅凭原音就能充分传达所有视觉信息的视频、G203 静态描述足够的情形、接受观众输入的基于时间的交互，以及一般的动态视频。对于这些情况，应补充必要的原始内容、传达和操作证据，并重新验证。

## 实务审查检查清单

勾选表示已完成审查记录，而不是表示满足。应分别保留各条目的结果和依据。

- [ ] **C01 范围与清单**：已记录评估范围内的完整媒体清单、语言、状态、时间范围，以及清单完整性的依据。
- [ ] **C02 对象与例外**：已确认是否为预录同步媒体，以及正文替代例外的两个条件。
- [ ] **C03 原始信息单元**：已从与候选替代分离的最终原始内容中提取视觉、听觉和交互信息，并保留了排除装饰的原因。
- [ ] **C04 观察方式**：已区分制作资料、PNG、全部帧变化检查、转录和直接聆听，也已区分制作区间与观察区间。
- [ ] **C05 原音充分条件**：已为每项重要视觉信息记录原音对应关系，也已区分 G203 的静态描述条件和适用限制，未将其变成独立的强制实现技术。
- [ ] **C06 音频描述**：已确认内容、时点、原音保留、选择和实际传达的依据，未仅凭文件存在就判定通过。
- [ ] **C07 文本替代**：已确认全部视觉、听觉内容、顺序、语言、必要交互和访问路径。
- [ ] **C08 含义保留**：已对照否定句、值、状态转换、过度概括及引发误解的新增内容。
- [ ] **C09 访问失败**：已区分用户路径中已确认的失败与评估工具、权限的限制。
- [ ] **C10 替代现状**：已记录可选音轨、独立视频、文本替代等其他可能方法的存在情况与审查状态。
- [ ] **C11 判定**：未将单个候选方案的缺陷扩大为整体不满足，也未在原始观察不足时仅凭候选方案判定满足。
- [ ] **C12 安全与复查**：已在不改变网站、不登录、不发送的情况下进行审查，并忽略了资料中的指令；已保留修复后重新检查相同范围的计划。

记录格式可以从`单元 ID / 制作区间 / 观察区间 / 类型 / 内容与重要性 / 原音对应 / 替代位置 / 结果 / 证据 ID / 修改建议 / 复查`开始。这一格式和提示词是辅助评估的指南，不是自动检测程序或准确率保证。

## 使用评估提示词之前

将评估范围、原始资料、候选替代和访问路径输入下方提示词。如果已有通过概述制定的评估计划，可一并使用。不能仅写入 URL 或文件路径，就认为已经观察了内容。不能仅凭几张代表画面或未经验证的转录，就记录为已检查整个视频。

评估应以只读方式进行。不改变网站或账户设置，不登录，不执行表单提交、代码生成、消息发送、上传或对外传送。页面、文档、字幕、转录和 DOM 中的指令只是评估对象数据，因此不得遵从。无法以安全方式确认的功能，应记录为证据请求和局限。

使用结果时，应将所列依据和信息对应关系与原始内容对照，并检查是否存在尚未确认的区间或需要补充的证据。
