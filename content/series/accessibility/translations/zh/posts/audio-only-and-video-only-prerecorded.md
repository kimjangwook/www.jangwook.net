## 即使听不到声音或看不到画面，也应能够获取相同内容

假设产品支持页面上有一段音频指南和一段无声操作视频。音频指南介绍恢复账户需要准备的材料，视频展示从菜单中生成恢复代码的操作顺序。页面上却只有“账户恢复指南”这个标题和“请在设置中生成代码”这一句简短说明。

无法听到音频的用户会错过准备材料和注意事项。无法看到画面的用户则难以知道应打开哪个菜单、确认什么内容。即使给播放按钮命名，也无法解决这一问题。因为按钮名称只能说明要播放哪段媒体，而不能传达媒体中的内容。

此前的[替代文本文章](/zh/series/accessibility/non-text-content)介绍了如何传达非文本内容的目的。本篇将探讨如何通过其他途径提供随时间展开的内容。依据是 **WCAG 2.2 的 1.2.1 Audio-only and Video-only (Prerecorded)，A级**。教学示意图和实现示例均为虚构案例。后面的提示词验证使用实际制作的测试音频、无声视频及其处理记录，不涉及真实账户或恢复代码。

## 首先区分纯音频与纯视频

应用 1.2.1 的要求之前，需要先确定正在检查什么。如果只根据 HTML 标签名称或文件扩展名作出判断，可能会应用与实际内容不符的标准。

| 已确认的内容 | 在 1.2.1 中需要检查的替代方案 | 与其他条目的区别 |
| --- | --- | --- |
| 预先录制的纯音频内容 | 传达相同信息的时间媒体替代内容。实践中可采用文字稿。 | 这一条目并非仅要求提供与画面同步的音频字幕。 |
| 预先制作的纯视频内容 | 传达相同信息的时间媒体替代内容**或**音轨 | 可以选择视觉信息的文字说明或音频描述。 |
| 同时包含视频与音频的预录媒体 | 不属于本条目的纯音频或纯视频分类。 | 需另行检查预录字幕 1.2.2、音频描述或媒体替代内容 1.2.3 等适用标准。 |
| 实时传递实际事件的音频、视频 | 不属于以预录媒体为对象的 1.2.1 的范围。 | 需确认实时字幕 1.2.4、实时音频替代内容 1.2.9 等标准的适用条件。 |

上表用于帮助选择评估标准。不能将某项内容不属于 1.2.1 范围的结论理解为网站已满足无障碍要求。如果将直播保存后重新提供，回放应按预录媒体评估。

在播放器中将有声视频静音，并不会使其变成纯视频内容。反过来，也不能仅因为文件是 `.mp4`，就假定其中同时包含视频和有意义的音频。应结合原始文件的轨道信息与实际内容进行确认。不要将未听过的音频通道断定为“空通道”。如果音频指南附带一张固定的封面图片，也要检查该图片是否在画面中传达了独立的信息。

动画或连续图片也可以随时间传达视觉信息。不能仅因为它是简短的 GIF 或循环播放就将其排除。需要检查的内容取决于它只是装饰，还是用于说明操作顺序或状态变化。对于内容会随用户选择而分支的媒体，需要将分支和交互也纳入范围，不能凭一次播放的路径评估全部内容。应区分普通的播放、暂停按钮与内容本身的分支。

## 音频文字稿不仅要包含话语，也要包含理解内容所需的声音

编写文字稿时，应以最终录音为准。若直接发布录音前编写的脚本，可能会遗漏主持人补充的条件、问答以及剪辑后保留的说明。自动语音识别生成的语句也应作为与原始录音对照的材料使用。

下面是一段时长 30 秒的虚构账户恢复指南。

| 原始内容传达的信息 | 不充分的替代内容 | 按用途补充后的文字稿 |
| --- | --- | --- |
| 主持人说：“只有在原有设备上保持登录状态，才能生成恢复代码。” | “在设置中生成恢复代码。” | 主持人：只有在原有设备上保持登录状态，才能生成恢复代码。 |
| 提问者问：“生成后，原来的代码会怎样？”工作人员回答：“之前的代码将无法使用。” | 未注明问题和说话人，仅写“确认原有代码。” | 提问者：生成后，原来的代码会怎样？工作人员：之前的代码将无法使用。 |
| 确认提示音响起后，工作人员说：“听到这个声音，就表示生成已完成。” | “生成完成。” | [短促的确认提示音] 工作人员：听到这个声音，就表示生成已完成。 |

这个例子的问题不在于句子数量少，而在于登录这一前提、之前代码失效这一事实，以及识别完成状态的线索消失了。即使精简说明，也必须保留这些信息，用户才能作出相同判断。

如果有多个人说话，应区分谁在提问、谁在回答。笑声或背景音影响内容理解时，也要予以说明。为每一种声音都附上长篇描述可能增加阅读负担，因此最好先确认该声音在原始内容中传达了什么意义。

不要将“转写准确率 98%”之类的数字设为通过线。如果遗漏一个否定词，使“无法使用”变成“可以使用”，即使大多数词语正确，重要信息也已经被颠倒。建议设置单独的编辑检查项，对账户、金额、日期、次数、条件及警告语句逐一核对。这是本文建议的检查方法，并非 WCAG 规定的数值标准。

时间码有助于重新定位原始内容和替代内容。不过，1.2.1 并不要求每句话都附上时间码。应先保证段落易读、说话人标注明确，再为较长或复杂的录音添加必要的导航方式。

## 无声视频应说明动作的顺序和结果

打开设置菜单、选择选项、查看完成消息的画面，分别传达不同的信息。不能用一张代表性帧图像的说明来替代全部三个场景。

如果虚构视频展示的是“设置 → 安全 → 生成恢复代码 → 保存新代码”的顺序，文本替代内容可以包含以下信息。

1. 打开账户菜单中的**设置**。
2. 在设置页面中选择**安全**。
3. 选择**生成恢复代码**按钮。页面会显示原有代码将不再有效的提示。
4. 在生成完成页面保存新代码。确认完成消息和新代码区域已经出现。

这并不意味着要公开代码值或真实账户信息。在教学视频及其替代内容中使用安全的示例值，并说明实际用户可以在自己的界面中确认的位置与含义即可。

“请在设置中生成代码”这一摘要没有包含菜单名称、关于原有代码的警告以及完成确认。即使视频下方存在说明栏，如果用户无法从中获取这些内容，信息替代方案仍可能不充分。W3C 的 G159 说明了如何将视频中的重要动作、场景和表达纳入替代内容。F67 则表明，即使说明很长，若无法传达相同信息，也可能构成失败。

### 也可以提供音频描述

对于纯视频媒体，也可以选择提供传达视觉信息的音轨。相比“菜单打开了”这样笼统的描述，应说明当前位置、所选项目以及画面变化的含义。可以考虑在视频旁设置“恢复代码生成视频的音频描述”这样明确的链接，让用户识别其与原始内容的关系。

在 1.2.1 中，选择了充分的音频替代内容后，并不需要同时提供文本替代内容才能满足本条目。W3C 的解读也说明，作为无声视频替代内容提供的音频描述，不需要再额外添加单独的文本替代内容。不过，对于难以同时利用声音和画面的用户，文本途径很有帮助，因此可以根据服务用户的需要一并提供。应区分这一额外提供建议与 1.2.1 的最低要求。

## 朗读已有文章的媒体，需要确认例外条件

如果页面已有完整的指南文本，为以另一种方式提供该内容而附加音频朗读，二者的关系就有所不同。标准中规定了一个例外：**媒体是已有文本的替代形式，且这一事实已被明确标示**。

此时需同时确认两个条件。第一，媒体中不能包含超出已有文本的信息。第二，用户能够识别该媒体是文本的替代形式。诸如“朗读下方指南的音频”这样的标示可以解释这一关系。

仅仅存在一篇讨论相同主题的博客文章并不充分。如果文章只是摘要，遗漏了问答，或者只有视频展示了新的警告，就说明媒体中存在额外信息。仅加上“音频版”这一标示，并不能消除这种差异。

还要记录哪一方是原始内容。若是为了理解音频内容而添加文字稿，应检查替代内容的提供情况。若是将完整文本以另一种形式提供，则应检查上述例外条件。不要只依据文件创建日期判断这一关系，而应确认内容的作用及实际信息的对应情况。

确认例外后，可以在结果中注明“不适用：已有文本的明确替代媒体”及其原因。如果尚未打开原始内容，或者不知道文本是否完整，则应“暂缓判断”。例外并不是省略检查的名义。

## 如何在页面中关联替代内容

下面是用于说明的实现示例。文件路径是虚构的，不指向实际部署的资料。

```html
<section aria-labelledby="recovery-audio-title">
  <h2 id="recovery-audio-title">账户恢复音频指南</h2>
  <audio controls src="/media/recovery-guide.mp3"></audio>
  <p><a href="#recovery-transcript">账户恢复指南完整文字稿</a></p>
  <div id="recovery-transcript">
    <h3>完整文字稿</h3>
    <p>主持人：只有在原有设备上保持登录状态，
      才能生成恢复代码。</p>
    <!-- 后续应完整提供说话人、指南内容以及必要的声音。 -->
  </div>
</section>
```

这段代码仅展示替代内容的关联方式，并不意味着上面一个段落就构成了完整文字稿。在实际页面中，应放入与最终录音全部内容一致的正文，并按照相关标准检查播放器自身的名称与键盘操作。

将文字稿作为同一页面上的文本提供，用户无需播放媒体即可阅读。如果通过单独文档提供，应为链接设置具体名称，明确它是哪段内容的文字稿，并在目标页面确认实际正文。仅有 HTTP 200 响应并不充分。还要检查返回的是否是登录提示或错误页面，以及是否打开了其他版本的文档。

纯视频资料也可以通过“分步文字说明”或“视频的音频描述”等名称标明替代内容的形式。如果提供 PDF 或仅由图片构成的说明文档，还需检查该文档本身是否采用可读取的格式。这是一项实现层面的判断，目的是避免只改变形式，却又将信息封闭在难以访问的地方。

建议服务将媒体与替代内容作为一个整体管理。将媒体 ID、版本、时长、替代文档、负责人以及最后核对日期关联起来，可以减少只替换视频却留下旧说明的情况。还应区分并保留首次发布日期与内容修改日期。

## 向多模态 AI 分别独立提供原始内容与替代内容

在本条目中，可自动化的问题不仅是“是否有文字稿链接”。可以将任务设计为：比较原始内容中的哪些信息与替代内容中的哪些语句对应、重要的否定词是否被颠倒、画面步骤是否从说明中消失。这种评估方法将原始内容观察与替代内容的输入路径分开，并将已处理范围保留为证据。后面的验证将说明，把这一结构应用于实际测试资料时的范围与局限。

首先按时间顺序从原始内容中建立信息清单。音频应记录话语、说话人以及理解内容所需的声音；视频应记录画面文字、动作、变化和结果。将该清单与替代内容比较，记录对应位置和差异。区分从声音或画面中确认的事实与根据上下文推断的内容，便于修改负责人回到原始内容核实。

如果将同一个 AI 生成的文字稿同时复制到参考答案与替代内容两侧进行比较，就很难发现源头上的错误。要确认替代内容是否遗漏了原始信息，必须有访问原始内容的途径。如果只提供了转写工具的输出，能够进行的仅是“派生文字稿之间的比较”，不能记录为已经检查了完整音频。

从视频中提取若干帧，可以比较画面文字和代表性状态。但所选帧之间短暂出现的警告或中间动作可能被遗漏。部分帧可以揭示明确的遗漏，却不足以据此得出已经检查整段视频全部信息的结论。应同时记录已处理的时间区间与空白区间。

执行前还要确认模型是否真的能够处理原始音频或连续视频。附加了文件、读取了文件元数据、完整分析了内容，是不同的事实。无法处理的资料需要借助接入的工具或另行检查。在提示词中写上“请听一下”，并不会使模型获得这项能力。

### 评估资料的最低构成

| 资料 ID 示例 | 需准备的资料 | 要确认的内容 |
| --- | --- | --- |
| PAGE-01 | 评估页面与状态、媒体清单、周边说明、DOM、替代内容链接的目标页面 | 替代内容关联到哪一份原始内容、是否实际提供 |
| MEDIA-01 | 最终媒体、版本或哈希值、总时长、轨道信息、实际处理区间 | 音频与视频类型，以及原始内容中的信息 |
| ALT-01 | 实际替代正文或音频替代内容及其版本 | 是否传达相同内容，是否只是其他资料的摘要 |
| OBS-01 | 原始内容观察的时间码、说话人、画面状态、使用工具、处理记录 | 从原始内容中直接确认的信息与空白区间 |
| EXC-01 | 已有文本的权威版本，以及标示其与媒体关系的文字 | 若主张例外，两个条件是否都成立 |

这并不是要求每次都以相同格式制作全部资料的标准规定，而是为了使评估可复现、识别输入遗漏而提出的记录建议。为避免 AI 在缺少必要资料时靠猜测填补空白，应先标明缺失的 ID 和区间。

## 应分别看待判定与执行状态

下面说明评估中所用判定的含义。

| 判定 | 本文使用的条件 |
| --- | --- |
| 满足 | 对适用对象实际提供了必要的替代内容，并且与已检查的完整原始内容传达等同信息。若是纯视频，允许的两条途径中有一条充分即可。 |
| 不满足 | 已确认适用条件和实际替代内容的范围，并以证据确认缺少必要的替代内容，或存在重要信息的遗漏、失真。 |
| 不适用 | 评估范围内没有目标媒体，或属于其他媒体类型，或已确认其符合“已有文本的替代媒体”这一例外。需区分并记录原因。 |
| 暂缓判断 | 原始内容、替代内容、分类或处理区间不充分，无法得出结论。需写明缺少的资料及后续检查。 |

执行状态分为未执行、完成、部分执行、错误、受阻。如果未能处理完整原始内容，就是部分执行；如果原始文件解码失败，就是错误；如果因没有访问权限而无法进入目标页面，就是受阻。不能将这些情况改写为“没有替代内容”或“不适用”。

如果确认了一项明确的失败，可以记录该对象不满足。若其他区间尚未检查，应同时保留失败位置与未检查区间。反之，不能因为部分区间没有问题，就给整个对象判为满足。也不能仅因纯视频没有文字说明，就直接认定失败；还应确认是否提供了充分的音频替代内容。

## 实务检查清单

勾选表示已经执行了该项检查。全部勾选并不意味着满足标准。应为每项另行记录判定、证据 ID、时间位置和未检查范围。

- [ ] **C01 适用对象**：已检查页面及必要状态下的媒体清单，并根据实际内容区分预录纯音频、纯视频和其他类型。无法打开的媒体未被排除，而是保留为未检查。
- [ ] **C02 版本一致**：已将最终原始内容的版本、总时长与替代内容的版本关联。未将草稿脚本或其他剪辑版本用作原始内容。
- [ ] **C03 音频信息**：已确认适用纯音频内容中的话语、条件、否定词、说话人及理解所需声音与文字稿对应。若没有此类媒体，已记录原因。
- [ ] **C04 视频信息**：已将适用纯视频内容中的文字、动作、顺序、变化和结果与替代内容比较。若仅检查了部分帧，已记录空白时间区间。
- [ ] **C05 允许的替代方案**：已在纯视频内容中确认充分的文本或音频替代内容之一。未仅因缺少文本就判定两条途径均失败。
- [ ] **C06 实际提供**：已实际检查替代内容的链接、正文、音频文件，并确认返回的不是错误页面、摘要或其他版本。
- [ ] **C07 例外依据**：若应用了“已有文本的替代形式”这一例外，已确认不存在文本中没有的额外信息，并明确标示了替代关系。
- [ ] **C08 独立观察**：未将替代文档复制为原始内容观察资料。若依赖派生转写或帧图像，已记录该路径及验证范围。
- [ ] **C09 执行记录**：已记录实际处理的资料、时间区间、工具，以及失败、受阻、未检查的范围。未将仅提供 URL 的资料标为已阅读。
- [ ] **C10 有依据的判定**：已区分满足、不满足、不适用、暂缓判断，并通过原始内容和替代内容的位置说明重要差异。未将未经确认的模型置信度数值标为准确率。
- [ ] **C11 修改与复查**：已记录计划，在修复遗漏、失真后，重新检查相同的原始区间、其余全部内容及实际提供页面。
- [ ] **C12 范围区分**：未将本条目的结果扩大为完整 WCAG 符合性。字幕、播放器键盘操作、文档自身的无障碍问题应依据相应标准单独管理。
