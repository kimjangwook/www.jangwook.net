## 同一张照片用在三个位置，替代文本也应该一样吗？

我们来想象一下网店中的一张夹克照片。在商品详情页中，它展示正面的样式和颜色。在商品列表中，点击照片会进入详情页。在说明页面中，正文已经用文字说明颜色和正面特征，随后附上同一张照片。

三个位置使用的文件相同，但用户要完成的任务不同。在详情页中，用户需要了解商品特征。在列表中，用户需要知道链接会跳转到哪里。在说明页面中，用户应当能够阅读正文说明，而不必重复听取相同信息。因此，仅为照片文件保存一份替代文本，并在所有位置重复使用，可能并不充分。

本文讨论 WCAG 2.2 的 **1.1.1 非文本内容（Non-text Content），级别 A**。商品说明、线框图和示例数值均为帮助理解而设置的虚构案例。后文还将介绍将提示词应用于已公开的概述页面后得到的实际运行结果。

## 1.1.1 要求提供能够实现同等目的的文本替代

该准则要求为呈现给用户的非文本内容提供能够实现同等目的的文本替代。除了照片和图标，图表、SVG、有意义的背景图像等也可能属于检查对象。如果将其理解为只要求存在某个 HTML 属性，就容易遗漏适用范围。

`alt` 是为 HTML 的 `img` 元素提供替代的一种典型方法。文本替代为难以看清屏幕的用户提供了阅读或听取信息的途径。如果是操作元素，用户还应能通过名称了解将执行什么操作。对于 SVG 或画布等不同的呈现技术，关联替代内容的实现方法也会有所不同。

在实践中，建议将以下两方面分开确认。一是图像传达的信息或功能是否已用文字表达，二是这些文字是否确实与相应元素关联并传递给用户。即使文字写得很好，如果关联断开，用户也无法使用替代内容。反过来，即使属性已关联，如果内容是文件名或错误的描述，也无法传达其目的。

W3C 的 Understanding 文档和图像教程提供了有关这类判断的说明。需要区分 WCAG 的要求与解读文档中的实现示例；下文按案例列出的流程，是将这些内容应用于团队工作的建议。

## 先确定图像承担的作用

暂时遮住图像，想一想剩下的界面，可以让判断更容易。记录用户获取信息或完成任务时会缺少什么。不要仅因为图像好看就将其归为装饰，也不要仅因为它包含信息就描述所有视觉细节。

| 使用情境 | 需要为用户保留的内容 | 替代方向 |
| --- | --- | --- |
| 展示商品特征的照片 | 区分当前所选商品所需的特征 | 符合上下文的简短描述 |
| 内容仅存在于图像中的通知横幅 | 活动条件、期限等实际文字 | 以可阅读的文本提供相同信息 |
| 仅以图像为内容的链接 | 跳转目标和目的 | 通过链接名称传达目的 |
| 只有图标的按钮 | 要执行的操作 | 提供按钮的可访问名称 |
| 图表、地图、流程图 | 数值、关系、方向、阅读顺序等关键信息 | 关联简短的识别性描述与详细替代内容 |
| 与周边文字完全重复的图片 | 保留已提供的信息，同时减少重复 | 如果没有其他功能，可考虑空 `alt` 等方式 |

表格中的最后一项是有条件的。照片旁边只有商品名称，并不代表已经提供了颜色或区分商品所需的特征。隐藏链接中的图片时，还要同时检查链接名称是否仍然存在。

### 信息性图像：需要识别或理解什么？

下面是一个用于查看颜色和正面样式的商品详情页示例。

```html
<h2>经典夹克</h2>
<img src="jacket-front.jpg"
     alt="深灰色夹克正面，两颗纽扣和两侧翻盖口袋">
```

这段描述传达了照片中实际可见的特征。不要添加仅凭照片无法确认的材质、防水性能或穿着感受。即使商品说明中写明了材质，也要区分哪些是图像所展示的，哪些是通过商品信息确认的事实。

替代内容可以随用途变化。在选择颜色的界面中，如果图像之外的文字已经充分提供颜色名称，就不必无条件重复相同措辞。如果是比较缝合位置的说明，相比颜色，描述缝线的差异更符合目的。把 `alt` 写得长与写得充分是两回事。

上下文变化时，也要重新检查替代内容。如果把同一张图像移到文章正文中，却原样使用商品页面的描述，可能无法传达读者在文章中需要了解的内容。

### 装饰与重复：空替代文本是有意省略信息后的结果

如果正文已包含所有活动条件，而背景照片只是烘托氛围，可以采用下面的处理方式。

```html
<img src="jacket-decoration.jpg" alt="">
<p>秋季夹克活动：截至10月15日，部分商品优惠10%</p>
```

空字符串 `alt=""` 与完全省略 `alt` 属性并不相同。空替代文本表达了无需朗读这张图像的意图。如果省略属性，某些屏幕阅读器可能会读出文件名等内容。

不过，如果上述示例的照片本身还写有其他折扣条件，就需要确认正文中是否包含这些条件。可以隐藏图片的判断，并不是基于图像好看或尺寸小。必须有依据表明它没有需要传达的信息，或相关信息已通过其他途径充分提供。

也不要因为有图注就自动选择空替代文本。需要确认图注只是注明照片来源，还是也提供了图像的关键信息，以及用户能否访问这些内容。减少重复与避免信息遗漏这两个目标需要一并考虑。

## 链接和按钮应传达操作目的，而不是外观

仅包含商品照片的链接，需要有一个能让用户了解跳转目的的名称。

```html
<a href="/products/classic-jacket">
  <img src="jacket-front.jpg" alt="查看经典夹克详情">
</a>
```

在这个链接中，用户首先需要知道的是会跳转到哪件商品，而不是夹克有几个口袋。如果照片本身的细节对购买判断必不可少，可以考虑通过周边商品说明等方式补充提供。

如果同一链接中已经以实际文本呈现了商品名称，结构就会有所不同。

```html
<a href="/products/classic-jacket">
  <img src="jacket-front.jpg" alt="">
  <span>查看经典夹克详情</span>
</a>
```

这个示例假定链接文字已经传达目的，图像不包含额外信息。如果图像用于区分同名商品的不同颜色，就需要另行提供这一差异。与其在两个分开的链接中重复相同目的，也值得考虑能否将图像和文字合并到一个链接中。

只有图标的按钮也可以按同样的思路处理。比起描述放大镜的形状，更需要一个能说明将执行何种搜索的名称。

```html
<!-- 修改前：假定这是一个没有其他名称提供方式的按钮。 -->
<button type="button">
  <img src="search.svg" alt="">
</button>

<!-- 修改后：为按钮提供目的，并隐藏重复的图标描述。 -->
<button type="button" aria-label="搜索商品">
  <img src="search.svg" alt="">
</button>
```

也可以采用将图像的 `alt` 用作按钮名称的其他实现方式。与其重复叠加多种方法，不如确认一种名称提供方式能否按预期传达。如果设置了 `aria-label` 等属性，计算结果可能与可见文本或图像描述不同，因此不要只罗列 DOM 中的字符串，而要确认最终的可访问名称。

按钮的角色、状态和键盘操作还会在 4.1.2、2.1.1 等准则中进一步讨论。不能因为在本项中修改了名称，就视为已评估按钮的整体无障碍情况。

## 复杂图表不能只用一句 alt 就结束

假设一张教学用图表显示咨询量：1月120次、2月80次、3月160次。`alt="每月咨询量图表"` 能说明画的是什么，但没有传达数值及其变化。需要比较这些数值的用户还需要详细信息。

简短替代文本可以识别图表，并指明详细说明的位置。在正文中提供主要变化和数据表。

```html
<img src="inquiries.png"
     alt="1~3月咨询量。每月数值和趋势见下方说明与表格。">
<p>咨询量从1月的120次减少到2月的80次，
   随后在3月增加到160次。</p>
<table>
  <caption>1~3月咨询量，单位：次</caption>
  <tr><th scope="col">月份</th><th scope="col">咨询量</th></tr>
  <tr><th scope="row">1月</th><td>120</td></tr>
  <tr><th scope="row">2月</th><td>80</td></tr>
  <tr><th scope="row">3月</th><td>160</td></tr>
</table>
```

<figure class="learning-figure"><img src="/images/accessibility/non-text-content/zh/03-chart-alternative-26d439f555d7.svg" alt="教学用咨询量图表及其替代内容。以图表和表格提供1月120次、2月80次、3月160次的数据，并用句子说明2月减少后3月增加的变化。"/><figcaption>示意图 03. 不只是转写图表标题，而是提供用户需要比较的数值和趋势。这些数值是用于说明的虚构数据。</figcaption></figure>

表格并不总是唯一的替代方式。流程图的重点可能是分支条件和下一步骤，地图的重点可能是位置和移动路线，组织结构图的重点可能是部门之间的关系。检查详细替代内容是否充分时，应考虑用户不看图也能否作出正文所要求的判断。

如果难以从画面中读出数值，就不能将 AI 推测的值当成确定值。应请求原始数据或清晰的资料。存在原始表格与用户能够访问该表格也是两回事，因此还要同时确认详细说明的链接和关联位置。

## 还要检查照片以外的呈现形式及准则的例外情况

如果有意义的信息只存在于 CSS 背景图像中，仅检查 `img[alt]` 列表就无法发现。需要将仅存在于图像中的提示文字与 DOM 文本进行比较。考虑能否将需要阅读的文字作为实际文本提供，并确认以图像形式提供的文字是否有替代内容。添加了 `alt`，并不意味着同时满足了 1.4.5 对文本图像的其他要求。

包含信息的 SVG 必须与这些信息的替代内容实际关联。如果将图标按钮内的 SVG 作为装饰隐藏，按钮本身的名称仍需保留。对于画布上绘制的图表，仅有清晰的截图并不充分，还需要确认是否提供了可用的文字说明、数据等替代内容。即使在这些情况下，也不能仅因添加了某个属性就判定通过。

1.1.1 对以下情境有相应要求。不能因为存在例外，就理解为可以省略所有替代内容。

| 情境 | 1.1.1 中需要确认的内容 |
| --- | --- |
| 基于时间的媒体 | 至少提供用于识别内容的描述。字幕、音频描述等详细要求还需在 1.2 中进一步检查 |
| 转换为文本后就无法成立的测试或练习 | 提供用于识别对象的描述。确认是否确实符合会损害测试目的的条件 |
| 主要提供特定感官体验的内容 | 至少提供识别性描述。不要以此条件隐藏普通信息性图像 |
| CAPTCHA | 提供说明验证真人目的的替代内容，以及采用其他感官方式的替代形式。这并不意味着公开答案就是替代内容 |
| 纯装饰、视觉格式设置、未呈现给用户的内容 | 以辅助技术可以忽略的方式实现 |

屏幕上不可见的内容，也可能通过其他方式呈现给用户，或在展开菜单等状态中出现。不要仅凭一张关闭状态的界面截图就套用不可见内容的例外，而要记录评估的状态和使用路径。

## 为多模态 AI 将图像、代码和上下文关联到同一对象

检查是否存在替代文本，与评估替代内容的含义，是不同的任务。图像中的折扣文字是否遗漏于替代内容、照片描述是否符合链接目的、详细表格是否传达了与图表相同的内容，都需要比较图像与上下文。可以设计利用多模态模型进行这类比较的评估。

在这一设计中，先评估现有替代内容是否足以满足用户目的，而不是先让模型仅凭图像生成描述。检查自动规则工具无法确认的语义，同时将模型回答与实际观察、操作记录关联起来。在后面的应用案例中，将通过实际页面资料和对照条件核对判定与依据。

<figure class="learning-figure"><img src="/images/accessibility/non-text-content/zh/04-evidence-flow-3dcb26b61e0f.svg" alt="通过元素 ID 关联图像、DOM、无障碍树和页面上下文，再依次进行语义比较、有依据的判定、改进及同一状态下的复查的评估流程。"/><figcaption>示意图 04. 必须将输入资料关联到同一元素和状态，才能验证比较结果。这是建议的评估设计，并非已经实现这一完整流程的服务或实验结果。</figcaption></figure>

评估资料可按以下方式准备。

1. **页面与任务**：记录 URL、语言、使用目标和需要确认的状态。将商品列表与详情页区分为不同状态。
2. **视觉资料**：提供页面全屏截图、目标图像的放大资料、原始图像或图表数据。确保能够同时查看整体上下文和细节。
3. **DOM**：不仅包含目标元素，还要包含父级链接或按钮、周边文本，以及名称和描述所引用的元素。范围应足以确认图像缺失或 `aria-label` 等情况。
4. **无障碍资料**：收集角色、最终计算得到的名称和描述，以及隐藏状态。区分根据 DOM 预期的名称与浏览器实际暴露的结果。
5. **状态关联**：附上元素 ID、采集时间、视口和登录条件等信息。如果混用不同状态的截图和 DOM，判定依据就会错位。

例如，将商品搜索按钮的 ID 定为 `E03` 后，可以将 `E03-screen` 对应到界面，`E03-dom` 对应到代码，`E03-ax` 对应到无障碍树，`E03-action` 对应到实际操作记录。不能仅因写了文件路径就认为模型已读取文件，而应实际附加文件，或提供读取工具的结果。

输入不同，可作出的判断也不同。只有界面截图时，可以识别视觉信息和潜在问题，但难以确认实际名称或隐藏处理。只有 DOM 时，虽然能检查属性，却难以确认照片中有哪些信息被遗漏。如果具备工具的智能体能够补充采集资料，就可以在附上观察依据的同时扩大评估范围。不必将输入不足认定为 AI 能力的永久局限。

### 让 AI 结果成为可用于修改的记录

如果模型只回答“合适”，负责修改的人就很难核对判断依据。应同时要求提供当前替代内容、角色分类的理由、缺失信息、实际证据 ID、用户影响、修改方案和复查方法。

还要将判定与执行状态分开。尚未收到资料的状态是**未执行**，图像下载或浏览器工具失败的状态是**执行失败**。即使读取了资料，如果缺少足以确定意图或上下文的依据，也应保留为**暂无法判定**。对于完整观察过的对象，将结果区分为**满足、不满足**；如果对象不在范围内，则写明原因并记录为**不适用**。

正确隐藏装饰图像的结果，意味着已确认相关实现。如果一律略过并记为不适用，就无法知道是否检查了必要的隐藏处理。要同时避免两种错误：仅凭空 `alt` 就判定通过，以及仅因存在空 `alt` 就判定违规。

对于分类模糊的图像，可以请求作者补充说明使用目的。不过，也不必将流程固定为每次都把结论交给人来决定。对于凭充分的上下文和观察资料即可判断的项目，应附上依据进行评估，只明确留下资料不足的部分。

## 已在概述页面上应用两份提示词进行验证

使用 **GPT-6.1 Sol**，对已公开的[网页无障碍概述](https://jangwook.net/series/accessibility/overview)中的示意图及查看原图链接进行了评估。先用第1轮的评估计划提示词整理范围和所需证据，再用本文的 1.1.1 提示词比较图像含义与当前替代内容。提示词中的指令保持原样，输入栏则填入实际页面资料。

提供的资料包括各示意图的截图、渲染原图后得到的图像、相应元素及父级链接的 DOM、浏览器无障碍树、正文和图注。首先检查的是正文中4张示意图传达的关系、顺序、比较，以及查看原图链接的名称。为避免被误判为实际操作了图中绘制的虚构注册、物流查询界面，将这些内容与实际 DOM 的功能加以区分。

| 阶段 | 确认的结果 |
| --- | --- |
| 第1轮提示词——评估计划 | 建立了阅读过程的开始与完成条件、包含和排除的范围、现有资料和额外所需证据，以及检查、修改、重新评估的顺序。 |
| 第2轮提示词——准则判定 | 比较实际图像与替代内容的含义，并分别记录图像本身的名称和父级链接的名称。为每项判定保留证据 ID 和相同条件下的复查方法。 |

使用相同输入重复运行，确认了最终提示词的判定、角色分类和计算得到的名称。

| 示意图 | 与替代内容比较的关键信息 | 重复3次的结果 |
| --- | --- | --- |
| WCAG 结构 | 原则→指南→成功准则之间的关系，以及 A、AA、AAA 的累积关系 | 均满足 |
| 注册状态 | 输入→条款→错误→修改→完成的顺序，以及对各状态的观察 | 均满足 |
| 图像上下文 | 装饰 A 与功能 B 的差异，以及实际查看原图链接的目的 | 均满足 |
| 证据流程 | 采集、检查、判定、复查，以及证据不足与执行失败的区分 | 均满足 |

除正常输入外，还使用基于原始页面制作的本地对照资料进行了评估。一组排除最后一张示意图的资料，另一组将比较示意图的替代文本改为“图像”，并移除详细说明。并未修改公开页面本身。

| 对照条件 | 预期判断 | 执行结果 |
| --- | --- | --- |
| 示意图在列表中，但缺少必要证据 | 不将尚未确认的对象判为满足 | 记录了暂无法判定和部分执行，并请求补充缺失资料。 |
| 缺少能够传达比较示意图含义的替代内容 | 区分链接名称与图像替代内容不足的问题 | 将图像和范围结果记录为不满足。父级链接的“查看原图”名称则单独判为满足。 |

在这些条件下，确认了**必需的输出结构、各元素的依据关联、判定、图像及父级链接计算得到的名称，以及重复运行的一致性**。判定仅限于正文示意图和图像链接的 1.1.1。评估额外操作或其他准则时，需要重新准备对应问题所需的状态与证据。

## 扩展案例时，应关注判断的一致性，而不是唯一的标准句子

应用于自己的网站时，应准备符合相应上下文的案例。下表是选择补充验证案例的依据。

| 案例 | 需要确认的结果 |
| --- | --- |
| 实际替代内容已包含必要商品特征的信息性图像 | 是否会凭空认定存在遗漏 |
| 替代内容只有文件名的信息性图像 | 能否发现关键信息不足 |
| 在上下文中属于纯装饰且已正确隐藏的图像 | 是否会将空替代文本误报为错误 |
| 除空替代文本外没有名称的图标按钮 | 能否发现操作目的缺失 |
| 图标相同，但按钮具有正确名称的情况 | 是否会仅凭图像属性就判定失败 |
| 图表数值与详细表格不一致的情况 | 能否发现不一致并列出作为依据的数值 |
| 同一张照片重复用于信息、链接和装饰的情况 | 判断能否随上下文变化 |
| 模糊图表、缺失 DOM、错误关联的状态资料 | 是否会请求必要资料，而不是以推测值判定通过 |

由理解准则的评估者准备附有依据的参考答案，并比较模型结果中的误报、遗漏和暂无法判定。一次生成了写得不错的 `alt`，并不代表整个评估已经得到验证。还要记录相同输入重复运行时，角色分类或判断是否发生波动。

分别测试只提供界面、提供界面与 DOM、同时提供界面、DOM 和无障碍资料的情况，可以了解额外输入如何帮助判断。记录模型版本、工具、提示词版本、输入资料包、执行时间和成本。不要将输入条件不同的运行结果合并成同一个准确率数值。

## 团队管理应以使用位置为依据，而不是以图像文件为依据

CMS 图像库中保存的默认描述可以作为起点。但仍应能够根据实际使用位置是信息性图像、链接还是重复说明来进行检查。系统应支持编辑人员选择装饰处理或符合上下文的替代内容，并支持开发人员以正确的代码输出这些意图。

可以这样划分责任：商品编辑确认必要的商品特征和文字，设计人员确认图片的传达目的，开发人员确认名称、描述和隐藏处理。复杂图表的说明和数据由原始作者一并更新。这是一项需要根据各组织角色调整的建议，并非要求所有团队采用相同的岗位配置。

同一个组件用于多个界面时，不仅要修改一处属性，还要抽样确认它在其他上下文中能否正确传达名称。也要检查图像或图表已经变化、旧替代内容却仍然保留的情况。运营标准应是当前界面与替代内容是否持续一致，而不是最初是否填写过。

## 实务检查清单

下面的勾选项表示**已完成该项目的检查记录**。勾选不代表满足条件。请在每项旁边另行记录判定和依据。

- [ ] **C01 范围**：已记录页面、语言、状态、使用目标，并建立实际确认过的元素列表。没有将一个状态的结果扩大到整个网站。
- [ ] **C02 对象采集**：除 `img` 外，已确认是否存在有意义的 SVG、画布、背景图像和图像内文字。
- [ ] **C03 角色**：已依据上下文区分信息、操作、复杂信息、装饰和重复内容，并将不明确的目的保留为待补充确认。
- [ ] **C04 信息替代**：已对照当前照片或图片中的必要信息是否通过替代内容传达。没有凭空添加不可见的性能或材质。
- [ ] **C05 操作目的**：已确认图像链接和图标按钮最终的可访问名称。没有仅用外观描述代替操作目的。
- [ ] **C06 空替代文本**：已确认装饰、重复图像的省略依据与隐藏处理。没有连同唯一的操作名称一起移除。
- [ ] **C07 复杂信息**：已确认简短描述与详细替代内容的关联，以及数值、单位、关系和顺序。没有推测模糊数值。
- [ ] **C08 特殊条件**：已确认媒体、测试、感官体验和 CAPTCHA 的情境要求。对未应用的条件保留了理由。
- [ ] **C09 关联一致性**：已比较同一元素、同一时间、同一状态下的界面、DOM 和无障碍资料。已区分资料缺失与执行错误。
- [ ] **C10 判定依据**：已将满足、不满足、不适用、暂无法判定与执行状态分别记录。没有将模型推测写成直接观察。
- [ ] **C11 复查**：修改后，已在相同使用目标和状态下重新确认。也已确认共享组件的其他使用位置。
- [ ] **C12 运营**：已确定图像或语言变化时更新替代内容的负责人和触发检查的时机。没有将缺少实际资料的状态勾选为检查完成。

记录格式可以从 `元素 ID / 页面·状态 / 角色 / 当前替代内容 / 判定 / 证据 ID / 用户影响 / 修改负责人 / 修改方案 / 复查结果` 开始。这份表单和提示词是帮助记录与评估的资料，并不是能够自行执行检查的程序。
