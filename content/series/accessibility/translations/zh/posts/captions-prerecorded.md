## 即使有字幕，指示的意思变了也不够

在账户恢复说明视频中，用户问：“现在可以丢弃旧代码吗？”引导员回答：“不可以。在保存新的恢复码之前，请不要丢弃。”然而，字幕显示的是“请在保存新的恢复码之前丢弃”。句子的大部分与原文相同，但如果相信这条字幕并照做，用户可能会失去所需的代码。

这类视频有字幕文件，播放画面上也能看到文字。自动检查或许能够确认字幕轨道的存在，但用户能否获得相同的信息，是另一个问题。一个否定表达、一声警告音、一次台词的显示时机，都可能改变说明的含义。

上一篇[预录音频与无声视频文章](/zh/series/accessibility/audio-only-and-video-only-prerecorded)区分了纯音频和纯视频内容的替代形式。本篇讨论 **WCAG 2.2 的 1.2.2 Captions (Prerecorded)，A 级**。这一准则要求通过可在观看画面时阅读的字幕，传达预先制作的同步媒体中的声音。恢复码说明是为本文的讲解与验证制作的虚构案例，不涉及真实账户或代码。

## 先明确字幕服务于什么内容

1.2.2 要求为预先制作的同步媒体中的音频提供字幕。常见示例包括有讲解者说明的产品介绍视频、包含对话和音效的教学视频，以及录制的访谈。讲解者的形象与说明一起播放的简单视频也在范围内。并不是只有画面与声音关系复杂时才适用这一准则。

仅凭文件名或 HTML 标签分类可能会出错。`video` 元素中实际上可能只有音频，视频文件也可能只包含装饰性音乐。播放器被静音，也不意味着原始媒体没有声音。需要确认实际的音频与视觉信息、是否为预录内容，以及用户应从声音中获得什么内容。

| 实际内容 | 优先审查的准则 | 检查要点 |
| --- | --- | --- |
| 包含台词或重要声音的预录同步媒体 | 1.2.2 预录字幕 | 是否与画面一起提供能够理解声音内容的字幕 |
| 预录纯音频内容 | 1.2.1 | 是否有传达相同信息的转写文本等替代形式 |
| 实际没有声音的预先制作视频 | 1.2.1 | 是否有充分的视觉信息替代形式或音轨 |
| 实时同步媒体 | 1.2.4 实时字幕，AA 级 | 是否为当前播出的声音提供字幕 |
| 录制实时活动后再次提供的媒体 | 所提供录制版本的 1.2.2 | 是否独立于直播时的处理，审查了录制版本 |

没有必要仅因为存在背景音乐，就机械地对所有文件要求相同的字幕。应判断音乐只是装饰，还是传达了理解所需的信息，例如氛围或事件的变化。反过来，也不能因为没有台词，就把含有重要警告音的视频当作无声视频处理。

## 字幕不仅传达台词，还传达重要声音和说话者

如果把字幕看作只是给语音识别结果加上时间的文件，就会遗漏内容。应检查：用户如果能够听到，原本会知道的信息中，哪些是理解场景和行为所必需的。

首先，要保留台词的含义。否定、条件、数值、顺序和警告尤其需要注意。把“生成后，旧代码将无法使用”改成“生成后，旧代码可以使用”，就颠倒了核心含义。即使只从“保存后丢弃”中漏掉“后”，也会改变操作顺序。

这并不意味着必须逐字复制每一个音节。减少重复或赘述的句子仍然可以传达相同含义。本文中的“将新代码保存在安全的地方。生成新代码后，旧代码将无法再使用”，如果缩写为“请安全保存新代码。生成新代码后，旧代码无法使用”，仍然保留了保存和旧代码失效这两项信息。应审查的是信息与含义，而不是文字匹配率。

说话者也是内容的一部分。如果画面外的用户和引导员进行问答，就应让听不到声音的用户知道是谁在说话。这是为了避免将问题读成引导员的指示，或混淆回答者。不过，如果画面和上下文已经清楚表明说话者，就没有必要把每行都重复姓名定为普遍义务。

声音还存在于台词之外。如果提示错误的警告音、敲门声、笑声或音乐变化会影响场景的含义，就应纳入字幕。仅标注“[警告音]”这样的声音类型是否足够，也应根据上下文判断。如果说明中两次警告音代表安全验证失败，用户就需要知道这一含义，才能决定下一步操作。

## 有完整转写文本，就可以省略字幕吗？

一般预录视频不会因为附有完整转写文本，就免除字幕要求。因为用户在阅读转写文本时，还需要自行关联画面正在进行哪个步骤、当前是谁在回答，以及警告发生在什么时候。转写文本是有用的附加途径，但与同步字幕的作用不同。

1.2.2 对作为正文媒体替代形式的情况设有例外：**媒体没有增加已提供正文中不存在的信息，并且明确标明该媒体是正文的替代形式**。必须同时确认这两个条件。

例如，假设页面已经完整说明了步骤、问答和警告的含义，并且实际标明“此视频是下方说明的媒体替代形式”。如果整个视频只传达与该说明相同的信息，就可以审查是否适用这一例外。相反，如果只有视频提到“旧代码将无法再使用”这一注意事项，即使有上述提示文字，也增加了正文中没有的信息。

不能仅凭相同标题、转写文本链接，或制作者“内容相同”的说法，就认可例外。必须比较完整媒体、与之关联的完整正文，以及用户实际看到的标示文字。如果确认两个条件中的一个不成立，就评估一般字幕要求。如果连用于比较这些条件的资料都没有，就既无法判断例外，也无法判断充分性，应记录为暂无法判定，并请求所需资料。

## 字幕出现的时间和位置也是信息的一部分

如果正确的句子在视频结束后才出现，用户就无法在需要的时刻阅读。在引导员回答“请不要丢弃”时没有字幕，而在下一画面才显示该回答，用户可能会误以为它是对当前步骤的指示。还需要检查是否与其他台词顺序混乱，或多个句子的显示时间过短。

评估时间时，应同时记录原始声音区间和字幕显示区间。要把相差几秒与当时用户需要从画面理解或决定什么联系起来，才能据此修改。相比一句“字幕不同步”，“回答的设计区间为 7.6–11.6 秒，但字幕在 12.6–16.6 秒显示，导致用户在安全验证结果画面中阅读上一段回答”更有用。

不应把本案例的 5 秒延迟推广为所有视频的合格线。不要给 WCAG 1.2.2 附加任意的延迟秒数或字符数，并将其当作固定标准。为阅读时间另设数值合格线，也不是这一准则的要求。显示时间对使用的影响，应作为说明原始内容与画面关系的实务审查记录。

图 03 中的 7.60–11.60 秒是安排回答的设计区间。通过对原始媒体的独立转写检测到的实际发话为 7.71–11.18 秒，下方输入示例使用这一观察值。不能把字幕显示区间和观察到的发话区间改成相同数值后记录。

字幕的布局也要审查。如果字幕遮住视频中的错误消息或需要选择的按钮，就可能在传达声音内容的同时丢失重要视觉信息。需要在长台词、小屏幕以及播放器控件显示的状态下检查。对字幕传达准则的审查，与播放器键盘操作等其他成功准则的审查，应分别记录。

## 区分 HTML 字幕轨道与视频内嵌字幕

用户可以开关的字幕称为封闭式字幕，始终存在于视频画面本身的字幕称为开放式字幕。1.2.2 允许这两种方式。如果开放式字幕已经充分提供，仅因为没有 `<track>` 就判为不满足，是错误的评估。

下面是为 HTML 视频关联封闭式字幕的示例。下方代码是与本文虚构说明视频相同形式的实现示例，仅有文件关联，并不能确认实际字幕质量。

```html
<video controls preload="metadata" playsinline
       aria-label="복구 코드 발급 안내"
       src="recovery-guide.mp4">
  <track kind="captions" src="recovery-guide.ko.vtt"
         srclang="ko" label="한국어 자막" default>
</video>
```

`kind="captions"` 表明这是传达台词和必要声音的轨道。`srclang` 和 `label` 用于帮助用户识别语言与轨道。`default` 用于指定默认显示的轨道，但最终显示状态也可能受浏览器和用户设置影响。需要在实际播放器中确认是否能够选择和阅读。

WebVTT 的提示（cue）是一段将开始时间、结束时间和句子组合起来的字幕。本例中的 B1、A2、SFX 是用于再次定位提示的 ID，与图 03 中区分两种显示条件的字幕 A/B 不同。这里分别记录问答的说话者，以及有意义的警告音。

```text
WEBVTT

B1
00:00:04.000 --> 00:00:07.000
用户：现在可以丢弃旧代码吗？

A2
00:00:07.600 --> 00:00:11.600
引导员：不可以。在保存新的恢复码之前，请不要丢弃。

SFX
00:00:12.200 --> 00:00:15.820
[两次表示安全验证失败的警告音]
```

原始警告音在 12.20–12.82 秒响起两次，但为了留出阅读其含义的时间，字幕持续到 15.82 秒。之后，引导员的下一条台词提示 A3 从 16.42 秒开始，独立转写中观察到的实际发话开始时间为 16.47 秒。这是一个在保持与声音关系的同时确保阅读时间的示例。仅机械地让所有字幕贴合声音的起止时间，并不足够。

即使网络请求成功、文件语法正确，也可能无法选择字幕，或字幕不显示在画面上。应同时检查轨道加载和显示状态、当前时间激活的提示，以及实际画面。反过来，如果因文件处理失败而无法读取原始媒体，不要把该错误转化为内容不足的无障碍判定。

### 不只记录字幕是否存在，还要记录哪些信息发生了变化

在完整字幕条件下，台词、画面外说话者、警告音及其含义都与原始内容对应。在遗漏警告音的条件下，留下了**没有字幕与 12.20–12.82 秒的原始声音对应的依据**。页面上的声音说明可用于解释警告音的含义，但它不是在播放过程中同步传达警告发生时刻的字幕。

在否定表达被改变的条件下，记录了 **A2 提示中的指示被颠倒这一事实**。结果不是简单地说“准确度低”，而是将原始内容的“在保存之前，请不要丢弃”与字幕的“请在保存之前丢弃”对应起来，说明用户可能错误操作的风险。修改具体落实为纠正该提示的含义，并重新检查同一区间。

在时间错位的条件下，确认同一句 A2 **没有在设计区间 7.60–11.60 秒，而是在 12.60–16.60 秒显示**。即使保留原句，用户仍会在安全验证结果与重新验证画面中阅读上一段回答，因此时间对应不足。

| 确认的条件 | 判定 | 支持结果的依据 |
| --- | --- | --- |
| 包含完整台词、说话者和警告音的封闭式字幕 | 满足 | 原始信息、字幕提示及实际显示相互对应 |
| 否定表达被颠倒的字幕 | 不满足 | A2 中不能丢弃的条件被改成了相反指示 |
| 遗漏警告音的字幕 | 不满足 | 没有与表示安全验证失败的声音对应的提示 |
| 未能识别必要的画面外说话者的字幕 | 不满足 | 没有让用户在无声情况下识别问答发话者的标示 |
| 晚 5 秒显示的字幕 | 不满足 | 原始回答与阅读字幕时的画面、时刻不同 |

| 有完整正文，但未标明是替代形式 | 不满足 | 例外的标示条件不成立，且没有字幕 |
| 标明是替代形式，但只有原始媒体传达警告 | 不满足 | 存在附加信息，例外不成立，且没有字幕 |
| 仅提供前 8 秒的原始资料 | 暂无法判定 | 无法证明后续原始内容与字幕的对应关系 |
| 无法读取或处理原始文件 | 暂无法判定 | 保留实际错误，不用字幕元数据推测原始内容 |
| 公开概述文章正文中没有目标媒体 | 不适用 | 在已核查完整正文媒体列表的范围内，没有目标媒体 |

在开放式字幕条件下，模型返回了满足，但所审查的显示资料是 9 个时刻的 PNG，输入中没有各字幕准确的显示起止时间。这个结果不能证明视频内嵌字幕在整个时段的时间对应。没有测试延迟的开放式字幕。实际应用时，还需要检查每条字幕出现和消失的帧，以及该区间的画面。查看样本的模型还记录了长字幕中类似“없습니/다.”的词内换行，以及字幕条遮住视频内进度条的现象。基于含义与警告仍然保留，并且仍有其他进度标示的依据，模型没有将这些观察判为不满足。换行的阅读便利性和进度信息的保留，需要在实际显示状态下另行复查。

两种资料不足条件并不意味着画面本身始终不完整。第一种限制了传给评估模型的原始资料，第二种则是无法加载原始文件。应区分实际练习画面与模型输入条件，避免把结果解读为对其他资料的性能。

这些结果在 Claude Opus 5.5 High 上得到确认。固定原始资料和两个提示词后，在三个新会话中分别按顺序审查了 14 个条件。总计 42 个模型范围判定与预先确定的基准答案一致。这个数字是返回判定的一致次数，并不意味着开放式字幕显示时间等尚未确认的依据也已满足。它们不是为每个条件分别开启会话的 42 次独立运行，同一会话中的条件可能共享前面已处理条件的上下文。概述提示词也分别在练习页面和没有目标媒体的公开概述文章上各应用三次，以确认它是否规划评估范围和附加证据。

基准答案在运行前固定，未提供给评估模型。这些答案是在同一资料制作与验证过程中，依据标准与原始内容的对应关系确定的，未经过独立无障碍专家审查。因此，这种一致性是针对该资料的重复一致性结果，不是外部专家确认的准确率，也不是对一般视频的性能。

判定一致与输出记录完整也不同。42 个输出中有 6 个存在记录警告：一方面将文件末尾约 0.019 秒的区间记为未审查，另一方面又标记了表示完整审查的字段。这 6 个输出全部判为满足。原始资料采集方另行测量确认了该尾段没有声音信息，但这不意味着评估模型直接确认过该区间。提示词没有明确规定如何统计容器时长与实际解码时长的细微差异，因此记录可能含糊。这正是除了返回判定，还必须将未审查区间和处理记录与原始证据对照的原因。

部分输出还在应记录原始发话时间的字段中填入了字幕提示时间。例如，独立转写中与 A2 对应的回答从 7.71 秒开始，与 A3 对应的说明从 16.47 秒开始，而部分记录使用了提示开始时间 7.60 秒和 16.42 秒。即使最终判定相同，也不意味着这些值准确转录了原始观察。传达修改位置时，应分别把原始发话时间和字幕显示时间与原始资料对照。

这不是评估模型直接听原始媒体或处理连续视频的测试。采用的是比较独立转写、声音处理记录、字幕提示和 PNG 的路径，在约 31 秒合成语音、画面外两个固定说话者角色及一种警告音组成的受控资料中确认对应关系。说话者角色关联到单独录制的区间、与原始媒体的相关性记录及角色说明。没有测量高噪声对话、任意音乐与音效的识别、快速运动画面、一般说话者分离，或所有移动播放器的显示状态。对此类内容，应补充实际音视频处理记录，并由人将重要否定、说话者和声音含义与原始媒体对照，保留未确认部分。

## 团队应同时管理字幕文件与原始媒体的关系

语音识别有助于制作初稿，但自动转写可能误识别否定表达，或遗漏说话者和声音的含义。因此，应把字幕制作过程与需要校验的原始媒体关联起来。视频修改后，不仅要重新检查字幕句子，也要检查时间和是否遗漏。

修改请求最好指定原始区间和提示，而不是笼统地说“改进全部字幕”。例如，可以记录为“将 A2 的否定表达改为符合原始含义，并重新确认：在未听到独立转写所确认的 7.71–11.18 秒回答的情况下阅读字幕，是否仍能理解不能丢弃代码”。如果遗漏了警告音，应同时指定声音发生时刻及其含义、要增加的字幕和显示时间。

保存模型结果时，应将执行状态与无障碍判定分开。即使读取资料的执行成功，如果没有确认原始媒体后半部分，也无法判断充分性。反过来，即使有些区间未查看，只要在已确认区间证明了指示被颠倒，就可以记录该违规。关键是不把未审查区间填成合格。

## 实务审查清单

- [ ] 已记录待评估的页面状态、媒体列表及排除范围。
- [ ] 已查看实际内容，区分预录同步媒体、纯音频、无声视频和实时媒体。
- [ ] 对正文替代形式例外，同时确认了没有附加信息和明确标示。
- [ ] 不仅检查台词，还检查了理解所需的说话者变化和重要声音。
- [ ] 字幕保留了否定、条件、数值、顺序和警告的含义。
- [ ] 没有仅因文字不同就将含义相同的精简字幕判为不满足。
- [ ] 已实际选择并显示封闭式字幕，或在实际画面中确认开放式字幕。
- [ ] 已关联字幕对应的原始区间、显示区间及对使用的影响。
- [ ] 在长字幕、小屏幕及控件显示状态下，能够阅读必要内容。
- [ ] 字幕没有遮挡重要画面信息。
- [ ] 已保留转写、工具、样本画面的局限、未审查区间及资料冲突。
- [ ] 已将修改与复查方法关联到媒体 ID、时间、提示和证据。

## 使用评估提示词之前

在下方综合提示词的输入栏中填入评估范围和实际资料。先确认模型能直接处理音频、视频和图像中的哪些类型，以及是否有读取浏览器或文件的工具。如果没有工具，就提供已采集的转写、画面和处理记录，同时说明这些资料的局限。

下方提示词是**用于 1.2.2 评估的完整版本**。请用实际资料填写输入栏，并将返回的时间、提示和依据与原始媒体对照。与其只重复一个正常字幕条件，不如同时检查内容遗漏、时间差、例外和资料不足，以审查判定边界。提示词完成，并不意味着保证能自动判定所有媒体的符合性。即使在已验证的输入中，开放式字幕的完整显示时间仍需要进一步确认，输出中的处理区间记录也仍有含糊之处。将相同条件应用到新资料时，应先复查这些局限。

### 输入栏填写示例

以下是练习完整字幕条件中，用于重新定位 A2 的输入格式示例。资料 ID 是文件名或审查记录中指定的标识符，应关联到同一原始媒体。仅凭下方摘录，不能给整个视频判定为满足。

```text
范围：完整字幕练习页面的恢复码说明 M1。
目的：理解说明内容。不执行真实账户代码生成。
原始媒体：M1，预先制作的音视频，容器时长 31.208333 秒。
  解码音频时长 31.189 秒。时长差异对应的尾段另行记录。
资料 SOURCE-ASR：从 M1 中独立于候选字幕提取的按时间转写。
  7.71–11.18 秒 / 引导员：不可以。在保存新的恢复码之前，请不要丢弃。
资料 DELIVERY-C01：从浏览器实际读取的字幕提示及显示记录。
  A2 / 7.60–11.60 秒 / 相同回答，字幕轨道 showing。
资料 DISPLAY-C01-1：另行附上 9.4 秒时的实际画面 PNG。
  只输入这一行的 ID，并不等于附加了图片。
局限：此处仅摘录 A2。其余原始媒体、提示和画面需另行提供。
```

原始文件的哈希应从最终文件计算后附上，提取的转写中也应保留相同的原始文件哈希、所用工具和处理区间。转写文本不要从候选字幕复制，而应单独处理原始音频，或直接听取后编写，再对照否定表达和条件。字幕提示可通过检查实际播放器中加载的 `video.textTracks` 的 `cues`，记录 ID、开始时间、结束时间和句子。跳转到相同时刻，截取画面 PNG，并一并记录轨道显示状态。不要仅凭几张画面就声称确认了整个显示状态。

如果要让模型负责完整范围，应同时提供所有台词和重要声音、完整提示列表、必要的显示观察及未审查区间。如果主张例外，还需要提供关联的完整正文和实际提示文字。`direct_audio_review` 等输出字段是模型的自我报告，必须用实际工具执行记录确认；仅凭 `true` 值不能证明直接听取过音频。如果转写、提示、PNG 与原始媒体的关联不明确，应先补充资料。
