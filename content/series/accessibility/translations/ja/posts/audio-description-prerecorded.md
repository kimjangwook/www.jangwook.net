動画の中で警告音が2回鳴りました。画面にはセキュリティ確認に失敗し、再認証が必要であるという文言とボタンが表示されます。音だけを聴く利用者はエラー信号には気づけても、何が失敗してどう進めばよいのかを見落とすおそれがあります。音声解説は、こうした画面の意味を原音とともに伝える方法です。

## 音だけでは見落とす情報を判断する基準

WCAG 2.2の<strong>達成基準 1.2.5（音声解説（収録済み）、Audio Description (Prerecorded)、レベルAA）</strong>は、収録済みの同期したメディアのすべての映像コンテンツに対して音声解説を提供することを求めます。この項目の判定は、達成基準の要件と関連する用語定義を根拠とします。W3Cが併せて提供する解説（Understanding）、十分な達成方法（Sufficient Techniques）、失敗例（Failures）はいずれも非規範（non-normative）の参考資料です。実務で達成方法を1つ満たせなかったからといって直ちに基準違反と断定したり、逆に特定の達成方法だけを唯一の正解と誤解したりしないよう、まずこの境界を切り分ける必要があります。

レベルAの<strong>SC 1.2.3（音声解説、又はメディアに対する代替）</strong>とレベルAAの<strong>SC 1.2.5</strong>の違いは明確です。SC 1.2.3では、画面・セリフ・重要な音と必要なインタラクションを漏れなく収めた時間依存メディアのテキスト代替、または音声解説のどちらかを選べます。しかし、レベルAAのSC 1.2.5では一般的なテキスト代替だけでは不十分です。視覚情報を音声で伝える音声解説が基本要件になります。

とはいえ、すべての動画に独立した音声解説トラックを義務的に付けなければならないわけではありません。重要な画面情報が基本の音声トラック（セリフ、ナレーション、効果音）にすでにすべて含まれている場合、追加の音声解説トラックは不要です。また、同期したメディア（synchronized media）の定義に基づく適用除外条件も区別する必要があります。動画が本文やそのテキスト代替より追加の情報を提供せず、テキストの代替であることが明確に示されている場合、SC 1.2.5の適用対象外となり、判定は`not_applicable`になります。

## 実装経路の選択：G78、G173、G226、そしてG203の限界

音声解説を提供する方法は単一の技術に固定されていません。制作環境やプレーヤーの対応範囲に応じて、次の十分な達成方法を検討できます。

* <strong>G78（利用者が選択可能な第2音声トラック）</strong>：基本音声とは別に音声解説を含む補助トラックを提供し、利用者がコンテンツ自体のコントロール、メディアプレーヤー、またはOS設定から有効にできるようにします。
* <strong>G173（音声解説を含む別バージョンの提供）</strong>：音声解説をミックスした別バージョンの動画を提供します。このバージョン自体もアクセシブルである必要があり、別ページに配置した場合は利用者がそのバージョンを容易に見つけて移動できるリンクがあるかを確認します。
* <strong>G226（解説を統合したナレーション）</strong>：台本作成の段階から画面の重要な視覚情報を基本ナレーションに自然に組み込む方法です。G173との組み合わせで十分な達成方法として認められており、特定の技術方式だけが義務づけられているわけではありません。

注意が必要な達成方法は<strong>G203（固定背景の単一話者動画に対する静的テキスト代替）</strong>です。G203は、通常の動画にテキスト代替だけを付けてレベルAAを通過させる方法ではありません。話者が1人で背景が固定されており、時間経過に伴って変化する重要な視覚情報が一切なく、原音にない文脈・話者名・クレジットなどの静的情報だけをプログラムで関連づけたテキストとして提供する、極めて限定的な通過経路です。UI操作画面やエラー案内が切り替わるチュートリアル動画にはG203を適用できません。

## セリフの空白、警告音の保持、そしてF113の失敗条件

失敗例<strong>F113</strong>は、画面に重要な視覚情報があり、セリフの間に適切に使える未使用の空白があるにもかかわらず音声解説を入れていないケースを扱います。ここで空白を判断する際、固定の時間しきい値（例：一律2秒以上）は適用しません。次の3つの要素を併せて検討します。

1. <strong>空白の長さと場面との近接性</strong>：解説を入れる区間が対象の視覚イベントから離れすぎず、理解可能な速度で伝えられるかを確認します。
2. <strong>重要な音響の保持</strong>：BGMは音量を下げる方法（ダッキング）で調整できますが、エラーを知らせる警告音や操作結果を示す重要な効果音を音声解説で覆い隠してはなりません。
3. <strong>空白不足時の判断</strong>：セリフの空白が足りないという事実だけでは、レベルAAの合格や不合格は自動的に決まりません。動画を一時停止して解説を挿入する<strong>拡張音声解説（Extended Audio Description）</strong>はレベルAAを満たす方法としても活用でき、空白が不足する場合に拡張音声解説を義務づけるのはレベルAAAの<strong>SC 1.2.7</strong>の追加要件です。

### 警告音だけでは分からない情報：12〜15秒のセキュリティ確認失敗区間

この動画で音声解説の必要性が最もはっきり表れるのは<strong>12〜15秒</strong>です。画面にはセキュリティ確認失敗の見出しとともに、再認証を求める案内文言と「セキュリティ確認をやり直す」ボタンが表示されます。一方、基本音声では警告音が2回鳴るだけで、16秒になるまでセリフが空いています。

警告音は何らかのエラーが起きたという合図にはなりますが、聴取者の立場では何が失敗したのか、動画が案内する手順の中でどのボタンで再認証するのかが分かりません。続く16秒で突然「セキュリティ確認をもう一度終えた後」というセリフが出てくると、視覚情報を見ていない利用者は失敗と再試行の間の文脈を見失います。

### 20〜26秒区間：文字列の読み上げと意味伝達の区別

20〜26秒区間には、教育用の架空コード `R7K2-P9M4` とともに「この画面のコードは実際のアカウントでは使用できません。」という注意文言が表示されます。基本音声はコードを安全な場所に保存する手順だけを案内しており、画面のコードが実際のアカウントでは使えない教育用の例である点には触れていません。このときの音声解説の目的は、架空文字列の8文字を機械的にすべて読み上げることではなく、画面に示されたコードが実際のアカウントでは使えない教育用の例であるという<strong>重要な意味の欠落</strong>を補うことにあります。

## 実習で確認した情報とまだ残っている判断

実際のメディア点検では、観察事実と最終判定を分離するプロセスが非常に重要です。今回の記録は、共通実習 1.0.2 バージョンをローカルサーバーにレンダリングした初期状態（`variant=a`、`state=initial`）で収集した証拠に限定されます。

* <strong>メディアファイルおよびDOMの確認</strong>：`source.mp4`（約31.21秒）は単一音声ストリームを含みます。DOMの `<track>` 要素には字幕（`captions`）のみが存在し、観察した領域内では音声解説バージョンへ移動するリンクは見つかりませんでした。
* <strong>技術的な誤判の防止</strong>：Chromium系ブラウザーで `audioTracks` API が公開されないという事実だけでは、音声解説トラックがないとは証明できません。同様に、ブラウザーでミュート状態のまま動画を最後まで連続再生できたからといって、音声を聴取検証した証拠にはなりません。
* <strong>観察範囲の限界</strong>：原音処理と約1秒間隔のフレーム観察および6枚の代表フレーム抽出を通じて、12〜15秒と20〜26秒の視覚情報欠落候補を確認しました。しかし、この結果は全フレームの連続観察や専門家による聴取、本番環境全体の監査を代替しません。本番ページの別状態、別ページの代替バージョンリンク、OSレベルのトラック選択経路、そして改善後の音声はまだ検討していません。

したがって、現在の観察範囲において基本音声に重要な視覚情報が欠けている欠陥候補は明確に説明できますが、実習対象全体の最終判定（`actual_decision`）は不合格の確定ではなく<strong>判定保留（`inconclusive`）</strong>に留めます。確定した事実（単一音声ストリーム、観察領域内での解説リンク未発見、12〜15秒の無セリフ警告音）と追加確認が必要な項目（別経路の代替バージョンの有無、本番環境の状態）を分けて記録することで、正確なアクセシビリティ監査が可能になります。

- [ ] <strong>原音と視覚情報の対照</strong>：主な場面転換、エラーメッセージ、ボタン・状態変化、告知文言などの重要な視覚情報が基本音声にすでに含まれているかを区間ごとに対照します。
- [ ] <strong>代替の有効化経路の確認</strong>：G78（プレーヤー・コンテンツ・OSのトラック選択）やG173（別バージョンのリンクおよびページのアクセシビリティ）など、利用者が実際に音声解説を有効にしたり移動したりできる経路が存在するかを点検します。
- [ ] <strong>解説内容の適切性の検討</strong>：単なる装飾や無意味な文字列の羅列ではなく、利用者が次の行動を理解したり注意事項を把握したりするために不可欠な意味が含まれているかを確認します。
- [ ] <strong>セリフの空白と音響保持の点検</strong>：セリフ間の空白の長さと場面との近接性を確認し、警告音などの重要な効果音を覆い隠していないか（BGMは音量調整可能）を検討します。固定の秒数基準は適用しません。
- [ ] <strong>限定達成方法（G203）の条件確認</strong>：静的テキスト代替だけで合格とする場合、単一話者・固定背景・時間依存の視覚情報の不在という条件をすべて満たしているかを厳密に確認します。
- [ ] <strong>根拠の記録と同条件での再検査</strong>：観察した環境（URL、状態、ファイルバージョン）と未確認範囲を分けて記録し、音声解説を追加・修正した後は同じ条件で音響の重なりと発話長を改めて測定して検証します。

## 再利用可能な評価プロンプトの入力準備と出力判定の読み方

アクセシビリティ点検に評価プロンプトを活用する際は、動画ファイルだけを渡すのではなく<strong>入力資料の範囲</strong>を明確に併記する必要があります。ページ内の代替バージョンリンクの有無、プレーヤーのトラック一覧、動画の目的（テキスト代替かどうか）、そして区間ごとの画面・音声観察記録を構造化して入力すると、過度な推測を抑えられます。

出力された判定結果は4つの状態に分けて読みます。

* <strong>`pass`</strong>：基本音声に重要な視覚情報がすべて含まれているか、アクセシブルな音声解説（G78/G173/G226）または厳密な条件を満たすG203が確認された場合です。
* <strong>`fail`</strong>：適用対象の動画で重要な視覚情報が欠落しており、代替経路がなく、適切な空白があるにもかかわらず解説が提供されていないなど、違反が確定した場合です。
* <strong>`not_applicable`</strong>：同期したメディアの定義上、テキストの代替として明示されており、追加の視覚情報がない場合です。
* <strong>`inconclusive`</strong>：欠陥候補が見えていても、別ページの解説バージョンリンク、OSトラック設定、または音声全体の聴取など重要な確認範囲が残っており断定できない状態です。この場合は不足している確認項目を補ったうえで再判定します。
