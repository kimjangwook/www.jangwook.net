日本語のサイトを触っている人にとって、WCAG 2.2 の達成基準 1.4.12 は少し他人事に見える。要求される4つの値のうち、単語間隔は日本語にほぼ効かない。単語の間に空白を置かないからだ。実際に測ってもそうだった。`word-spacing: 0.16em` だけを当てたとき、日本語ページで新たに切れた要素は<strong>1件</strong>だった。

問題は残りの3つのほうにあった。とくに1つ。

## 4つの値と、チェッカーが読む範囲

先に基準そのものを押さえておく。達成基準 1.4.12 Text Spacing はレベル AA で、4つの値で書かれている。行の高さはフォントサイズの1.5倍以上、段落の後ろの間隔は2倍以上、字間は0.12倍以上、単語間隔は0.16倍以上。この4つを利用者が自分で設定したときに<strong>内容や機能が失われないこと</strong>、というのが要求の本体だ。

この基準が何のためにあるのかを一度書いておきたい。ディスレクシアや弱視、一部の認知障害のある読者は、行が詰まっていると次の行を見つけられずに同じ行へ戻ってしまう。だから拡張機能やユーザースタイルシートで間隔を強制的に広げて読む。1.4.12 は「間隔を広く取れ」と言っているのではない。<strong>読者が自分で広げたときに、あなたのレイアウトが耐えるか</strong>を問うている。著者の仕事は間隔の設定ではなく、余白の確保だ。

そして [W3C の Understanding 文書](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)は、失敗の型を3つ図で示している。縦に切れる、横に切れる、次の文と重なって読めなくなる。逆に省略表示そのものは失敗と見なさない、とも書いてある。切り詰めた部分を表示する手段があれば許容される。この但し書きが、後半でこの記事の結論を分けることになる。

では自動チェッカーはこれをどう判定するのか。axe-core で 1.4.12 に対応するルールは `avoid-inline-spacing` ひとつだけだ。Deque が公開しているルールの説明はこうなっている。"Ensure that text spacing set through style attributes can be adjusted with custom stylesheets."

インラインの `style` 属性で指定した間隔を、ユーザースタイルシートが上書きできるか。見ているのはそこまでだ。間隔を当ててみることはしないし、当てた後のレイアウトも見ない。

自分のサイトにこのルールだけを走らせた結果がこれだ。

```
axe-core 4.13.0  ·  runOnly: avoid-inline-spacing
24 pages
violations: 0   passes: 24   incomplete: 0   inapplicable: 0
```

24ページすべて合格。インライン `style` で間隔を固定した箇所がないのだから当然で、ルールは仕事を正確にこなしている。

[昨日、W3C の ACT テストケース1,213件で axe の守備範囲を測ったとき](/ja/blog/ja/act-rules-axe-coverage-wcag-sc-2026)、1.4.12 は14件中13件が検出され、カバレッジの良い側に並んでいた。あの数字も正しい。ただしその13件はすべてインライン `style` の例題だった。正解付きテストが問うものと、実サイトが実際に踏むものが別種だったということになる。

## 4つの宣言を1つずつ当てる

そこでルールではなく基準そのものを当てるスクリプトを書いた。`scripts/audit-text-spacing.mjs` だ。やることは単純で、Playwright でページを開き、素の状態で全要素の寸法を記録し、4つの値を `!important` で注入してもう一度記録し、差分を取る。

損失の判定は3つの経路に分けた。

- `overflow: hidden` または `clip` の箱で `scrollHeight` が `clientHeight` を超えた要素
- `-webkit-line-clamp` の箱で、隠れる行数が増えた要素
- 文書全体に横スクロールが新しく生えたページ

標本は24 URL。4言語のトップ、記事一覧、静的ページ、本文ページ、404 を混ぜた。ビューポートはデスクトップ 1280×800 とモバイル 390×844 の2種類で、合計48画面になる。

4つ全部を当てた結果はこうなった。

| 指標 | 値 |
|---|---|
| 新たに切れた要素 | 570 |
| クランプで行を追加で失った要素 | 1,438 |
| 損失が出た画面 | 48中29 |
| 横スクロールが新たに生えたページ | 0 |
| ページ高さの増加 | 最小1.006倍・中央値1.123倍・最大1.487倍 |

横スクロール0は素直に嬉しい数字だった。流動レイアウトなので、字間が広がっても文書の幅は保った。起きたことはすべて箱の内側だ。

ただ570という合計だけでは、どこを直せばいいのか分からない。4つのうち誰が犯人なのかが分からないからだ。そこで1回に1つだけを当てて、あと4回まわした。

![SC 1.4.12の4つの宣言を1つずつ当てたときに新しく切れた要素数を比べた横棒グラフ。line-height 1.5と段落間隔2emは0件、word-spacing 0.16emは122件、letter-spacing 0.12emは523件、4つ同時では570件](../../../assets/blog/text-spacing-1412-clamp-audit-2026/declaration-decomposition.png)

| 宣言 | 新たに切れた要素 | 失ったクランプ行 | ページ高さ中央値 |
|---|---|---|---|
| `line-height: 1.5` | 0 | 0 | 1.000倍 |
| `margin-bottom: 2em`(段落後) | 0 | 0 | 1.064倍 |
| `word-spacing: 0.16em` | 122 | 225 | 1.004倍 |
| `letter-spacing: 0.12em` | 523 | 1,316 | 1.036倍 |
| 4つすべて | 570 | 1,438 | 1.123倍 |

数字が完全に片側へ寄った。縦方向の2つは<strong>1件も損失を生まなかった</strong>。損失はすべて横方向の2つから出て、そのうち字間ひとつが523件、全体の92%を占めている。

## 伸びる軸と、切れる軸は別だ

この結果を見て、自分が順番を取り違えていたと気づいた。

1.4.12 の解説はたいてい行の高さ1.5から始まる。私もそう理解していた。では行の高さを1.5に上げると何が起きるか。行間が開き、段落が長くなり、ページが下へ伸びる。`-webkit-line-clamp` の箱も一緒に伸びる。クランプ箱の高さは行数×行の高さで決まるからだ。3行は3行のまま。見える文字数は変わらない。

段落後の間隔も同じだ。ページ高さの中央値を1.064倍まで押し上げたが、損失は0件。縦にずれる分はスクロールが吸収する。

字間は違う。0.12em は1文字あたりの幅が増えるということで、1行に入る文字数が減るということだ。3行クランプの箱は3行のままだが、その3行が抱える内容が減る。箱は変わらず、中身が膨らんで溢れる。

まとめるとこうなる。<strong>目につく軸と、内容を失う軸が別々だ。</strong>ユーザースタイルシートを入れた読者が体感するのは「ページが長くなった」であり、実際に消えるのは横へ押し出された文末のほうだ。そして目視のQAで気づきやすいのは前者になる。

ここで測定方法をもう1つ確かめる必要があった。よく使われるテキスト間隔のブックマークレットは `line-height: 1.5` をそのまま書き込む。ところが私の本文はすでに1.58で組んである。1.5で上書きするのは<strong>縮める</strong>動作だ。事実、行の高さだけを当てたときページ高さの最小値は0.926倍だった。7%短くなったページがある。

そこで「1.5未満の要素だけ1.5へ上げる」というもう一つの読み方で48画面を回し直した。結果は新たに切れた要素570件、失った行1,438件。1つめの方式と<strong>完全に同じ</strong>だった。変わったのはページ高さの中央値が1.123倍から1.168倍になったことだけ。行の高さをどう解釈しても損失の数字は動かない。原因ではないという証拠がもう1つ増えた。

## 空白のある言語と、ない言語

`word-spacing` だけを当てたときの122件を言語別に割ると、予想していなかった図が出た。

| 言語 | 新たに切れた要素(デスクトップ / モバイル) |
|---|---|
| 日本語 | 1 / 1 |
| 中国語 | 3 / 4 |
| 韓国語 | 40 / 15 |
| 英語 | 0 / 55 |

日本語と中国語は実質ゼロ。理由ははっきりしていて、単語の間に空白を置かないので `word-spacing` の効く場所がほとんどない。Understanding 文書にもこの点への手当てがある。当該のプロパティを使わない文字体系は、存在するプロパティだけで適合できるという例外だ。

問題は韓国語の40件だ。韓国語は CJK でひとくくりにされるが、<strong>分かち書きをする</strong>。単語間の空白が実在するので `word-spacing` がそのまま効く。W3C の例外は日本語と中国語には掛かり、韓国語には掛からない。

多言語サイトを扱う立場では、ここは実務的に効く区別だ。「CJK は word-spacing の影響なし」とひとまとめに処理すると、韓国語ページで静かに間違える。自分がそう考えていたことに、この表を見て気づいた。

英語のモバイル55件は事情が違う。英語の抜粋は平均168文字で4言語のうち最も長い。390px 幅ではその長さが3行クランプの境界にちょうど乗っていて、単語間隔が少し開くだけで越える。デスクトップで0件だったのも同じ理由で、幅が広ければ余裕がある。

`letter-spacing` のほうは言語を選ばない。文字ごとに付くからだ。韓国語のデスクトップが164件で最も強く当たった。日本語も61件出ている。

## 切ってよい文と、切ってはいけない文

ここまでが基準の話だ。実際に何を直すかは別の問いだった。

測定データの中でクランプが掛かっていたコンポーネントは3種類。それぞれについて「箱が自分の中身の何パーセントを見せているか」を、素の状態と間隔適用後に分けて出した。

| コンポーネント | 観測数 | 素の状態 | 間隔適用後 |
|---|---|---|---|
| 記事カードの抜粋(`line-clamp: 3`) | 2,688 | 86.2% | 76.6% |
| トップの最新記事抜粋(`line-clamp: 2`) | 24 | 49.4% | 40.8% |
| 推薦理由(`line-clamp: 1`) | 42 | <strong>35.1%</strong> | 30.7% |

3行目で手が止まった。

`.item-reason` は関連記事リストに添える一文だ。「この記事を読んだならあちらも」を毎回手で書いている。4言語それぞれに別々に書く。平均108文字。そしてこの文は<strong>サイトのどこにも再掲されない</strong>。その場にしかない。

1行クランプが、そのうち35%しか見せていなかった。間隔を当てる前からそうだった。

![関連記事リストの修正前。3項目とも推薦理由の文が1行で省略記号に切られている](../../../assets/blog/text-spacing-1412-clamp-audit-2026/item-reason-before.png)

この発見は 1.4.12 と直接の関係がない。テキスト間隔を当てたから生まれた問題ではなく、最初からあった問題だ。アクセシビリティ基準を測るために作った計測器が、コンテンツのバグをくわえてきた。こういうことはときどき起きる。[標本26ページでは捕まらなかった違反を全件走査で見つけたとき](/ja/blog/ja/wcag-em-2-sampling-vs-full-sweep-audit-2026)も似た経路だった。

そして先送りにしていた但し書きがここで戻ってくる。Understanding 文書は省略表示を失敗と見なさない、ただし<strong>切り詰めた部分を表示する手段があるとき</strong>という条件を付けていた。この条件で3つのコンポーネントを見直すと、判定が割れる。

記事カードの抜粋はクリックすれば本文が出る。手段がある。76.6%まで落ちても、これは設計された要約であって損失ではない。トップの抜粋も同じだ。

推薦理由には手段がない。展開するボタンもなければ、同じ文が載る別ページもない。切られた65%は誰にも見えない。間隔を当てる前から損失だった。

だからクランプを増やすのではなく、外した。

```css
.item-reason {
  margin: 0;
  font-size: 0.8125rem;
  color: var(--ink-2);
  line-height: 1.5;
  /* この文は推薦ごとに書いていて、他の場所に再掲されない。
     ここで切ると表示する手段がないので、切らない。 */
}
```

`line-height` も1.4から1.5へ上げた。理由は前の分解結果から出てくる。<strong>著者が組んだ行の高さが基準の1.5をすでに満たしていれば、利用者による行の高さの上書きは箱を縮められない。</strong>1.4のままだと、1.5を強制する利用者の前で箱が広がりレイアウトが動く。1.5で組んでおけばその軸では何も起きない。クランプを使うテキスト全般に当てはめてよい規則だと思う。

トップの最新記事抜粋は2行から3行へ増やした。こちらは本文へのリンクがあるので、切ること自体は残した。

![修正後。同じ3項目の推薦理由が2行にわたって文末まで表示されている](../../../assets/blog/text-spacing-1412-clamp-audit-2026/item-reason-after.png)

## 直したのに数字が悪化した

ビルドし直して48画面を測り直した。そして次の数字を見た。

```
修正前:  新たに切れた要素 570
修正後:  新たに切れた要素 574
```

4つ増えている。

最初は退行を疑ったが、違った。指標そのものの性質の問題だ。「新たに切れた」は<strong>素の状態では切れておらず、間隔適用後に切れた</strong>要素を数える。閾値をまたぐ瞬間だけを捕まえる指標である。`.item-reason` は修正前、素の状態ですでに切れていた。常に切れている箱は「新たに」切れようがない。この指標の視野の外にいたわけだ。

クランプを外してその席が空き、代わりにトップの抜粋が2行から3行になったことで素の状態に余裕ができ、間隔適用後に溢れる要素が4つ新しく観測範囲へ入ってきた。

同じデータを別の指標で見ると向きは逆になる。

| | 修正前 | 修正後 |
|---|---|---|
| 損失が出た画面 | 48中29 | 48中<strong>18</strong> |
| トップ抜粋の表示率(素の状態) | 49.4% | <strong>74.2%</strong> |
| 推薦理由の表示率(素の状態) | 35.1% | <strong>100%</strong> |

これをわざわざ書くのには理由がある。アクセシビリティのゲートを CI に置くとき、私たちはたいてい違反件数ひとつを指標にする。あの数字は閾値をまたいだかどうかしか数えない。<strong>恒常的に失敗している要素は、その数字に現れない。</strong>いつも切れている箱は今日も切れているだけで、変化がないからだ。件数をゼロにすることへ集中すると、この種の失敗を構造的に取りこぼす。

割合の指標を併記すべき理由がここにある。[固定ヘッダーがフォーカスを隠すかを測ったとき](/ja/blog/ja/focus-not-obscured-sticky-header-scroll-padding-2026)、辿る向きで結果が割れたのと同じ種類の罠だ。何を数えるかが、何を見るかを決めてしまう。

## この測定が言っていないこと

範囲を正直に狭めておく。

Chromium 1系統、Mac 1台、24 URL。1,356ページ全部ではない。Firefox と WebKit は `letter-spacing` のサブピクセル処理も `-webkit-line-clamp` の実装も違うので、数字は変わりうる。確認していない。

重なりはそもそも測っていない。判定に使ったのは `overflow: hidden` の箱の溢れとクランプの行数の2つだけだ。切り取る祖先がないまま次の要素の上に文字が乗る失敗型は、このスクリプトでは捕まらない。Understanding 文書が明示する3つの失敗型のうち、1つを丸ごと外していることになる。

「横スクロール0件」は文書レベルの話で、ページが横へずれなかったという意味しかない。すべての要素が無事だという意味ではない。

そして axe は誤っていない。`avoid-inline-spacing` はルールの説明に書かれた仕事を正確にやったし、私のサイトにはそのルールが探すインライン宣言がない。合格が正しい。この記事はチェッカーへの批判ではなく、<strong>ルールの射程と基準の射程が違うことを数字で確かめた記録</strong>だ。

## まとめ: 切ってよい文かどうかを先に決める

今回の測定から実際に使えるものだけ残す。

- <strong>クランプを使う前に質問をひとつ通す。</strong>「切った先を読める経路があるか」。抜粋から本文へのリンクは経路だ。その場にしかない文には経路がない。後者は切ってはいけない。
- <strong>クランプが掛かるテキストの `line-height` は、著者側で先に1.5以上にしておく。</strong>基準の下限をすでに満たしていれば、利用者の上書きはその軸で何も変えられない。
- <strong>損失を心配すべき宣言は `letter-spacing` だ。</strong>523対0。行の高さと段落間隔はページを長くするだけ。レビューの時間は横方向へ使う。
- <strong>多言語サイトで「CJK」をひとまとめにしない。</strong>`word-spacing` は日本語・中国語にはほぼ無害だが、韓国語にはそのまま効く。分かち書きの有無が分かれ目になる。
- <strong>違反件数の横に割合の指標を残す。</strong>件数は閾値をまたぐ瞬間しか数えない。常に失敗している要素は件数に出てこない。

再現手順はそのまま置いてある。`scripts/audit-text-spacing.mjs` に URL 一覧を食わせ、`--mode` で4つの宣言を1つずつ分けて回せば、自分のサイトのどこが誰に切られているかが30秒ほどで出る。

チェッカーが通した基準を実際に当てて測り直す。これが私の仕事のかなりの部分を占めている。どこから手を付けるか決まっていない段階でも構わないので、気になったら[お問い合わせページ](/ja/contact/)から声をかけてもらえればいい。
