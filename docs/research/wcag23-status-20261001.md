# WCAG 2.3 요청에 대한 버전 확인

확인일: 2026-10-01. 사용자 요청: 첫 개요를 WCAG 2.3 기준으로 재작성. 이 파일은 조사 기록이며 새 개요 초안이 아니다.

## 현재 확인한 사실

1. W3C WCAG 2 FAQ는 AG WG가 WCAG 2.3을 계획하지 않고 WCAG 3을 개발한다고 설명한다.
2. `https://www.w3.org/TR/WCAG23/`는 직접 HTTP 요청에서 404였다. `https://w3c.github.io/wcag/guidelines/23/`에서도 공개 편집자 초안을 확인하지 못했다. 공개된 2.3 요구의 정본을 확보하지 못했다는 의미이며, GitHub의 모든 향후 논의를 부정하는 근거로 사용하지 않는다.
3. W3C 공식 GitHub에는 WCAG 2.3 라벨의 변경 제안이 있다. PR #5183은 초점이 가려지는 기준의 이름을 고치는 제안이며, 본문에서 가능성 있는 2.3을 위한 제안이라고 명시한다. 원문은 확정된 2.3 표준이 아니다.
4. Alastair Campbell의 2026-06-09 공식 메일은 향후 WCAG 2.x 업데이트를 결정할 경우 보관할 변경 제안과 현 버전 errata를 구별한다. 이 메일은 2.3 출판 일정이나 전체 기준 목록을 확정하지 않는다.
5. W3C의 WCAG 3 소개는 3.0이 변경될 미완성 초안임을 설명한다. 2026년 9월 초안은 WCAG 2.x와 구조·적합성 모델이 다르므로 A/AA/AAA와 86개 성공 기준을 그대로 사용해서 설명할 수 없다.

## 기준 문서에 따른 집필 차이

- WCAG 2.3 변경 제안을 추적하는 방향이라면 확정된 2.2 요구를 실무 기준으로 구별하고, 제안별 상태·원문·변경 이유·실험적 평가 방법을 설명한다. 2.3을 이미 발행된 표준이나 전체 목록이 정해진 버전으로 소개하지 않는다.
- WCAG 3.0 공개 초안이 대상이라면 해당 날짜의 공식 초안과 Explainer를 바탕으로 개요와 항목 분류, 프롬프트 구조를 다시 설계한다. 초안의 성숙도와 변경 가능성을 표시한다.
- 사용자가 별도의 2.3 원문을 지칭했다면 그 문서의 출처·판본·공개 상태를 확인한 뒤 집필한다.

이후 사용자에게 현행 권고가 WCAG 2.2임을 설명했다. 사용자는 기존 개요를 긍정적으로 평가하고 도식 보완을 요청했다. 이번 시각 자료 보완본은 2.2 기준을 유지하며, 기존 검토 PDF도 보존한다.
