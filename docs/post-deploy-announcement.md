# 블로그 발행 후 @effloow 발표 — 2026-10-03

사용자의 현재 X 운영 계정은 @effloow 하나다. 사용자가 승인한 jangwook.net 글의 신규 공개 또는 본문 갱신을 production URL에서 확인한 뒤, @effloow에 영어로 발표한다. 사이트 파일 커밋이나 배포 시도만으로 발표하지 않는다. 승인되지 않은 준비 문서와 실패한 배포를 발표하지 않는다. 기존 일본어 X 초안의 Telegram 전달은 현재 기본 절차에서 제외한다.

기본 형식은 `[1/4]`~`[4/4]` 영어 게시물 네 개의 연결된 스레드이며, 공개된 영어 원고의 내용만 사용한다. 한국어 번역은 검토 기록에 함께 둔다. 앞 네 개에는 URL을 넣지 않는다. 네 번째 게시물을 올린 뒤 그 게시물에 별도의 자기 답글로 영어 기사 canonical URL 하나만 붙인다. 링크 답글을 독립 게시물로 올리거나 첫 글·중간 글에 붙이지 않는다. 영문판이 준비되거나 승인되지 않았다면 링크를 임의로 다른 언어로 대체하지 않는다.

## 실행 순서

1. manifest의 공개 상태·승인 해시·현재 번역 정본을 확인한다. 운영 영어 URL의 HTTP 2xx, 제목, article-source-sha256가 로컬 승인 원고의 sourceHash와 일치해야 한다. 원고 해시는 제목·요약·본문·프롬프트까지 포함한 SvelteKit 콘텐츠 identity를 사용한다.
2. 공개 글을 바탕으로 구체적인 문제, 확인 방법, 조건과 한계, 새 글의 내용을 영어로 설명한다. 장욱의 웹 개발자 페르소나와 effloow-x-growth 지침을 적용한다. 기사에 없는 측정·성과·실험·개인 경험을 만들지 않는다. 각 게시물은 번호 포함 X 가중 길이 280 이하이며, 해시태그·영업 문구를 넣지 않는다.
3. 계정·영어 sourceHash·문구·한국어 번역·마지막 링크·가중 길이를 발행별 x-announcement-en.json에 저장한다. 같은 sourceHash와 계정의 발행 영수증이 이미 있으면 중복 발표하지 않는다. 일부 게시되었거나 전송 결과가 불명확하면 공개된 상태부터 확인하고 미완료 단계만 이어간다.
4. Computer Use로 활성 계정이 @effloow인지 확인한다. 다중 게시물 작성 창에서 본문 네 개를 검토하고 연결된 스레드로 게시한다. 실제 공개 게시물의 순서·문구·계정·URL을 확인한 뒤, 네 번째 글에 영어 기사 URL만 답글로 게시한다.
5. 마지막 답글의 실제 대상·게시물 URL·기사 링크의 전체 목적지를 확인한다. 각 본문 URL과 링크 답글 URL, 시간, sourceHash, 계정, 공개된 본문, 캡처를 x-publication-receipt.json에 기록한다. 작성 창 입력이나 전송 시도만으로 발표 완료라고 기록하지 않는다.

이 절차는 승인된 수동 발행의 후속 작업이다. 새로운 집필 예약·정기 작업·자동 X API 게시를 활성화하지 않는다. 기존 `lm jangwook-net x-draft`는 일본어 Telegram 초안용 레거시 명령이며, 현재 영어 X 발표의 실행 명령으로 사용하지 않는다.
