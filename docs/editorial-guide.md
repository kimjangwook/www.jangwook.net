# 편집·교육·컨설팅 페르소나

김장욱은 방문자의 실무 판단을 돕는 웹 전문가이자 교육자·컨설턴트로 말한다. 독자를 동료로 존중하면서 먼저 기준을 설명하고 구체적인 선택을 권한다. 개인 경험·고객 사례·측정 수치·인증을 만들어내지 않는다. 예제는 교육용 가상 사례로 명시한다. 회사 내부 정보는 공개하지 않는다.

각 글은 독자의 문제 → 기준의 취지와 예외 → 사례·의사결정 → AI 입력 자료 준비 → 항목별 프롬프트 → 결과 해석 → 개선/재점검으로 구성. 접근성을 체크리스트 암기보다 실제 이용자의 목적 달성으로 가르친다. AI 자동화 범위를 영구 고정하지 않으며 스크린샷·DOM·접근성 트리·조작 기록·음성/영상의 조합으로 검증한다. 기준의 내용과 평가 가설은 구분한다. 모델 성능 주장은 정상/실패/경계 사례의 오탐·누락·일관성·비용 측정 이후에만 한다.

사용자가 주제와 발행 순서를 선정한다. 신규 초안·자동 생성은 공개 승인이 아니다. 초안에는 status=draft, reviewedAt=null, publishedAt=null을 둔다. 승인할 때 문서와 프롬프트의 contentHash를 approvalHash에 묶는다. 문서 수정으로 hash가 바뀌면 재승인한다. 업데이트에는 기준/프롬프트 버전, 변경 이유, 검증 상태를 함께 남긴다.

첫 시리즈: 개요 1편 + WCAG 2.2의 모든 활성 성공 기준 86편(각 1개 고유 프롬프트) + 에이전트 통합 마무리 1편. AAA도 포함하되 서비스 기본 평가 목표 A/AA와 구분. 제거된 4.1.1 Parsing은 기준 연혁 안내에만 기록. 항목별 글은 심화 집필의 1차 초안이며 실험 검증을 완료했다고 주장하지 않는다.


## 시리즈의 지속 기준 — 2026-10-01 사용자 요청 반영

- 사용자가 직접 선별한 주제를 전문가·교육자·컨설턴트의 판단으로 설명한다. 일반론을 자동으로 늘리는 방식으로 글의 수를 채우지 않는다.
- 개요는 독자가 시리즈의 목표와 자신의 첫 실습을 이해하도록 쓴다. 이후 항목별 글에서는 취지·적용 조건·예외·구현 판단을 충분히 설명하고 고유한 프롬프트를 제공한다.
- 기존 규칙 도구의 검사 범위를 AI 평가의 영구적인 한계로 취급하지 않는다. 멀티모달 모델과 DOM·접근성 트리·실제 조작·음성·영상 입력을 조합해 평가 범위를 확장하는 방법을 탐구한다.
- 기준의 요구, 필자의 평가 설계, 외부 연구 성과, 직접 실행 결과를 구별한다. 입력 누락·실행 실패·해석 불확실성을 구별해 프롬프트와 도구를 개선한다.
- 시리즈별로 글과 프롬프트를 지속적으로 업데이트한다. 사용한 표준 원문·판본·확인일·변경 이유·검증 범위를 남긴다. 개요에서부터 확정되지 않은 평가 성능을 약속하지 않는다.
- 마무리 글에서 전체 프롬프트를 에이전트 평가 과정과 서비스 구조로 연결한다. 전체 자료 신청 폼 → 내부 데이터베이스의 리드 → 신청 이메일로 프롬프트 모음집 전달의 의미를 유지한다. 개요에 서비스 홍보를 과도하게 넣지 않는다.
- 표준 버전을 바꿀 때에는 해당 버전의 공식 문서와 공개 상태를 먼저 확인한다. 현재 표준·공개 초안·향후 버전 후보 제안을 같은 요구로 다루지 않는다. 기존 버전의 기준 수·수준·번호를 새 버전에 그대로 붙이지 않는다.

### 요청한 버전의 원문 확인

2026-10-01 사용자가 WCAG 2.3 개요로의 전환을 요청했다. 공식 자료 조사 결과, 현행 권고는 WCAG 2.2이며 2.3 후보 제안은 공개 표준이 아니다. 2.2임을 설명한 뒤 사용자는 기존 개요를 긍정적으로 평가하고 시각 자료 보완을 요청했다. 따라서 이번 개요와 도식은 2.2를 유지한다. [버전 조사 기록](research/wcag23-status-20261001.md)을 참조한다. 기존 2.2 초안과 검토 PDF를 2.3 표준이라고 재표기하지 않는다.

### 이해를 돕는 시각 자료

2026-10-01 사용자 요청에 따라 복잡한 구조·상태 변화·문맥 비교·평가 흐름에는 학습 목적이 있는 도식을 제공한다. 정확한 한글과 연결 관계가 필요한 도식은 수정 가능한 SVG로 제작한다. 장식용 이미지를 의무적으로 추가하지 않는다. 도식의 핵심 관계를 대체 텍스트와 본문으로도 전달하고, 가상 예시·평가 설계·실제 결과를 구분하는 캡션을 붙인다. 모바일·JavaScript 비활성 환경·검토 PDF에서 렌더링과 가독성을 확인한다. 자산 파일은 내용 해시를 포함한 경로로 연결해 도식 변경이 원고의 승인 해시에 반영되도록 한다.

### 언어별 글과 도식

새 시리즈는 한국어·영어·일본어·중국어 간체를 필수로 제공한다. 한국어 정본을 기준으로 본문·프롬프트·도식 내부 문구·SVG title/desc·대체 텍스트·캡션·목차·내비게이션을 번역하고 별도 원문 대조를 수행한다. 언어별 자료 신청 페이지는 아직 한국어이므로 UI에서 표시한다.

2026-10-01 첫 개요의 네 언어 본문·프롬프트·도식과 88편 전체의 제목·요약을 작성했다. 나머지 본문은 완성된 번역이라고 표시하지 않는다. 한국어의 기존 항목별 내부 초안은 보존하되 reviewReady=false로 일반 로컬 화면에도 노출하지 않는다. 영어·일본어·중국어의 87편 문서·프롬프트 파일은 준비 안내만 작성해 두었으며 hasContent=false다.

88편 × 4개 언어의 URL은 미리 제공하며 목차·이전/다음·언어 전환으로 연결한다. 준비 중 페이지는 제목·요약·준비 안내·기준 원문 링크만 SSR로 제공한다. 본문과 프롬프트는 페이지 데이터에도 포함하지 않는다. HTTP 200과 noindex,follow를 사용하며 발행 날짜·BlogPosting·RSS·sitemap 글 항목은 생성하지 않는다. 완성 후 동일 주소에서 교체한다.

검토 가능한 본문에는 reviewReady=true를 설정한다. 실제 번역에는 hasContent=true와 정본 translationSourceHash가 필요하며 원문이 바뀌면 번역은 재검토 전까지 준비 화면으로 돌아간다. 공개에는 각 언어의 현재 sourceHash와 일치하는 approvalHash 및 reviewedAt/publishedAt이 필요하다. 원문 승인으로 번역을 자동 승인하지 않는다. [초기 점검 및 변경 기록](research/overview-language-audit-20261001.md)을 참조한다.


## 2026-10-02 공개 및 UI 정책

루트 `/`는 선택 언어 쿠키(`site_language`, 180일)를 우선하고 브라우저 `Accept-Language`를 참고해 `/ko/`, `/en/`, `/ja/`, `/zh/` 홈으로 302 이동합니다. 응답은 `private, no-store`, `Vary: Accept-Language, Cookie`입니다. 홈은 실제 승인·공개된 최신 글을 발행 시각 내림차순으로 최대 5편 표시하고, 시리즈와 메뉴 링크만 제공합니다. 현재 공개 글은 접근성 개요 한 편이므로 준비 중 글을 채워 넣지 않습니다. 네 언어 홈은 SSR·고유 canonical·상호 hreflang·x-default와 언어 선택기를 제공합니다. 한국어 시리즈의 기존 무접두 경로와 아카이브 URL은 유지합니다.

개인 이름은 `/about` 소개 페이지에서만 표시합니다. 공통 작성자 표시, 푸터 이름, 홈 소개, 도구 메뉴, 자료받기 CTA와 독립 신청 폼은 제거합니다. 기존 `/resources/accessibility` 주소는 선택 언어의 마지막 글 `/series/accessibility/agentic-accessibility`로 308 이동합니다. 신청 폼은 마지막 글이 완성되고 모음집이 승인될 때 그 글 안에 추가할 예정입니다. 현재 마지막 글은 준비 중이며 폼과 메일 전송을 제공하지 않습니다. 이전 독립 폼 기반 브라우저 검증 기록은 이전 버전의 이력입니다.

접근성 개요의 네 언어 본문·평가 프롬프트·도식 4개를 사용자 지시로 공개합니다. 정확한 sourceHash 승인과 번역 원본 일치 검증을 유지하고, RSS·sitemap·BlogPosting에 공개 글만 포함합니다. 나머지 87편 × 4언어는 본문 없는 준비 중 문서이며 noindex,follow입니다.

모든 문서에 ‘초판 공개일’(`firstPublishedAt`)과 ‘최종 수정일’(`updatedAt`)을 표시합니다. 초판 공개일은 첫 실제 발행 때만 기록하며 수정 후에도 유지합니다. 준비 중 문서는 공개일을 만들지 않고 ‘공개 예정’이라고 표시합니다. 수정일은 보존된 본문·프롬프트·참조 도식 파일의 수정 기록에서 복원했습니다. compiler는 내용 해시가 변경되면 최종 수정일을 Asia/Tokyo 날짜로 갱신하며 초판 공개일은 덮어쓰지 않습니다. 내용 변경 시 기존 해시 승인은 자동으로 무효화됩니다. 최종 수정일은 공개 글의 dateModified, article:modified_time, sitemap lastmod에도 동일하게 제공합니다. 초판 공개일은 datePublished와 article:published_time에 사용합니다. 날짜 표기를 위한 메타데이터는 본문 승인 해시를 변경하지 않습니다.


## 시리즈 상세 페이지 원칙 — 2026-10-02

사용자가 전체 학습 목록 토글, 학습 성과를 설명하는 제목 아래 요약, 글과 시리즈의 JSON-LD 연결을 승인하고 향후 작성 원칙으로 저장하도록 요청했습니다. 상세 페이지 작업 전에 [article-detail-guidelines.md](article-detail-guidelines.md)를 읽고 적용합니다. 기본 접힘, 현재 글 순서와 강조, 공개/준비 상태, 네 언어 SSR 링크, PC 사이드바/모바일 요약 아래 배치, 키보드·no-JS 동작을 유지합니다. 준비 중 글에는 BlogPosting이나 발행 날짜를 만들어 넣지 않습니다.

## 프롬프트 검증과 최종 원고 구성

공개된 이전 글을 실제 평가 페이지로 삼고, 1회차 평가 계획 프롬프트와 해당 항목의 평가 프롬프트 원문을 그대로 사용한다. 입력란의 실제 자료만 채우며 프롬프트·입력 자료를 고정해 GPT-6.1 Sol과 Claude Opus 5.5 High에서 비교한다. 모델과 반환 모델, 적용 범위, 사전에 정한 검증 항목, 반복 일관성, 실제 실행 결과를 내부 자료로 보존한다. 품질을 먼저 비교하고 동률인 경우에만 지연 시간을 추가 기준으로 삼는다.

최종 글에는 성과가 더 좋은 모델의 확인된 결과와 독자가 사용할 완성된 프롬프트를 싣는다. 수정 이력, 시행착오, 모델 교체·인증·출력 오류 처리 과정은 독자용 본문에 쓰지 않는다. 실행 언어를 불필요하게 설명하지 않는다. 검증 범위와 실제 결과를 짧게 명시하고, 특정 사례의 통과를 모든 웹사이트에서의 완벽한 성능으로 확대하지 않는다.

사용 문맥을 비교하는 그림에는 각 화면의 와이어프레임, 주변 텍스트, 실제 클릭 범위를 보여 준다. 대안의 핵심은 본문과 alt에도 제공하고, 큰 도식은 원본 보기 링크와 PDF 확대 가독성을 확인한다.
