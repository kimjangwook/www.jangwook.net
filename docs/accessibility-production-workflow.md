# 접근성 시리즈 제작 원칙

2026-10-11 사용자 지정. 접근성 시리즈의 신규 글과 내용 갱신에 적용한다. 이전의 GPT-6.1 Sol·Claude Opus High 필수 비교 지침보다 이 모델 배정이 우선한다. 이미 공개한 실행 결과의 모델·effort·검증 기록은 당시 사실대로 보존한다.

## 단계와 담당 모델

| 단계 | 담당 | 작업과 산출물 |
|---|---|---|
| 1. 기초 조사 | Ollama Cloud의 DeepSeek v4.1 Cloud | 표준 원문, 적용 조건·예외, 관련 기법·사례를 수집하고 주장별 출처와 확인일을 정리한다. |
| 2. 보강 조사 | GPT-6.1 Sol High | 기초 조사의 원출처를 확인하고 누락·상충·경계 사례를 보완한다. 모델 요약 자체를 근거로 사용하지 않는다. |
| 3. 글 작성 | 브라우저의 Gemini 4 Argon | 2026-10-16 사용자 변경 지시. 브라우저에서 Argon 선택을 확인한 뒤 한국어 본문·도식 설명·개요 및 항목별 프롬프트를 집필한다. 공개 출처와 검증 자료를 전달하며 대화 URL·선택 모델·입출력·해시를 기록한다. CLI 가용성을 브라우저 가용성으로 대신 판단하지 않는다. 사용 한도 도달이나 경량 모델 자동 전환이 보이면 추가 집필을 중단하고 상태를 기록한다. 대체 모델을 Argon 결과로 취급하지 않는다. |
| 4. 테스트 실행 | Claude Opus Medium | 실제 공개 페이지 또는 통제된 실습 자료에 고정한 프롬프트를 실행한다. 원시 출력·판정·근거·오류·검토 범위를 보존한다. |
| 5. 리뷰 | GPT-6.1 Sol High + Fable Low | 두 모델이 별도 세션에서 동일한 최종 원고·프롬프트·출처·테스트 기록을 검토한다. 각 리뷰의 지적 사항을 수정하고 변경 범위를 다시 평가한다. |
| 6. 배포 | 검토 완료된 정확한 콘텐츠 버전 | 기존 사용자 검토 절차와 공개 승인을 적용하고 네 언어를 완성·검수한 뒤 커밋·푸시·배포·운영 확인·영어 X 발표까지 진행한다. |

과거 집필 단계의 Sonnet 5.5 Medium + GPT-6.1 Sol Medium 배정은 2026-10-16부터 브라우저 Gemini 4 Argon으로 대체한다. 기초·보강 조사, 테스트, 리뷰의 배정은 유지한다. 테스트의 Claude 버전은 Opus 5.5다. Fable은 사용자가 지정한 Low를 유지한다. 모델 세대나 공급자 ID를 추측해 바꾸지 않으며 실행 직전 실제 선택 가능한 모델과 effort를 확인한다. GPT Sol의 세대는 이 지시에서 명시한 GPT-6.1 Sol로 통일한다.

## 실행 모델과 기록

기초 조사의 지정 대상은 Ollama Cloud의 DeepSeek v4.1이다. 기존 Life Manager 설정의 `deepseek-v4.1-flash`는 실행 ID 확인을 위한 후보이며, 이 문서만으로 호출 성공이나 가용성이 확인된 것은 아니다. 각 작업에서 요청 모델·공급자·실제 반환 모델·effort·실행일·입출력 해시·출처·도구를 기록한다. 지정 모델 실행에 실패하면 해당 단계는 미완료로 남긴다. 다른 모델로 조용히 대체하거나 대체 결과를 지정 모델의 결과로 보고하지 않는다.

이 배정은 접근성 시리즈의 수동 제작 절차다. Life Manager의 전역 writer/researcher/reviewer 역할이나 다른 프로젝트의 모델 설정을 이 시리즈 때문에 변경하지 않는다. 문서 저장을 자동 파이프라인 구현·모델 실행 완료로 간주하지 않는다.

## 프롬프트와 실제 테스트

개요의 평가 계획 프롬프트와 해당 항목의 평가 프롬프트 원문을 함께 고정한다. 입력란에 실제 자료만 채우고 본문·프롬프트·입력 자료·사전 기준 답의 해시를 기록한다. 일반적인 자동 도구의 한계를 모델의 영구적인 한계로 삼지 않으며 DOM·접근성 트리·스크린샷·조작 기록·원본 음성·영상 등 실제 사용한 입력을 구분한다. 파생 전사·프레임 비교를 원본 음성·영상 직접 처리로 설명하지 않는다.

정상·실패·예외·입력 부족 사례를 포함하고 기본적으로 최소 세 개의 독립 세션에서 반복한다. 기준 답과 이전 출력은 테스트 모델에 제공하지 않는다. 같은 세션 안에서 여러 조건을 실행했다면 그 공유 문맥과 독립성 한계를 기록한다. 입력 부족·실행 실패·판단 유보를 충족으로 처리하지 않는다. 판정 일치율뿐 아니라 근거 정확성·누락·오탐·미검토 구간·반복 일관성도 확인한다.

검증 실패로 프롬프트나 평가 입력이 바뀌면 새 버전으로 다시 고정하고 영향을 받는 테스트를 반복한다. 기준 답이 잘못되었다면 모델 출력에 맞추어 조정하지 말고 원출처와 별도 검토로 수정 이유를 내부 기록에 남긴다. 과거 검증 결과를 새 버전의 성능으로 재사용하지 않는다.

## 리뷰와 최종 원고

Sol High는 표준 해석·출처 일치·실험 설계·수치·입력 범위·근거와 결론의 연결을 확인한다. Fable Low는 독자의 이해·문장·구성·도식·과장 여부와 재사용 가능한 프롬프트를 확인한다. 두 리뷰 모두 사실과 근거를 검토하며, 서로의 평가를 보기 전에 독립적으로 제출한다. 점수만으로 통과하지 않는다. 해결되지 않은 문제는 수정하거나 공개 결론의 범위를 제한하고 재검토한다.

공개 글은 충분한 설명 → 글 안의 실습 iframe과 직접 링크 → 실제 프롬프트로 얻은 결과와 해석 → 검증한 최종 프롬프트 → 이전/다음 글로 자연스럽게 전개한다. 독자에게 필요한 검증 범위와 한계는 설명하되 내부 수정 이력·시행착오·제작 도구 홍보를 본문에 넣지 않는다. 완성된 프롬프트는 검증한 범위에서 재사용 가능한 지침을 뜻하며 모든 입력의 완벽성·WCAG 인증을 보장하지 않는다.

리뷰는 정확한 콘텐츠 해시에 묶는다. 리뷰 뒤 본문·프롬프트·요약·도식·핵심 입력이 바뀌면 영향받는 검증과 리뷰를 갱신한다. 과거 Opus High 실행은 그때의 결과로 보존하고 앞으로의 Medium 결과로 다시 표시하지 않는다.

## 네 언어와 공개 확인

기존 한국어 정본 → 검토용 HTML/PDF → Telegram 검토 → 사용자 승인 → 영어·일본어·중국어 간체 완성 절차를 유지한다. 이미 승인된 작업 범위는 재확인을 반복하지 않는다. 번역 본문·프롬프트·도식·대체 텍스트·캡션·실습 UI·언어별 링크를 원문과 대조하고, 번역에 새로운 성과나 주장을 추가하지 않는다. 두 리뷰 모델이 네 언어의 최종 내용과 근거 일치를 검수하며, 같은 역할이라도 집필/번역과 검수는 별도 호출로 진행한다.

공개 승인 해시, SSR 본문, JSON-LD, canonical/hreflang, 초판 공개일과 최종 수정일, 기존 URL, iframe·직접 링크·미디어·자막·키보드·모바일·no-JS, ads.txt와 공통 광고 태그를 확인한다. 저장소의 필요한 콘텐츠·타입·빌드 검사를 수행하고 검토한 변경만 커밋·푸시·배포한다. 운영 URL에서 승인 해시와 실제 동작을 확인한 뒤 공개 완료로 기록한다.

운영 확인 후 @effloow에 영어 스레드를 발표한다. 본문에는 URL을 넣지 않고 마지막 게시물의 별도 자기 답글에 영어 canonical URL만 게시한다. 기존 [발행 후 발표 지침](post-deploy-announcement.md)에 따라 중복 발표를 방지하고 실제 게시물과 링크 영수증을 보존한다.
