## 실행 모델과 기록

모든 제작 단계는 GPT와 Gemini로 수행한다. 실제 모델·공급자·effort·실행일·입출력 해시·출처·도구를 기록한다. GPT는 지정한 Sol 모델·effort를 확인하고, Gemini 집필은 브라우저에서 Neon 선택을 확인한다. 실행에 실패하면 해당 단계를 미완료로 남기며 다른 모델로 조용히 대체하지 않는다. Ollama·Claude 인증 복구를 현재 제작의 선행조건으로 삼지 않는다.

이 배정은 접근성 시리즈의 제작 절차다. 2026-11-20부터 이 대화의 일일 자동화가 제작을 이어간다. Life Manager의 전역 writer/researcher/reviewer 역할이나 다른 프로젝트의 모델 설정을 이 시리즈 때문에 변경하지 않는다. 문서 저장을 자동 파이프라인 구현·모델 실행 완료로 간주하지 않는다.

## 프롬프트와 실제 테스트

개요의 평가 계획 프롬프트와 해당 항목의 평가 프롬프트 원문을 함께 고정한다. 입력란에 실제 자료만 채우고 본문·프롬프트·입력 자료·사전 기준 답의 해시를 기록한다. 일반적인 자동 도구의 한계를 모델의 영구적인 한계로 삼지 않으며 DOM·접근성 트리·스크린샷·조작 기록·원본 음성·영상 등 실제 사용한 입력을 구분한다. 파생 전사·프레임 비교를 원본 음성·영상 직접 처리로 설명하지 않는다.

정상·실패·예외·입력 부족 사례를 포함하고 기본적으로 최소 세 개의 독립 세션에서 반복한다. 기준 답과 이전 출력은 테스트 모델에 제공하지 않는다. 같은 세션 안에서 여러 조건을 실행했다면 그 공유 문맥과 독립성 한계를 기록한다. 입력 부족·실행 실패·판단 유보를 충족으로 처리하지 않는다. 판정 일치율뿐 아니라 근거 정확성·누락·오탐·미검토 구간·반복 일관성도 확인한다.

검증 실패로 프롬프트나 평가 입력이 바뀌면 새 버전으로 다시 고정하고 영향을 받는 테스트를 반복한다. 기준 답이 잘못되었다면 모델 출력에 맞추어 조정하지 말고 원출처와 별도 검토로 수정 이유를 내부 기록에 남긴다. 과거 검증 결과를 새 버전의 성능으로 재사용하지 않는다.

## 리뷰와 최종 원고

GPT와 Gemini가 각각 표준 해석·출처 일치·실험 설계·수치·근거와 결론의 연결, 독자의 이해·문장·구성·도식·프롬프트 재사용성을 교차 확인한다. 두 리뷰 모두 사실과 근거를 검토하며, 서로의 평가를 보기 전에 독립적으로 제출한다. 점수만으로 통과하지 않는다. 해결되지 않은 문제는 수정하거나 공개 결론의 범위를 제한하고 재검토한다.

공개 글은 충분한 설명 → 글 안의 실습 iframe과 직접 링크 → 실제 프롬프트로 얻은 결과와 해석 → 검증한 최종 프롬프트 → 이전/다음 글로 자연스럽게 전개한다. 독자에게 필요한 검증 범위와 한계는 설명하되 내부 수정 이력·시행착오·제작 도구 홍보를 본문에 넣지 않는다. 완성된 프롬프트는 검증한 범위에서 재사용 가능한 지침을 뜻하며 모든 입력의 완벽성·WCAG 인증을 보장하지 않는다.

리뷰는 정확한 콘텐츠 해시에 묶는다. 리뷰 뒤 본문·프롬프트·요약·도식·핵심 입력이 바뀌면 영향받는 검증과 리뷰를 갱신한다. 과거 Opus High 실행은 그때의 결과로 보존하고 앞으로의 Medium 결과로 다시 표시하지 않는다.

## 네 언어와 공개 확인

사용자가 네 언어 집필을 승인한 범위에서 한국어 정본 → 영어·일본어·중국어 간체 집필·검수 → 검토용 HTML/PDF와 네 언어 묶음 → Telegram 검토 → 사용자 공개 승인 순서로 진행한다. 이미 승인된 작업 범위는 재확인을 반복하지 않는다. 번역 본문·프롬프트·도식·대체 텍스트·캡션·실습 UI·언어별 링크를 원문과 대조하고, 번역에 새로운 성과나 주장을 추가하지 않는다. 두 리뷰 모델이 네 언어의 최종 내용과 근거 일치를 검수하며, 같은 역할이라도 집필/번역과 검수는 별도 호출로 진행한다.

공개 승인 해시, SSR 본문, JSON-LD, canonical/hreflang, 초판 공개일과 최종 수정일, 기존 URL, iframe·직접 링크·미디어·자막·키보드·모바일·no-JS, ads.txt와 공통 광고 태그를 확인한다. 저장소의 필요한 콘텐츠·타입·빌드 검사를 수행하고 검토한 변경만 커밋·푸시·배포한다. 운영 URL에서 승인 해시와 실제 동작을 확인한 뒤 공개 완료로 기록한다.

운영 확인 후 @effloow에 영어 스레드를 발표한다. 본문에는 URL을 넣지 않고 마지막 게시물의 별도 자기 답글에 영어 canonical URL만 게시한다. 기존 [발행 후 발표 지침](post-deploy-announcement.md)에 따라 중복 발표를 방지하고 실제 게시물과 링크 영수증을 보존한다.

상세 글 구성은 [article-detail-guidelines.md](article-detail-guidelines.md), 편집 기준은 [editorial-guide.md](editorial-guide.md)를 함께 적용한다.

브라우저의 Neon 실제 선택, 대화 URL, 입출력·해시를 기록한다. 모델 사용 한도·접속·지정 검증 모델의 가용성 문제는 해당 단계의 미완료로 남기고 가능한 조사·실습·자료 준비를 계속한다. 자동화 등록은 모델 실행 성공이나 글 발행 완료의 증거가 아니다. 매일 제작을 목표로 하되 테스트·독립 리뷰를 통과한 정확한 네 언어 원고만 사용자 공개 검토로 넘긴다. 공개 승인이 확인된 콘텐츠만 기존 절차로 발행하며 승인 전 푸시·배포·X 발표·외부 전송은 하지 않는다. 이 대화에서 검토 자료를 안내한다.
