## A. 평가 범위

- 선택한 이용 과정: 학습 페이지에서 무음 안내 영상 M-V와 단계별 텍스트 ALT-V를 통해 복구 코드 생성의 전제 조건, 다섯 단계, 경고, 완료 결과를 이해하는 과정
- 시작 조건: 페이지를 처음 연 상태(수집된 초기 문서 상태)
- 완료 조건: 이용자가 영상 또는 대안 중 하나로 다섯 단계의 정보와 순서를 얻은 상태. 평가 측면에서는 원본과 대안의 비교 증거, 그리고 후보 기준별 증거 수집 계획이 갖춰진 상태
- 포함 범위: M-V 원본 전체(0~19.916667초), M-V와 연결된 ALT-V, 영상과 대안을 담은 본문 영역, 플레이어 컨트롤(계획만)
- 제외 범위: 수집 기록의 제외 항목(플레이어 키보드·자막·다른 기준은 수집 단계에서 제외됨), 외부 또는 실제 사용자 계정, 폼 제출, 실제 복구 코드 생성
- 목표 버전·수준: WCAG 2.2, AA(가정). 첫 질문은 1.2.1, 나머지는 후보로 구분
- 미정인 실행 환경: 브라우저와 버전, 뷰포트 크기, 확대 배율, 키보드·포인터 입력, 화면 낭독기 종류와 버전
- 전체 사이트 평가와의 차이: 이 계획은 한 페이지의 한 이용 과정과 그 안의 미디어 하나만 다룹니다. 결과를 사이트 전체나 다른 페이지의 적합성으로 넓힐 수 없고, WCAG-EM 같은 대표 표본 선정과 전체 페이지 적합성 판단은 하지 않습니다.

## C. 권장 실행 순서

현재 권한은 제공된 텍스트와 PNG 열람뿐입니다. 아래 1~3단계 중 제공 자료만으로 할 수 있는 부분을 제외한 모든 단계는 실행 제안입니다.

1. 상태 복원 준비: 같은 sha256의 MP4와 같은 판본의 페이지 HTML을 확보하고, 테스트 브라우저·뷰포트·확대·보조 기술을 정해 기록합니다. 실제 계정이나 실제 복구 코드는 사용하지 않습니다.
2. 자료 수집(실행 제안): S0과 S1의 DOM 원문, 접근성 트리, 전체 화면 캡처를 수집합니다. `video` 요소의 autoplay·loop·muted·controls 속성과 포스터 이미지를 기록합니다.
3. 1.2.1 원본·대안 비교(제공 자료로 가능): OBS-V의 그룹 5개와 FRAME-1~5를 기준으로 원본 정보 단위(화면 제목, 안내 문구, 버튼, 순서)를 정리하고, ALT-V paragraph 2~6과 단위별로 대조해 E 양식에 기록합니다. 이 단계는 이 계획 문서에서는 수행하지 않았습니다.
4. 규칙 검사(실행 제안): 수집한 DOM으로 페이지 언어, 컨트롤 이름, 목록 구조 같은 규칙 기반 항목을 확인합니다. 같은 기준 안에서도 의미 판단이 필요한 질문(예: 대안이 단계의 의미를 전달하는가)은 별도로 남깁니다.
5. 조작 기록(실행 제안): S4 키보드 조작, S5 화면 낭독기 탐색, S6 확대를 수행하고 조작 순서·초점 위치·출력 원문을 기록합니다. 스크린샷만으로 초점 이동이나 낭독 출력을 확정하지 않습니다.
6. 검토: 각 결과에 증거 ID를 연결하고, 증거가 없는 항목은 '미실행' 또는 '판단 유보'로 남깁니다.
7. 수정 후 재평가: 수정이 있으면 같은 판본 식별자, 같은 환경, 같은 상태에서 3~5단계를 반복하고 이전 결과와 비교합니다.

## D. AI 평가 검증 계획

측정 전이므로 정확도, 비용, 평가 완료를 주장하지 않습니다.

- 사례 구성: 같은 원본 영상에 대해 대안만 바꾼 사례 묶음을 만듭니다.
  - 정상 사례: 모든 단계·경고·부정어가 원본과 같은 의미인 대안
  - 문제 사례: 부정어를 반대로 바꾼 대안, 중간 단계를 뺀 대안, 대안이 아예 없는 페이지
  - 경계 사례: 텍스트 대신 음성 대안만 있는 경우, 기존 텍스트의 미디어 대안이라고 표시한 경우(텍스트가 완전한 경우와 요약뿐인 경우), 원본 일부 구간만 관찰된 경우, 원본 파일이 손상된 경우, 오디오 트랙이 실제로 없는 경우와 플레이어에서만 음소거된 경우
- 기준 답의 근거 검토: 사례마다 원본 제작 문구와 독립 관찰 기록(프레임 그룹, ASR)을 함께 보관합니다. 평가자 두 명 이상이 WCAG 2.2의 1.2.1 원문과 Understanding 문서를 근거로 기준 답과 이유를 따로 적고, 차이가 나면 근거 문장을 놓고 합의 과정을 기록합니다.
- 결과 분류: AI 결과를 기준 답과 비교해 오탐(문제가 없는데 미충족), 누락(문제가 있는데 충족), 판단 유보, 실행 실패(자료를 읽지 못함·출력 형식 오류)를 따로 셉니다. 판단 유보가 정당한 사례(증거 부족)와 부당한 사례(증거가 충분한데 유보)를 구분합니다.
- 반복 일관성: 같은 입력을 같은 모델·설정으로 여러 번 실행해 판정·근거·인용 구간이 바뀌는지 기록합니다. 실행 횟수와 설정은 측정 전에 정합니다.
- 재현 노력 기록: 사례마다 입력 준비 시간, 수집 도구 실행 여부, 사람이 확인해야 했던 지점, 재실행에 필요한 파일과 해시를 적습니다.

## E. 후속 결과 기록 양식

| 상태·환경 | 기준·검사 질문 | 실행 상태 | 판정 | 증거 ID와 위치 | 사용자 영향 | 가정·반대 증거 | 수정 제안 | 재평가 조건 |
|---|---|---|---|---|---|---|---|---|
| 예: S2, 원본 sha256 `72f45aef…`, 파생 프레임 기록 | 예: 1.2.1, 원본 3/5 화면의 경고가 대안에 같은 의미로 있는가 | 미실행 / 실행됨 / 실패 / 차단 | 미평가 / 충족 / 미충족 / 해당 없음 / 판단 유보 | 예: OBS-V 그룹 3, FRAME-3, ALT-V paragraph 4 | | | | |

- 실행 상태: '미실행'은 시도하지 않음, '실행됨'은 수집·검사를 마침, '실패'는 도구 오류 등으로 끝내지 못함, '차단'은 권한·환경 때문에 시작하지 못함입니다.
- 판정: '미평가'는 판정하지 않은 상태이고, '판단 유보'는 평가를 시도했지만 증거나 해석이 부족한 상태입니다. '해당 없음'에는 적용하지 않는 이유를 반드시 적습니다(예: 오디오 트랙이 없음을 확인한 증거 ID).
- 위 예시 행은 양식 설명이며 실제 결과가 아닙니다.
