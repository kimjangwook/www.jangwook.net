# P-LAB 평가 계획: 복구 코드 학습 실습 페이지의 영상 가이드와 대안

이 문서는 평가 계획입니다. 접근성 판정(충족·미충족 등)은 내리지 않았습니다. 제공된 텍스트 기록을 읽었고 PNG 5장(FRAME-1~5)은 Read로 직접 열었습니다. 페이지 URL을 방문하거나 영상을 재생하지 않았고, 키보드·화면 낭독기 조작도 하지 않았습니다.

## 0. 입력 구분: 제공된 사실, 가정, 미확인

## A. 평가 범위

- **선택한 이용 과정**: 이용자가 K63 실습 페이지에서 영상 가이드(M-V)와 그 텍스트 대안(ALT-V)을 통해 복구 코드 생성의 전제 조건·절차·경고·완료 결과를 이해하는 읽기/재생 과정.
- **시작 조건**: 페이지 초기 문서 상태에 진입함(PAGE-K63에 기록된 상태).
- **완료 조건(이용자 관점)**: 이용자가 영상 또는 대안으로 다섯 단계의 조건·절차·경고·결과를 모두 알 수 있음.
- **완료 조건(이번 작업)**: 위 과정의 평가 범위와 원본·대안 비교를 위한 증거 수집 계획을 확정함.
- **포함**: M-V 원본 0~19.916667초 전체, ALT-V 전체 문단, M-V와 ALT-V의 연결 관계, 초기 상태의 대상 목록.
- **제외(입력에 명시됨)**: 플레이어 키보드 조작, 자막, 1.2.1 이외의 기준(후보로만 구분), 외부·실제 사용자 계정.
- **목표 버전·수준**: WCAG 2.2, A·AA(AA는 A를 포함). 첫 질문은 1.2.1(A). 다른 기준은 아래 B표에서 후보로만 둡니다. 4.1.1 Parsing은 넣지 않습니다.
- **미정인 실행 환경**: 브라우저 종류·버전(수집기는 Chromium으로만 기록), 화면 크기, 확대 배율, 입력 방식(마우스·키보드·터치), 보조 기술 종류와 버전.
- **전체 사이트 평가와의 차이**: 이 계획은 로컬 fixture 페이지 한 곳의 초기 상태와 미디어 1개만 다룹니다. 결과를 jangwook.net 전체, 다른 글, 다른 상태로 넓혀 적합성을 주장할 수 없습니다. WCAG 적합성 주장에 필요한 전체 페이지·전체 과정 평가가 아닙니다.

## C. 권장 실행 순서

현재 권한은 제공 자료 열람뿐이므로, 아래에서 수집·조작이 필요한 단계는 실행 제안으로만 남깁니다.

1. **상태 복원(제안)**: 같은 fixture 페이지를 같은 판본으로 열 수 있는 환경을 준비하고, 브라우저·뷰포트·확대·입력 방식을 기록합니다. 실제 계정과 폼 제출은 쓰지 않습니다.
2. **자료 수집(제안)**: S0의 DOM과 접근성 트리, S2의 대안 전문(paragraph 1 포함)과 연결 방식, S6의 ffprobe 원시 출력을 수집합니다. 각 자료에 ID, 수집 시각, 상태를 붙입니다.
3. **원본 처리 확인(제공 자료로 가능)**: OBS-V의 그룹 경계가 0~19.916667초를 빈틈없이 덮는지, 대표 이미지 5장이 모두 열람됐는지 확인합니다. 이번 작업에서 PNG 5장은 열람했습니다.
4. **규칙 검사와 의미 평가**: 목록·트랙 구성처럼 규칙으로 확인할 수 있는 질문과, 대안이 원본과 같은 정보를 주는지 같은 의미 질문을 같은 1.2.1 안에서 나눠 기록합니다. 기준 단위로 방법을 고정하지 않고 검사 질문마다 방법과 증거를 정합니다.
5. **조작 기록 확인(제안)**: S4·S5는 키보드 조작 기록, 초점 기록, 화면 낭독기 출력이 수집된 뒤에만 검토합니다. 이번 1.2.1 질문과 섞지 않습니다.
6. **검토와 재평가**: 대조 결과에 사람 검토를 붙이고, 수정이 있으면 같은 원본 sha256, 같은 대안 판본, 같은 환경에서 재평가합니다.

## D. AI 평가 검증 계획

측정 전이므로 정확도, 비용, 평가 완료를 주장하지 않습니다.

- **사례 구성**: 같은 원본 영상에 대해 대안만 바꾼 변형을 준비합니다.
  - 정상: 모든 단계가 동등한 텍스트 대안, 또는 동등한 음성 대안.
  - 문제: 단계 누락, 부정어 반전, 경고 문장 삭제, 대안 없음, 요약에 불과한 텍스트를 "완전한 단계"라고 표시한 예외 주장.
  - 경계: 원본 일부 구간만 관찰된 경우, 원본 파일 손상으로 디코딩 실패, 처리 기록과 프레임 그룹 경계가 다른 경우, 정당한 예외(기존 텍스트와 정보가 같고 명확히 표시됨).
- **기준 답 근거 검토**: 기준 답마다 원본의 시간 구간, 대안의 문장 위치, 적용한 1.2.1 문구를 연결합니다. 제작 대본이 아니라 원본에서 독립적으로 관찰한 기록을 기준 답의 근거로 삼고, 두 명 이상이 따로 검토해 불일치를 기록합니다.
- **결과 분류 기록**: 각 실행을 오탐(기준 답이 충족인데 미충족), 누락(기준 답이 미충족인데 충족), 판단 유보, 실행 실패(입력 미읽기, 도구 오류, 출력 파싱 불가)로 나눠 기록합니다. 판단 유보와 실행 실패는 정확도 계산에서 따로 셉니다.
- **반복 일관성**: 같은 입력을 같은 모델·설정으로 여러 번 실행해 판정과 근거 위치가 같은지 기록합니다. 실행 횟수는 측정 계획 단계에서 정하고 미리 값을 가정하지 않습니다.
- **재현 노력**: 사람이 결과를 확인하는 데 걸린 시간, 추가로 연 자료 수, 근거 위치가 원본에서 바로 찾아졌는지를 기록합니다.

## E. 후속 결과 기록 양식

| 상태·환경 | 기준·검사 질문 | 실행 상태 | 판정 | 증거 ID와 위치 | 사용자 영향 | 가정·반대 증거 | 수정 제안 | 재평가 조건 |
|---|---|---|---|---|---|---|---|---|
| 예: S1+S2, 초기 문서, 환경 미정 | 1.2.1 / M-V 원본 7.9~11.9초의 경고가 대안에 동등하게 있는가 | 미실행 | 미평가 | (수집 후 기재) | (판정 후 기재) | (기재) | (기재) | 같은 sha256 원본, 같은 대안 판본, 같은 환경 |

- **실행 상태**: 미실행 / 실행됨 / 실패 / 차단.
- **판정**: 미평가 / 충족 / 미충족 / 해당 없음 / 판단 유보.
- **미평가**는 판정을 시도하지 않은 상태이고, **판단 유보**는 평가를 시도했지만 증거나 해석이 부족한 상태입니다.
- **해당 없음**에는 적용하지 않는 이유(대상 없음, 검증된 예외, 범위 밖)를 적습니다.
- 위 예시 행은 양식 설명용이며 실제 결과가 아닙니다.

## F. 바로 준비할 자료 (우선순위순)

1. **S0 DOM 또는 HTML 원문**: 목록 확정과 대안 연결 방식 확인에 필요합니다. 질문: 영상과 대안은 어떤 마크업으로 연결되어 있습니까?
2. **ALT-V paragraph 1과 대안 주변 본문**: 대안 전문을 확보해야 대조할 수 있습니다.
3. **ffprobe 원시 출력**: 영상 전용 분류(음성 트랙 없음)를 관찰 문구가 아닌 원시 기록으로 확인합니다.
4. **FRAME PNG와 OBS-V 그룹의 대응 기록**: 제공 PNG 경로와 OBS-V의 `observed-N.png` 경로가 다르므로, 같은 이미지라는 근거(파일 해시 등)를 받아 둡니다.
5. **평가 환경 확정**: 브라우저 버전, 화면 크기, 확대, 입력 방식, 보조 기술을 정합니다.
6. **S4·S5용 조작 기록 수집 여부 결정**: 범위 밖으로 둘지, 다음 단계에서 수집할지 정합니다.

자료를 제출할 때 개인정보, 인증 정보, 실제 복구 코드가 들어가지 않도록 하십시오. 이 fixture는 실제 코드를 표시하지 않는다고 화면에 적혀 있지만, 실제 서비스 화면을 추가로 수집할 때는 해당 값을 가린 뒤 제출해야 합니다.
