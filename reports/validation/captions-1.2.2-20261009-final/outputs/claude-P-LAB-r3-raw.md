# P-LAB — 평가 범위·증거 수집 계획

이 문서는 계획입니다. 페이지 방문, 재생, 키보드 조작, 화면 낭독기 실행은 하지 않았고 접근성 판정도 내리지 않습니다. 아래에서 "제공됨"은 입력 JSON에 실제로 들어 있는 자료, "가정"은 평가자가 둔 전제, "미확인"은 아직 수집·관찰하지 않은 내용입니다. 입력이 참조하는 DISPLAY-C01-1~3 PNG는 이 조건에 첨부되지 않았으므로 내용을 사용하지 않았습니다.

## C. 권장 실행 순서

1. **상태 복원**: 제공된 기록과 같은 Chromium·URL·자막 mode에서 S0을 재현(실행 제안. 현재 권한 밖).
2. **자료 수집**: 전체 DOM·접근성 트리·head 정보 → 키보드 조작 로그(S1·S2·S5·S6) → 각 큐 활성 시점 표시 캡처 → 첨부되지 않은 DISPLAY-C01 PNG 확보.
3. **규칙 검사와 의미 평가**: 같은 기준 안에서도 검사 질문별로 방법을 고름. 예) 1.2.2는 트랙 존재 확인(메타데이터)과 원본-자막 의미 대응(전사 대조)과 표시 가림 확인(화면)을 모두 거침. 4.1.2는 접근성 트리 속성 확인과 실제 낭독 출력 확인을 구분.
4. **조작 기록 확인**: 마우스 기록뿐인 현재 상태를 키보드·보조 기술 기록으로 보완. 화면 낭독 출력은 실제 낭독 로그로만 확정.
5. **검토**: 판정마다 증거 ID와 반대 증거를 붙이고 다른 평가자가 재검토.
6. **수정 후 재평가**: 수정 항목별 재평가 조건(E표)을 기준으로 같은 상태를 다시 수집.

도구가 없거나 허용 범위를 벗어난 단계(1, 2의 수집, 4)는 이번 실행에서 수행하지 않고 제안으로만 남깁니다.

## D. AI 평가 검증 계획

- **사례 구성**: 같은 원본(M1)에 대해 정상(동등 자막), 문제(부정 반전, 소리 누락, 화자 누락, 시간 지연, 자막 없음), 경계(의미 보존 축약, 개방 자막, 매체 대안 예외 성립·불성립, 원본 부분 처리, 매체 로드 실패, 매체 없는 페이지)를 각각 한 변수만 바꿔 만듭니다.
- **기준 답 근거 검토**: 각 사례의 기준 답에 원본 출처(전사·출처 상관·측정)와 WCAG 원문 조항을 연결하고, 작성자가 아닌 검토자가 근거만 보고 같은 답에 도달하는지 확인합니다. 의견이 갈리면 기준 답을 "판단 유보 허용"으로 표시합니다.
- **오류 분류**: 오탐(위반 없는데 미충족), 누락(위반 있는데 충족), 판단 유보(증거 부족을 정확히 지적했는지 별도 채점), 실행 실패(도구·수집 오류를 판정으로 바꿨는지)를 따로 셉니다.
- **반복 일관성**: 같은 입력을 여러 번 독립 실행해 판정·근거 ID가 같은지 기록하고, 실행마다 모델·노력 수준·입력 해시·출력 해시를 남깁니다.
- **재현 노력 기록**: 사람 검토 시간, 추가로 요청한 자료 수, 재실행 횟수를 사례별로 기록합니다.
- 측정 전이므로 정확도·비용·평가 완료를 주장하지 않습니다.

## F. 바로 준비할 자료(우선순위)

1. 이 조건에 첨부되지 않은 표시 화면 DISPLAY-C01-1~3, 또는 각 큐 활성 시점의 화면 캡처.
2. 전체 페이지 HTML과 접근성 트리(head의 title·lang 포함, 하단 내비게이션 제외 표시).
3. 키보드만으로 플레이어를 조작한 로그(재생·정지·탐색·자막 메뉴·전체화면, 초점 순서).
4. 원본 화면 문구와 음성 대응표(1.2.3 검토용). 화면에만 있는 정보가 음성이나 대안으로 전달되는지 확인.
5. 사용할 보조 기술과 버전, 브라우저 버전, 뷰포트·확대 설정.
6. 질문: 자동 재생 여부와 3초 초과 소리가 있는지, 페이지에 입력 폼이 있는지, 범위에서 제외한 하단 내비게이션 외에 반복 블록이 있는지.

자료를 보낼 때 실제 계정 정보, 복구 코드, 인증 토큰, 개인정보가 들어간 캡처나 로그는 제출하지 말고 가리거나 테스트 값으로 바꿔 주세요.
