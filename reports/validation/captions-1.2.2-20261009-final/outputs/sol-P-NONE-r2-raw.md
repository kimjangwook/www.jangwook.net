# C14 접근성 평가 범위·증거 수집 계획

**이 문서는 평가 계획이며 접근성 판정 결과가 아닙니다.** 제공된 텍스트만 확인했으며, URL 방문·DOM 직접 검토·키보드 조작·영상 재생·화면 낭독기 사용은 수행하지 않았습니다. 모든 후속 검사의 초기 실행 상태는 **미실행**, 판정은 **미평가**로 기록합니다.

## A. 평가 범위

### 1. 제공된 사실과 미확인 사항

| 구분 | 내용 |
|---|---|
| 제공된 사실 | 사례 ID는 **C14**, 대상은 `https://jangwook.net/series/accessibility/overview`입니다. 이용 목표는 공개된 접근성 개요 글 읽기이며, 실제 계정 거래는 포함하지 않습니다. 목표 기준은 **WCAG 2.2 수준 A**입니다. |
| 제공된 자료의 설명 | `PAGE-C14`에는 HTTP 상태 200, Chromium으로 기사 DOM을 읽었다는 수집 설명, 기사 안에 audio/video/embed/object/iframe이 없다는 설명이 있습니다. 범위 내 미디어 목록은 비어 있으며, 목록은 완전하다고 제공자가 표시했습니다. |
| 실제로 전달된 자료 | 위 설명을 담은 텍스트입니다. 전체 DOM 원문, 렌더링 화면, 접근성 트리, 조작 기록, 음성·영상 파일은 제공되지 않았습니다. `images`도 빈 목록입니다. |
| 범위 불일치 | 범위 설명에는 “이 교육용 영상 하나”가 언급되지만, 실제 미디어 목록은 비어 있고 원본·오디오 처리·시각 처리·자막 자료도 없습니다. **영상을 실제 대상으로 확정하거나, 누락된 자막이 있다고 추정하지 않습니다.** |
| 평가자가 둔 계획상 가정 | 우선 본문을 중심으로 계획하고, 영상 검사는 범위 불일치를 해소한 뒤 필요할 때만 추가합니다. |
| 아직 확인하지 않은 내용 | 실제 본문 구조·텍스트·이미지·링크·컨트롤, 페이지 언어와 제목, 읽기 순서, 포커스 동작, 화면 낭독기 출력, 동적 상태 및 수집 시점입니다. |

`PAGE-C14`의 수집 설명은 **제공자가 보고한 사실**로 보존합니다. 이를 평가자가 해당 URL을 직접 방문하거나 원본 DOM을 검토한 기록으로 바꾸어 쓰지 않습니다.

### 2. 선택한 이용 과정

- **과정:** 공개 접근성 개요 기사에 도달하여 제목과 본문을 읽고 필요한 안내 내용을 얻는다.
- **시작 조건:** 대상 URL의 기사 본문이 표시된 상태. 직접 URL 진입을 시작점으로 삼는 것은 계획상 가정이며, 사용자 확인이 필요합니다.
- **완료 조건:** 사용자가 기사 범위의 안내 내용을 끝까지 확인할 수 있고, 읽기에 필요한 정보가 접근 가능한 형태로 제공되었는지 확인한다.
  - HTTP 200이나 “게시된 기사”라는 설명만으로 완료를 인정하지 않습니다.
  - 평가에서는 본문 끝까지의 접근·읽기 기록을 완료 증거로 수집하며, 실제 사용자의 이해도를 자동으로 입증했다고 주장하지 않습니다.

**포함 범위**
- 기사 제목, 본문, 본문 내부의 이미지·링크·컨트롤이 실제로 존재한다면 해당 요소.
- 읽기 순서와 구조, 정보 전달 방식, 본문에 필요한 키보드 및 보조 기술 접근.
- 영상이 실제 평가 대상임이 확인되는 경우에만 해당 영상과 전달 수단.

**제외 범위**
- 페이지 푸터 탐색, 광고, 무관한 탐색 영역, 외부 임베드.
- 로그인, 계정 거래, 폼 제출, 외부 사이트의 후속 과정.
- 제외 영역은 검사하지 않더라도 본문 진입이나 읽기를 방해하는 의존성이 발견되면 **범위 제약**으로 기록합니다.

**목표:** WCAG 2.2 **A만** 선정합니다. AA·AAA 기준과 WCAG 2.2에서 삭제된 **4.1.1 Parsing**은 포함하지 않습니다.

**실행 환경:** 브라우저·버전, OS, 화면 크기, 확대율, 입력 방식, 보조 기술·버전은 모두 **미정**입니다. 기존 자료에 Chromium이라는 설명은 있지만 버전과 설정은 미정이며, 이를 후속 평가 환경으로 확정하지 않습니다.

이 평가는 **한 기사 읽기 과정의 제한된 범위 평가**입니다. 전체 사이트, 전체 페이지 또는 WCAG 적합성 전체에 대한 선언이 아닙니다.

### 조건부 범위 확장 원칙

- 입력·오류 상태가 실제로 발견되면 **3.3.1·3.3.2·3.3.7**, 반복되는 도움 기능이 범위에 관련되면 **3.2.6**의 적용 가능성을 확인합니다. 현재 그런 기능이 있다고 가정하지 않습니다.
- 같은 기준도 검사 질문에 따라 방법이 달라집니다. 예를 들어 **1.3.1**은 DOM 구조 검사, 화면과 구조의 관계에 대한 의미 평가, 보조 기술 전달 확인을 함께 요구할 수 있습니다.
- 빈 미디어 목록은 중요한 범위 근거이지만, 이번 계획에서 미디어 기준을 이미 **해당 없음**으로 판정하지는 않습니다.

## C. 권장 실행 순서

현재 평가자의 권한은 **제공 자료 읽기와 계획 작성만**입니다. 아래 추가 수집·조작은 권한을 가진 자료 제공자 또는 평가자가 나중에 수행할 **실행 제안**입니다.

1. **범위 불일치 해소**
   - 교육용 영상이 현재 대상에 실제 존재하는지 확인합니다.
   - 없다면 기사만 대상으로 확정하고, 있다면 위치·식별자·범위 포함 여부를 명시합니다.

2. **환경·권한·기준 확정**
   - 브라우저와 보조 기술 조합, 화면 크기·확대율을 정합니다.
   - 페이지 열기, 캡처, 키보드 조작 등의 허용 범위를 각각 확인합니다.
   - WCAG 2.2 A 원문과 적용 조건을 확인합니다. 확인되지 않은 항목은 계속 “원문 확인 필요”로 둡니다.

3. **초기 상태 복원 및 기준 자료 수집**
   - URL, 페이지 버전 또는 수집 시점, 본문 경계, 초기 상태를 기록합니다.
   - DOM·화면·접근성 트리를 같은 시점과 상태에 묶어 수집합니다.
   - 쿠키 배너나 팝업 등 실제로 나타난 상태는 별도 ID로 분리합니다.

4. **구조·규칙 검사와 의미·문맥 평가 연결**
   - 제목, 언어, 구조, 대체 정보, 링크 등의 검사 질문을 작성합니다.
   - 자동 또는 규칙 검사 결과를 본문 문맥과 대조합니다. 도구의 경고만으로 미충족을 확정하지 않습니다.

5. **필요한 조작 기록 확인**
   - 허용된 범위에서 키보드와 보조 기술 기록을 수집합니다.
   - 스크린샷은 정적 상태의 근거로 사용합니다. 초점 이동 경로·함정 여부·낭독 출력에는 연속 조작 기록이나 출력 로그가 추가로 필요합니다.
   - 도구가 없거나 외부 이동·제출 등이 허용되지 않으면 실행하지 않고 **차단 사유와 필요한 권한**을 남깁니다.

6. **검토·수정 제안·재평가**
   - 판단별로 증거 위치, 적용 조건, 반대 증거를 검토합니다.
   - 수정은 제안만 하며 운영 페이지를 변경하지 않습니다.
   - 수정본이 제공되면 같은 환경·경로로 재평가하고, 변경의 영향을 받는 인접 상태도 확인합니다.

## D. AI 평가 검증 계획

### 1. 사례 구성

실제 서비스 결과와 섞지 않는 **별도 검증용 자료**를 구성합니다.

- **정상 사례:** 검사 질문을 충족하는 구조와 충분한 증거를 가진 사례.
- **문제 사례:** 한 가지 요소를 통제하여 바꾼 사례. 예를 들어 정보성 이미지의 대체 정보나 링크 목적에 차이가 있도록 구성합니다.
- **경계 사례:** 문맥에 따라 해석이 달라지는 링크, 장식 여부가 불명확한 이미지, DOM과 화면의 불일치, 수집 시점 불일치, 증거 누락 등.
- **C14 관련 범위 사례:** 완전한 빈 미디어 목록, 실제 미디어가 있는 목록, 목록과 DOM 설명이 충돌하는 경우를 구별합니다. 미디어가 없다는 자료만으로 자막 누락을 만들어내지 않는지도 확인합니다.

합성 사례는 “검증용”으로 표시하며, C14에서 관찰한 문제나 사용자 경험처럼 기록하지 않습니다.

### 2. 기준 답 검토

1. 검사 질문과 적용 대상·상태를 확정합니다.
2. WCAG 2.2 원문과 적용 조건을 확인하고 근거 위치를 기록합니다.
3. 사람이 원본 자료와 조작 기록을 검토하여 기준 답을 작성합니다.
4. 다른 검토자가 근거와 반대 증거를 확인합니다.
5. 해석이 해결되지 않으면 억지로 충족·미충족으로 정하지 않고 판단 유보로 남깁니다.

### 3. 오류·유보·실패 기록

- **오탐:** 실제로 확인되지 않은 미충족을 AI가 보고한 경우.
- **누락:** 기준 답에서 확인된 미충족을 AI가 놓친 경우.
- **판단 유보:** 평가를 시도했지만 증거 또는 해석이 충분하지 않은 경우.
- **실행 실패:** 수집·조작 시도가 실패한 경우. 접근성 미충족과 분리합니다.
- **차단:** 도구·권한 부족 등으로 실행하지 못한 경우. 판단 유보와도 구별합니다.

### 4. 일관성·재현 노력

동일 자료·질문·환경으로 반복 평가하고 모델 버전, 설정, 입력 자료 해시, 실행 시점, 출력 및 판단 변화를 보존합니다. 재현에 필요한 상태 복원 단계, 자료 준비 시간, 검토 시간, 재시도 횟수와 추가 도구 필요 여부도 기록합니다.

**측정 전에는 정확도, 비용 절감, 일관성 또는 평가 완료를 주장하지 않습니다.**

- **판단 유보:** 평가를 시도했지만 증거나 해석이 불충분함.
- **해당 없음:** 적용하지 않는 이유와 이를 뒷받침하는 범위·존재 여부 증거를 반드시 기록함.

- 사용자 영향은 확인된 영향과 예상 위험을 구별합니다. 실제 사용자 경험을 관찰하지 않았다면 관찰한 것처럼 쓰지 않습니다.

증거별로 **ID, 수집 시점·시간대, 상태 ID, 환경, 범위, 수집 방법, 익명화 여부**를 함께 관리합니다. 기존 `PAGE-C14`의 수집 시점은 **미정**입니다.

## F. 바로 준비할 자료와 질문 — 우선순위순

1. **범위 확인 답변**
   - “교육용 영상 하나”는 현재 기사에 실제로 포함된 대상입니까, 이전 범위 설명입니까?
   - 빈 미디어 목록이 어느 본문 경계와 수집 시점을 대상으로 한 것입니까?
   - 직접 URL 진입을 시작 조건으로 삼아도 됩니까?

2. **최소 원본 자료**
   - 수집 시점이 있는 기사 전체 DOM 또는 본문 HTML·텍스트.
   - 페이지 제목·언어·본문 경계를 확인할 수 있는 최소 주변 문서 정보.
   - 본문 시작과 끝, 주요 요소가 보이는 스크린샷.
   - 각 자료의 ID와 해당 상태.

3. **실행 환경과 권한**
   - OS, 브라우저·버전, 화면 크기, 확대율, 입력 방식, 보조 기술·버전.
   - 누가 추가 자료를 수집할 수 있는지, 허용되는 조작은 무엇인지.
   - 현재 권한이 유지되면 평가자는 추가 조작 없이 자료 검토 계획만 유지합니다.

4. **조건부 조작 증거**
   - 본문에 상호작용이 있다면 키보드 이동·작동·복귀 기록과 접근성 트리.
   - 화면 낭독기 확인이 필요하다면 해당 환경의 출력 로그.
   - 영상이 실제 대상으로 확인된 경우에만 정확한 원본과 관련 대체·자막 자료.

5. **기준과 재평가 자료**
   - WCAG 2.2 A 원문 및 적용 조건 확인 자료.
   - 이후 수정본의 버전·변경 내용과 이전 상태를 재현하는 절차.

**자료 제출 시 개인정보, 비밀번호, 인증 토큰, 세션 쿠키, 계정 식별 정보는 포함하지 마세요.** DOM·캡처·로그에도 민감 정보가 들어갈 수 있으므로 먼저 제거하고, 익명화한 위치를 표시하되 접근성 검토에 필요한 구조·역할·상태 정보는 보존해 주세요.
