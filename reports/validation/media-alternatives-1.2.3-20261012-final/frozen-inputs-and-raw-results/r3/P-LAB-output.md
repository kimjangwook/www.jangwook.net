# SC 1.2.3 평가 계획 — 복구 코드 발급 안내 영상과 대안 비교 페이지

> 이 문서는 계획입니다. 대상 URL을 열거나 영상을 재생·청취하거나 페이지를 조작하지 않았습니다. 원본 내용 자료(DOM, ASR, 소리 분석, 디코드 PNG)는 아직 첨부되지 않았으므로 접근성 판정은 하나도 내리지 않았습니다. 현재 근거는 자료 ID `PLAN-CONTEXT`(범위 기획용 설명) 하나뿐입니다.

## 사실·가정·미확인 구분

| 구분 | 내용 |
|---|---|
| 제공된 사실 (PLAN-CONTEXT) | 교육용 복구 코드 발급 안내 영상과 대안 비교 페이지. 사전녹화 31초. 시연 단계: 보안 설정 → 실패 → 재인증 → 발급 → 완료. 녹화 시연이며 실제 계정 연결 없음. 목표 WCAG 2.2 수준 A 중 이번 범위는 1.2.3. 환경 Chromium/WebKit, 한국어, 1280px. URL `http://127.0.0.1:8826/labs/accessibility/media-alternatives-1-2-3/ko/v01.html`. 후속 평가에 전체 DOM 조작 관찰, 독립 ASR, 소리 분석, 실제 디코드 PNG, 범위 자료 제공 예정. |
| 평가자 가정 | ① 페이지에 동기화된 미디어(영상+음성) 1개가 있고 그 영상에 대한 대안(음성 해설·텍스트 대안 등)이 1개 이상 있다. ② "대안 비교"는 대안 버전이 여럿일 수 있음을 뜻한다(v01은 그중 하나로 추정). ③ 31초 안의 시각 정보 중 일부는 음성으로 전달되지 않는다(1.2.3 적용 여부를 가르는 핵심이므로 확인 필요). |
| 미확인 | 영상에 음성 트랙이 실제 존재하는지(없으면 1.2.3이 아니라 1.2.1 대상), 대안의 종류와 위치, 대안이 "텍스트 대안으로서의 미디어"로 표시된 예외 상황인지, 화면 텍스트(코드 값·오류 문구·버튼명) 내용, 브라우저 버전·확대 설정·보조 기술, 대안이 WebKit/Chromium에서 동일하게 노출되는지. |

## A. 평가 범위

- **이용 과정:** 화면을 보지 않는 이용자가 31초 안내 영상의 정보를 대안(음성 해설 또는 시간 기반 미디어 대안)만으로 이해하는 과정.
- **시작 조건:** 페이지 로드 후 영상과 대안이 초기 상태로 노출된 시점.
- **완료 조건:** 원본의 시각·청각 정보 단위 목록과 대안 내용을 1:1로 대응시키고, 누락·불일치·순서 차이를 기록할 수 있는 증거 계획이 확정된 상태.
- **포함:** 영상 내 시각 전용 정보(화면 텍스트, 상태 변화, 오류 표시, 발급 코드 표시 방식, 완료 표시), 원본 음성 내용, 대안의 존재·종류·위치·연결 방식(영상과 프로그램적으로 연결되거나 가까이 있는지), 대안의 정보 동등성.
- **제외(후속 검토):** 1.2.1, 1.2.2(자막), 1.2.5(AA, 이번 목표 수준 밖), 1.4.2, 2.1.1, 2.2.2, 4.1.2 등 플레이어 조작·자막·색상 관련 기준. 4.1.1 Parsing은 WCAG 2.2에서 삭제되어 대상 아님. 실제 계정 발급 흐름은 존재하지 않으므로 제외.
- **목표 버전·수준:** WCAG 2.2, 수준 A, 기준 1.2.3 단일. 1.2.3 원문(사전녹화 동기화 미디어의 영상에 대해 시간 기반 미디어 대안 또는 음성 해설 제공, 단 미디어가 텍스트의 대안이고 그렇게 명확히 표시된 경우 예외)은 평가 시점에 W3C 원문과 Understanding 문서로 재확인 필요.
- **미정 실행 환경:** 브라우저 버전, 확대 배율, 입력 방식, 화면 낭독기 종류(현 도구 구성상 보조 기술 실행 불가).
- **전체 사이트 평가와의 차이:** 한 페이지·한 미디어·한 기준만 다룹니다. 이 계획의 결과로 페이지나 사이트 전체의 WCAG 적합성을 주장할 수 없습니다(적합성 주장에는 전체 페이지·전체 과정·모든 A 기준이 필요).

## B. 상태와 증거 계획표

모든 행은 **계획한 상태**입니다. 실제 관찰한 상태는 0개입니다.

| 상태 ID | 진입·종료 조건 | 사용자 작업 | 후보 WCAG 기준과 적용 이유 | 필요한 증거·도구 | 이미 제공된 자료 | 추가 수집 | 완료 확인 방법 |
|---|---|---|---|---|---|---|---|
| S0 페이지 초기 | 로드 직후 / 재생 전 | 영상과 대안 위치 파악 | 1.2.3: 대안이 존재하고 찾을 수 있는지, 예외 표시가 있는지 | 전체 DOM, 접근성 트리, 초기 PNG | 없음(PLAN-CONTEXT만) | DOM 스냅숏(`<video>`, `<track kind=descriptions>`, 대안 링크·텍스트, aria 연결) | 대안 요소 식별자와 영상과의 관계가 기록됨 |
| S1 보안 설정 구간 | 영상 시작 ~ 실패 표시 전 (시간 범위 미정) | 무엇을 설정하는지 이해 | 1.2.3: 화면 전용 설정 정보가 대안에 있는지 | 디코드 프레임 PNG, ASR, 대안 텍스트 해당 문단 | 없음 | 구간 타임코드, 프레임 PNG, ASR 구간 | 정보 단위 목록과 대안 대응 표 작성 |
| S2 실패 | 실패 표시 시작~종료 | 실패 원인 이해 | 1.2.3: 오류 문구·시각 표시(색, 아이콘)가 음성이나 대안에 있는지 | 프레임 PNG, 소리 분석(경고음 등 비언어 음향), ASR | 없음 | 오류 화면 프레임, 경고음 유무 | 오류 의미가 대안에 전달되는지 대응 기록 |
| S3 재인증 | 재인증 단계 구간 | 재인증 방법 이해 | 1.2.3: 단계 전환이 시각으로만 표시되는지 | 프레임 PNG, ASR | 없음 | 전환 시점 타임코드 | 동일 |
| S4 발급 | 코드 표시 구간 | 코드 저장 필요성·형식 이해 | 1.2.3: 화면에 보이는 코드·지시 문구가 대안에 있는지(교육용 가짜 코드 가정) | 프레임 PNG, 대안 텍스트 | 없음 | 코드 표시 프레임(실제 비밀 아님 확인) | 동일 |
| S5 완료 | 완료 표시 ~ 31초 | 완료 여부 인지 | 1.2.3: 완료 상태 시각 표시의 대안 전달 | 프레임 PNG, ASR, 소리 분석 | 없음 | 종료 프레임 | 동일 |
| S6 대안 소비 | 대안 시작~끝 | 대안만으로 정보 획득 | 1.2.3: 대안의 동등성·순서·누락 | 대안 텍스트 원문 또는 해설 음성 ASR | 없음 | 대안 전문 | 원본 정보 단위 전부에 대응/누락 표시 |
| S7 대안 비교 | 비교 대상 버전 각각 | 버전 간 차이 확인 | 1.2.3: 버전별로 충족 여부가 다를 수 있음 | 버전별 DOM·대안 | 없음 | 비교 대상 목록 | 버전별 대응표 완성 |

주의: 스크린샷만으로는 대안이 화면 낭독기에 어떻게 읽히는지, 해설 트랙이 실제 재생되는지 확정할 수 없습니다. 접근성 트리와 조작 기록(재생·해설 전환)이 함께 필요합니다. 같은 1.2.3 안에서도 "대안이 존재하는가"는 DOM 규칙 검사로, "정보가 동등한가"는 의미 평가로, "해설 트랙이 실제 나오는가"는 재생 조작 관찰로 확인해야 하므로 질문 단위로 방법을 고릅니다.

## C. 권장 실행 순서

1. **상태 복원:** 로컬 URL 초기 상태 확보(실행 제안: 현재 브라우저 도구 없음).
2. **자료 수집:** 후속 제공 예정인 DOM 조작 관찰, 독립 ASR, 소리 분석, 디코드 PNG를 받고 각 자료에 ID·수집 시점·상태(S0~S7)를 붙입니다.
3. **원본 정보 단위 목록화:** PNG·ASR·소리 분석으로 시간순 시각 전용·음성 정보 단위를 만듭니다. 이 단계는 대안을 보기 전에 끝내 편향을 줄입니다.
4. **규칙 검사:** DOM에서 대안 존재, 영상과의 연결, 예외 표시 유무를 확인합니다.
5. **의미 평가:** 대안 내용과 정보 단위를 대응시켜 누락·왜곡·순서 오류를 기록합니다.
6. **조작 기록 확인:** 해설 트랙 전환·대안 열기가 실제 동작하는지 조작 로그로 확인(도구 없으므로 제공 자료 의존, 없으면 '차단').
7. **검토:** 판정마다 증거 ID를 연결하고 가정·반대 증거를 적습니다.
8. **수정 후 재평가:** 수정본에서 동일 정보 단위 목록으로 3~6을 반복합니다.

## D. AI 평가 검증 계획

- **사례 구성:** 정상(모든 시각 정보가 대안에 있음), 문제(오류 문구·코드 표시 등 핵심 단위 누락), 경계(음성이 이미 시각 정보를 대부분 설명해 대안이 불필요할 수 있는 경우, 예외 표시가 모호한 경우, 대안은 있으나 영상과 연결이 불명확한 경우)를 버전별로 둡니다.
- **기준 답 근거 검토:** 기준 답마다 정보 단위 ID와 타임코드, 원본 증거(PNG/ASR) 위치를 적고 두 번째 검토자가 원본에서 독립 재확인합니다.
- **오류 기록:** 오탐(충족을 미충족으로), 누락(미충족을 충족으로), 판단 유보(증거 부족), 실행 실패(자료 읽기 실패·도구 없음)를 별도 열로 셉니다. 판단 유보와 실행 실패를 오답과 섞지 않습니다.
- **반복 일관성:** 동일 입력으로 여러 번 실행해 판정·근거 정보 단위가 일치하는지 기록합니다.
- **재현 노력:** 실행마다 사용한 자료 ID, 읽은 파일 수, 수작업 시간, 사람이 개입한 지점을 기록합니다.
- 아직 측정하지 않았으므로 정확도·비용·평가 완료는 주장하지 않습니다.

|---|---|---|---|---|---|---|---|---|

- 실행 상태: 미실행 · 실행됨 · 실패 · 차단

## F. 바로 준비할 자료 (우선순위)

1. 원본 정보 단위를 만들 자료: 디코드 PNG(타임코드 포함), 독립 ASR, 소리 분석 결과.
2. 전체 DOM과 접근성 트리, 대안 요소 위치.
3. 대안 전문(텍스트 또는 해설 음성 ASR)과 비교 대상 버전 목록.
4. 질문: 영상에 음성 트랙이 있는가? 대안 종류는 무엇인가? "텍스트의 대안" 예외 표시가 의도된 것인가?
5. 브라우저 버전, 확대 설정, 보조 기술 사용 여부.

개인정보·인증 정보 주의: 녹화의 복구 코드가 실제 코드가 아닌 교육용인지 확인하고, 실제 계정 정보·실제 코드·세션 토큰이 담긴 자료는 제출하지 마세요.
