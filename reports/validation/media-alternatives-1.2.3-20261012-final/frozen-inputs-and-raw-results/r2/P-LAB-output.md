# SC 1.2.3 평가 범위와 증거 수집 계획 (P-LAB)

작성 근거: 입력 프롬프트의 "[이번 실행의 실제 입력]"(자료 ID: PLAN-CONTEXT)만 사용했다. URL 방문, 영상 재생·청취, DOM 확인, 사이트 조작은 하지 않았다. 아래 내용은 모두 **계획**이며 접근성 판정이 아니다.

구분 표기: [사실]=입력으로 제공됨 / [가정]=평가자가 둔 가정 / [미확인]=아직 확인하지 않음

1.2.3 적용 조건 관련 확인 질문(원문 확인 필요):
- 영상이 동기화된 미디어(영상+음성)인지, 무음 영상 또는 오디오 전용인지 [미확인]. 유형에 따라 1.2.1이 적용될 수 있음.
- 영상이 텍스트의 "미디어 대안"으로 명확히 표시된 것인지 [미확인]. 그렇다면 적용 제외 조건 검토 필요.
- 대안이 오디오 해설인지, 시간 기반 미디어용 대체 텍스트인지 [미확인].

## B. 상태와 증거 계획표

모든 상태는 **계획한 상태**이며 실제 관찰한 상태는 없다(관찰 0건).

| 상태 ID | 진입·종료 조건 | 사용자 작업 | 후보 WCAG 기준과 적용 이유 | 필요한 증거·도구 | 이미 제공된 자료 | 추가 수집 | 완료 확인 방법 |
|---|---|---|---|---|---|---|---|
| S0 페이지 초기 | 진입: URL 로드 / 종료: 미디어·대안 위치 확인 | 영상과 대안 존재 인지 | 1.2.3: 대안의 존재와 연결 여부가 적용 판단의 출발점 | 전체 DOM, 접근성 트리, 페이지 스크린샷 | PLAN-CONTEXT(설명뿐) | DOM 스냅샷(수집 시점 포함), 접근성 트리 | 영상 요소, 대안 요소, 둘의 관계 표기를 증거 ID로 지목 가능 |
| S1 영상: 보안 설정 장면 | 진입·종료 시각 [미확인] | 장면 정보 이해 | 1.2.3: 이 장면의 시각 정보가 대안에 있는지 | 디코드 프레임 PNG, 독립 ASR 전사, 소리 분석 | 없음 | 장면 경계 타임코드, 프레임, 전사 | 장면 시각 정보 단위 목록 ↔ 대안 문장 대응표 작성 |
| S2 영상: 실패 장면 | 같음 | 오류 정보 이해 | 1.2.3: 오류 표시가 시각 전용(색·아이콘·화면 문구)인지, 음성으로 전달되는지에 따라 대안 필요성이 달라짐 | 프레임, ASR, 소리 분석(경고음 등) | 없음 | 같음 | 같음 |
| S3 영상: 재인증 장면 | 같음 | 절차 이해 | 1.2.3: 화면 조작 시연이 말로 설명되는지 | 같음 | 없음 | 같음 | 같음 |
| S4 영상: 발급 장면 | 같음 | 복구 코드 발급 이해 | 1.2.3: 코드·지시 등 화면 텍스트 정보의 대안 포함 여부 | 같음 | 없음 | 같음. 시연용 코드라도 실제 값처럼 보이면 마스킹 여부 확인 | 같음 |
| S5 영상: 완료 장면 | 같음 | 완료 상태 이해 | 1.2.3: 완료 표시 정보 | 같음 | 없음 | 같음 | 같음 |
| S6 대안 소비 | 진입: 대안 접근 / 종료: 끝까지 읽음·청취 | 화면 없이 대안으로 정보 획득 | 1.2.3: 대안이 원본 정보 단위를 동등하게 담는지, 프로그램적으로 접근 가능한지 | 대안 텍스트 원문, 접근성 트리, (가능 시) 화면 낭독기 출력 기록 | 없음 | 대안 전문, 화면 낭독기 조작 기록 | 정보 단위별 대응·누락 표 |

주의: 스크린샷만으로 화면 낭독기 출력이나 초점 이동을 확정하지 않는다. 화면 낭독기 기록이 없으면 S6의 "접근 가능 여부"는 판단 유보 대상이다. 장면 구분(S1–S5)은 입력의 상태명에서 가져온 가정이며, 실제 경계와 개수는 원본 관찰 후 수정한다.

## C. 권장 실행 순서

1. 상태 복원: 수집 자료의 환경(브라우저·버전·시점)을 S0과 대응. 현재 도구로는 브라우저 실행 불가 → **실행 제안**.
2. 원본 관찰: 디코드 PNG·독립 ASR·소리 분석으로 31초 영상의 시각·청각 정보 단위를 타임코드와 함께 목록화. 음성으로 이미 전달되는 정보와 시각 전용 정보를 구분.
3. 대안 수집: DOM·접근성 트리에서 대안 원문과 영상과의 연결(위치, 라벨, 링크) 확인.
4. 규칙 검사 + 의미 평가: 대안 존재·연결은 구조 확인으로, 동등성(누락·왜곡·순서)은 정보 단위 대조로. 같은 1.2.3 안에서도 질문별로 방법이 다르다.
5. 조작 기록 확인: 화면 낭독기·키보드로 대안에 도달·청취한 기록이 있으면 대조. 없으면 판단 유보로 기록.
6. 검토: 반대 증거(예: 음성만으로 충분히 전달되는 장면)를 검토 후 판정.
7. 수정 후 재평가: 대안 수정 시 같은 정보 단위 표로 재대조.

현재 허용 범위(파일 Read/출력 Write)를 벗어나는 1·5단계의 실기 조작은 이번 실행에서 하지 않는다.

## D. AI 평가 검증 계획

- 사례 구성: 정상(모든 시각 정보 단위가 대안에 있음), 문제(특정 장면 정보 누락·잘못된 내용), 경계(음성이 이미 시각 정보를 설명함, 영상이 텍스트의 미디어 대안임, 대안이 존재하지만 연결이 불명확함)를 같은 영상의 변형으로 만든다.
- 기준 답 검토: 각 사례의 기대 판정에 원본 정보 단위 목록·타임코드·대안 문장을 근거로 붙이고, 2인 이상이 독립 검토 후 불일치를 기록한다. 기준 원문 확인 전에는 확정하지 않는다.
- 결과 분류: 오탐(문제 없는데 미충족), 누락(문제 있는데 충족), 판단 유보(증거 부족 명시), 실행 실패(자료 열기·도구 실패)를 판정과 분리 기록.
- 반복 일관성: 같은 입력을 여러 번 실행해 판정과 근거 정보 단위의 일치 여부를 기록.
- 재현 노력: 실행 시간, 사람이 확인한 항목 수, 추가로 필요했던 자료를 기록.
- 측정 전이므로 정확도·비용·평가 완료를 주장하지 않는다.

## E. 후속 결과 기록 양식

| 상태·환경 | 기준·검사 질문 | 실행 상태 | 판정 | 증거 ID와 위치 | 사용자 영향 | 가정·반대 증거 | 수정 제안 | 재평가 조건 |
|---|---|---|---|---|---|---|---|---|
| 예: S2 / Chromium 1280px | 1.2.3: 실패 장면의 시각 전용 정보가 대안에 있는가 | 미실행 | 미평가 | (수집 후 기입) | (관찰 후 기입) | (기입) | (기입) | (기입) |

- 실행 상태: 미실행 · 실행됨 · 실패 · 차단
- 판정: 미평가(판정 시도 안 함) · 충족 · 미충족 · 해당 없음(적용하지 않는 이유 필수) · 판단 유보(시도했으나 증거·해석 부족)
- 현재 모든 행은 미실행 / 미평가.

## F. 바로 준비할 자료 (우선순위)

1. 원본 영상의 디코드 프레임 PNG와 타임코드 범위 자료
2. 독립 ASR 전사와 소리 분석(음성 외 소리 포함)
3. 전체 DOM과 대안 원문, 영상-대안 연결 정보
4. 영상 유형 확인: 음성 트랙 유무, 텍스트의 미디어 대안 표시 여부
5. 화면 낭독기 조작 기록(가능하면), 환경 버전·수집 시점
6. WCAG 2.2 SC 1.2.3 원문·이해 문서

질문: 대안의 형태(오디오 해설 / 텍스트 대안)는 무엇인가? 자료에 시연용 복구 코드 등 인증 정보처럼 보이는 값이 있는가? 있다면 마스킹 후 제출하고 실제 개인정보·인증 정보는 제출하지 말 것.
