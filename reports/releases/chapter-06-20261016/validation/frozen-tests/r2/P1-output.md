# 실시간 자막(WCAG 2.2 SC 1.2.4) 평가 계획 — 교육 자료 /labs/accessibility/captions-live/ko/

> 이 문서는 평가 **계획**입니다. 접근성 판정(충족·미충족)은 포함하지 않습니다.
> 표기: **[제공]** 입력·첨부 자료에 적힌 사실 / **[가정]** 평가자가 계획을 위해 둔 가정 / **[미확인]** 아직 확인하지 않은 내용 / **[미정]** 입력에서 정해지지 않은 조건.

## A. 평가 범위

| 항목 | 내용 |
|---|---|
| 선택한 이용 과정 | 학습자가 교육 자료의 매체(녹화 재생, 컴퓨터 생성 데모, 가상 방송 관찰 기록)를 보고 ① 1.2.4의 실시간 대상인지 구분하고 ② 대상이면 자막이 필요한 음성 정보를 전달하는지 확인할 증거 계획을 세우는 과정 [제공] |
| 시작 조건 | 로컬 교육 자료와 첨부 `cases-input.json`(L01–L12), `labs-observed.json`, 화면 이미지 2장(replay/generated PNG)을 읽을 수 있는 상태 [제공] |
| 완료 조건 | 적용성, 원음 의미, 화자·중요 소리, 실제 자막 표시와 시간 대응, 자료 출처와 미검토 범위가 계획에 모두 기재됨 [제공] |
| 포함 범위 | ① 녹화 재생 페이지(replay)의 실시간 여부 분류 ② 컴퓨터 생성 데모(generated)의 실시간 여부 분류 ③ 가상 방송 관찰 기록(L01–L08, L12)의 조건부 추론 ④ URL만 있는 입력(L11)의 처리 방식 ⑤ 각 자료의 출처·한계 기록 |
| 제외 범위 | 실제 생중계 감사, 원음 직접 청취, 새 방송 접속, URL 방문, 로그인·폼 제출·업로드·외부 전송, 페이지·설정 변경. 녹화본 자막 내용의 1.2.2 평가는 이 과정의 범위 밖이며 별도 과정으로 분리 [제공] |
| 목표 버전·수준 | WCAG 2.2 A/AA (AA는 A 포함). 중심 기준 1.2.4 Captions (Live) (AA). 4.1.1 Parsing은 2.2에서 삭제되어 제외 |
| 미정인 실행 환경 | 확대(200%·400%) 조건, 화면 낭독기 등 보조 기술 조합, 실제 생중계 시청 환경(플레이어·OS·네트워크), 실제 방송의 원음·영상 [미정] |
| 알려진 관찰 환경 | 로컬 Chrome/Playwright, 960×1000, 390/320 너비 [제공] |

**전체 사이트 평가와의 차이**: 이 계획은 "실시간 자막 교육 자료"라는 한 이용 과정의 매체 분류와 자막 증거 요건만 다룹니다. 사이트 전체의 내비게이션, 다른 페이지, 모든 WCAG 기준의 적합성을 대상으로 하지 않으며, 이 계획의 결과로 사이트 전체의 적합성을 주장할 수 없습니다. 또한 가상 관찰 기록에 대한 결론은 "그 가정 아래에서의 조건부 추론"이며 실재 방송의 감사 결과가 아닙니다.

## C. 권장 실행 순서

1. **상태 복원**: 로컬 자료의 해시(sources.json, 매체 sha256)를 확인해 자료가 수집 시점과 같은지 기록. 새 브라우저 실행은 이번 권한 밖이므로 *실행 제안*으로만 남김.
2. **자료 수집 정리**: 사례마다 evidence_type(observed / hypothetical / missing), 수집 시점(2026-10-16 관찰 기록), 관찰 범위, 시계 기준, 다른 자막 경로 정보를 표로 정리.
3. **적용성 판정 먼저**: 3축(동기화 미디어 / 텍스트 대안 예외 두 조건 / live 정의)을 사례별로 확인. 비대상이 확인되면 내용 평가로 넘어가지 않고 해당 없음 사유를 기록.
4. **규칙 검사와 의미 평가**: 적용 대상에 한해 원음 이벤트와 표시 자막을 ID 단위로 대조(부정어·핵심 지시어, 화자 귀속 필요 여부, 행동에 필요한 비음성 소리, 같은 시계 위 시간 대응과 결정 화면과의 관계). 같은 1.2.4 안에서도 질문마다 방법이 다르므로 "자동 검사 대상 기준" 같은 고정 분류를 두지 않음.
5. **조작 기록 확인**: 폐쇄 자막 켜기·끄기, 오픈 자막 존재 등 다른 경로의 실제 표시 기록을 확인. 한 경로만 관찰된 경우 대안 경로 미확인을 남김. 실제 조작은 *실행 제안*.
6. **검토**: 사례 간 사실 혼입, JSON 필드 간 모순, 출처 ID 실재 여부를 교차 확인.
7. **수정 후 재평가**: 수정안이 의미·비음성 소리·화자·행동 기회를 보존하는지 확인하고, 실제 송출 환경의 동시 기록으로 재평가하는 조건을 기록.

## D. AI 평가 검증 계획

- **사례 구성**
  - 정상: 원음·표시 자막이 같은 시계에서 의미·화자·경고음까지 일치하는 가상 기록.
  - 문제: 부정어 반전, 화자 귀속 누락, 중요 경고음 누락, 결정 시점 이후 표시(기능적 동기화 위반)처럼 한 요소만 바꾼 변형.
  - 경계: 별시계 로그만 있음, 정지화면 1장, 폐쇄 자막 미표시이나 오픈 자막 완전 표시, 텍스트의 미디어 대안 두 조건 충족, 사전 녹화, 완전 컴퓨터 생성, URL만 있음.
- **기준 답 근거 검토**: 기준 답마다 근거 문장을 W3C 원문(source-00/01 등)의 정의·SC 문장과 "그로부터의 도출"로 나누어 적고, 두 명 이상이 독립 검토한 뒤 불일치를 기록. 정보 문서(Understanding, 기법)를 규범처럼 쓰지 않았는지 확인.
- **오류 분류 기록**: 오탐(정상을 실패로), 누락(문제를 놓침), 판단 유보(증거 부족으로 cannot_determine), 실행 실패(JSON 형식 오류, 필드 누락, 금지 enum)를 별도 열로 기록. 판단 유보는 그 자체로 정답일 수 있으므로 기준 답과 대조해 "적절한 유보 / 부적절한 유보"를 구분.
- **반복 일관성**: 같은 프롬프트·입력으로 독립 세션 여러 회 실행해 판정 일치 여부와 근거 차이를 기록. 세션 간 출력은 서로 참조하지 않게 격리.
- **재현 노력 기록**: 모델·설정, 프롬프트 해시, 입력 해시, 실행 일시, 사람 검토 시간, 재실행 횟수를 기록.
- 이 계획 단계에서는 정확도·비용·평가 완료를 주장하지 않습니다. 측정 전입니다.
