# P1 출력 — 실시간 자막(1.2.4) 이용 과정 평가 계획

작성 근거: `P1-filled.txt`의 입력 블록만 사용. 이 문서는 계획이며, 어떤 자료도 이 단계에서 판정하지 않았다. 아래에서 "제공됨"은 입력란에 적힌 사실, "가정"은 평가자가 둔 전제, "미확인"은 아직 읽거나 관찰하지 않은 내용을 뜻한다.

## A. 평가 범위

| 항목 | 내용 |
|---|---|
| 선택한 이용 과정 | 교육 자료 `/labs/accessibility/captions-live/ko/`에서 매체(녹화 재생, 컴퓨터 생성 데모, 가상 방송 기록)를 하나씩 골라 (1) 1.2.4 실시간 대상 여부를 구분하고 (2) 자막이 필요한 음성 정보를 전달하는지 확인할 증거 계획을 세우는 과정 |
| 시작 조건 | 매체가 정지 상태로 로드되어 있고 자막 표시 여부를 아직 확인하지 않은 상태 (제공됨: "녹화본 정지" 상태가 알려진 상태에 포함) |
| 완료 조건 (제공됨) | 적용성, 원음 의미, 화자·중요 소리, 실제 자막 표시와 시간 대응, 자료 출처와 미검토 범위가 각 매체마다 계획에 기록됨 |
| 포함 | 녹화 MP4 재생(실제 동작 자료), 컴퓨터 생성 데모의 대기·재생·알림음 이벤트(실제 동작 자료), 가상 방송 관찰 기록(조건부 추론 입력), L01–L12 사례(cases-input.json) |
| 제외 | 실제 생중계 감사, 새 방송 접속, 직접 청취, 카메라·마이크 사용, 로그인·폼 제출·업로드·외부 전송, 사이트 전체 페이지 탐색 |
| 목표 버전·수준 | WCAG 2.2 A/AA (A와 AA 포함). 4.1.1 Parsing은 2.2에서 삭제되어 제외 |
| 미정인 실행 환경 | 확대(200%/400%) 조건, 화면 낭독기 종류·버전, 실제 생중계 시청 환경, 운영체제 자막 설정. 관찰 환경 중 확정된 것은 로컬 Chrome/Playwright 960x1000 및 390/320 너비뿐 |
| 전체 사이트 평가와의 차이 | 이 계획은 한 이용 과정(매체 분류와 자막 증거)만 다룬다. 사이트 전체의 탐색 일관성, 다른 페이지의 양식, 전체 대표 표본은 다루지 않으므로 이 결과로 사이트 적합성을 주장할 수 없다 |

### 중심 기준과 관련 기준 구분 (가정 포함)

- 1.2.4 Captions (Live), AA: 중심 기준. 동기화된 매체의 **실시간** 오디오 콘텐츠에 자막을 요구. 적용 조건(“live”, “synchronized media”의 정의)은 sources/ 원문으로 확인 예정. 현재는 원문 확인 필요.
- 1.2.2 Captions (Prerecorded), A: 녹화 재생은 실시간이 아닐 가능성이 높아 이 기준으로 넘어갈 수 있음. 분류 근거가 확인되기 전까지는 후보로만 둔다.
- 1.2.1 Audio-only and Video-only (Prerecorded), A: 컴퓨터 생성 데모가 영상 없는 오디오일 경우 후보.
- 1.2.5 Audio Description (Prerecorded), AA / 1.2.3, A: 시각 정보 전달 여부. 이번 이용 과정의 초점 밖이므로 범위 메모만 남김.
- 1.4.2 Audio Control, A: 자동 재생 3초 초과 오디오가 있을 때 후보.
- 2.1.1 Keyboard, 4.1.2 Name, Role, Value: 플레이어 자막 토글 조작이 필요할 때 후보. 화면 낭독기 출력은 스크린샷만으로 확정하지 않는다.
- 1.4.10 Reflow, 1.4.4 Resize Text: 390/320 너비 관찰과 연결되는 후보. 자막 영역이 잘리는지 확인.

## C. 권장 실행 순서

1. **상태 복원 근거 정리**: labs-observed.json의 수집 시점(2026-10-16)과 PNG 2장이 어떤 상태(S1–S6)에 해당하는지 대응표를 먼저 만든다. 대응을 확인할 수 없는 이미지는 "상태 미상"으로 둔다.
2. **정의 원문 확인**: sources/의 W3C 발췌에서 "live", "synchronized media", "captions", 1.2.4 이해 문서의 적용 조건을 읽고, 인용 위치를 증거 ID로 남긴다. 원문이 없는 항목은 "원문 확인 필요".
3. **규칙 검사**: HTML 소스에서 `<track kind="captions">` 존재, 자막 텍스트 요소, 자동 재생 속성 같은 구조 사실을 확인한다. 이 결과만으로 1.2.4 충족을 판정하지 않는다.
4. **의미 평가**: 자막 텍스트와 원음(또는 가상 원음 기록)을 구간별로 대조해 의미·화자·중요 소리 누락을 기록한다.
5. **조작 기록 확인**: 재생·정지·알림음 이벤트가 관찰 기록에 실제로 남아 있는지, 계획한 상태와 대조한다. 새로운 조작은 이번 권한(파일 Read만) 밖이므로 실행 제안으로만 남긴다.
6. **사례별 판정(L01–L12)**: 각 사례의 evidence_type과 자료 내 한계를 따라 판정하고, 가상 입력은 조건부 결론으로 표시한다.
7. **검토와 재평가**: 수정이 이뤄지면 같은 상태·같은 환경에서 재관찰한다. 실제 생중계·보조 기술 조건은 별도 세션 제안으로 남긴다.

허용 범위 밖이라 실행하지 않는 작업: URL 방문, 실제 방송 시청, 직접 청취, 마이크·카메라 사용, 설정 변경, 화면 낭독기 실행.

## D. AI 평가 검증 계획

- **사례 구성**: 정상(자막이 원음 의미·화자·소리를 모두 전달), 문제(대사 누락, 화자 미표시, 중요 소리 누락, 큰 지연), 경계(녹화 재방송을 "라이브"로 표기, 지연 송출, 생성 매체, 오디오 전용 실시간)를 각각 포함한다. L01–L12가 이 세 범주를 어떻게 덮는지는 사례 읽기 후 표로 확인한다.
- **기준 답 근거 검토**: 기준 답마다 인용한 W3C 원문 위치와 사례 자료의 위치를 짝지어 두고, 두 사람 이상이 독립적으로 확인한다. 이번 세션에서는 기준 답을 읽지 않으므로 이 절차는 후속 단계 제안이다.
- **오류 유형 기록**: 오탐(문제 없음을 미충족으로), 누락(문제를 충족으로), 판단 유보(증거 부족을 명시), 실행 실패(파일 읽기 실패, 이미지 해석 불가)를 구분해 기록한다. 판단 유보는 오류가 아니라 별도 범주로 집계한다.
- **반복 일관성**: 같은 프롬프트·입력으로 r1/r2/r3을 독립 실행하고 판정·적용성 분류의 일치율을 비교한다. 이번 세션은 r1만 작성한다.
- **재현 노력 기록**: 실행 시간, 읽은 파일 목록, 사람이 개입한 횟수를 남긴다.
- 측정 전이므로 정확도·비용·평가 완료는 주장하지 않는다.

## F. 바로 준비할 자료 (우선순위)

1. sources/의 1.2.4 및 용어 정의 원문(live, synchronized media, captions)과 출처 메타데이터
2. cases-input.json의 L01–L12 evidence_type과 자료 한계 설명

4. 녹화 MP4 자막 트랙 원문과 원음 전사(없으면 미검토 범위로 기록)
5. 질문: 생성 데모의 내용은 실행 시마다 달라지는가, 고정 스크립트인가?
6. 질문: 확대·화면 낭독기 환경을 후속 세션에서 지정할 계획이 있는가?

자료 제출 시 개인정보(시청자 이름, 계정)나 인증 정보(토큰, 쿠키)가 들어 있는 로그·화면은 제외하거나 가린 뒤 제출하도록 안내한다.
