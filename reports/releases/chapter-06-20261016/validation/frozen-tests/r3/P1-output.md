# 실시간 자막(1.2.4) 평가 계획 — P1 실행 결과 (r3)

> 실행 조건: P1-filled.txt의 프롬프트를 원문 그대로 실행. 이 단계에서는 자료(HTML 소스, MP4 메타데이터, 관찰 기록, PNG, cases-input.json)를 아직 검토하지 않았으므로 **어떤 접근성 판정도 내리지 않는다.** 아래 내용은 모두 계획이며, "제공됨"은 입력란에 자료가 있다고 적힌 사실이지 평가자가 내용을 확인했다는 뜻이 아니다.

## A. 평가 범위

- **선택한 이용 과정**: 이용자가 교육 자료의 매체(녹화 재생, 생성 데모, 가정한 방송 사례)를 보고 ① 1.2.4 적용 대상(실시간 동기화 미디어의 오디오)인지 구분하고, ② 자막이 필요한 음성 정보(대사 의미, 화자, 중요 소리)를 전달하는지 확인할 증거 계획을 세우는 과정.
- **시작 조건**: 로컬 실습 페이지가 초기 상태(녹화본 정지, 데모 대기)로 로드됨. URL 방문은 허용되지 않으므로 평가자는 제공된 관찰 기록으로 이 상태를 대신 확인한다.
- **완료 조건**: 사례별로 적용성, 원음 의미, 화자·중요 소리, 실제 자막 표시와 시간 대응, 자료 출처와 미검토 범위가 계획(이후 결과 양식)에 기록됨.
- **포함**: 녹화본의 정지·재생·자막 상태, 생성 데모의 대기·재생·알림음 이벤트, 가정 방송 자료의 조건들, 해당 매체 과정에서 1.2.4를 중심으로 한 관련 기준의 범위 구분.
- **제외**: 실제 생중계 감사, 사이트 전체 평가, 로그인·폼·업로드, 직접 청취·마이크·카메라 사용, 외부 네트워크.
- **목표 버전·수준**: WCAG 2.2 A/AA(AA는 A 포함). 4.1.1 Parsing은 2.2에서 삭제되어 제외.
- **미정 환경**: 화면 확대, 화면 낭독기 등 보조 기술, 실제 생중계 시청 환경(플레이어·지연·네트워크).
- **전체 사이트 평가와의 차이**: 이 계획은 한 매체 과정의 1.2.4 적용성과 자막 내용·타이밍만 다룬다. 페이지 전체의 대비, 키보드 조작, 제목 구조 등은 관련 기준으로 "범위 구분"만 하고 판정하지 않는다. WCAG-EM 의미의 대표 표본·적합성 주장은 하지 않는다.

## C. 권장 실행 순서

1. **상태 복원**(실행 제안): 로컬 페이지를 초기 상태로 로드. 이번 세션에서는 URL 방문이 금지되어 있으므로 제공된 관찰 기록과 PNG로 대체하고 그 한계를 기록.
2. **기준 원문 확보**: 1.2.4, 1.2.2, "live", "captions", "synchronized media" 정의 원문을 W3C 발췌에서 확인. 없으면 "원문 확인 필요".
3. **자료 수집 대조**: S1–S6에 대해 제공 자료의 식별자·수집 시점(2026-10-16)·해당 상태를 표로 연결.
4. **규칙 검사**(소스 기반): 자막 트랙 존재, `track kind`, 플레이어 설정 등 기계적으로 확인 가능한 항목. 이것만으로 1.2.4 충족을 결론 내지 않는다.
5. **의미 평가**: 원음 의미 대비 자막 내용, 화자 식별, 중요 소리, 시간 대응. 같은 1.2.4 안에서도 "적용성" 질문은 출처·정의 검토, "내용 동등성" 질문은 대본 대조가 필요함.
6. **조작 기록 확인**: 재생·알림음 이벤트 로그와 캡처 시점을 대조. 직접 재생·청취는 이번 세션 범위 밖이므로 실행 제안으로만 남긴다.
7. **검토와 재평가**: 판단 유보 항목의 부족 증거를 명시하고, 자료 보강 후 같은 질문으로 재평가.

## D. AI 평가 검증 계획

- **사례 구성**: 정상(실시간 매체 + 대사·화자·소리 모두 전달), 문제(자막 누락·의미 왜곡·화자 누락·지연 과다), 경계(녹화를 재방송, 사전 대본 기반 생성 데모, 음악만 있는 구간, 자동 자막 오류의 경미/중대 구분)를 균형 있게 둔다. 실제 자료와 가상 조건 사례는 라벨로 구분한다.
- **기준 답 근거 검토**: 각 기준 답에 W3C 원문 위치(정의·Understanding 문서)를 연결하고, 두 명 이상의 검토자가 근거를 독립 확인. 해석 차이는 판단 유보 사유로 기록.
- **오류 분류 기록**: 오탐(문제 없는데 미충족), 누락(문제 있는데 충족), 판단 유보(증거 부족 명시), 실행 실패(파일 읽기·도구 오류)를 서로 다른 칸으로 기록. 판단 유보를 오답이나 정답으로 자동 환산하지 않는다.
- **반복 일관성**: 같은 프롬프트·입력으로 독립 세션 여러 회(r1, r2, r3 등) 실행 후 판정·근거 차이를 비교. 세션 간 출력은 서로 참조하지 않는다.
- **재현 노력 기록**: 실행 시간, 읽은 파일 목록, 수동 개입 여부, 도구 제약을 기록.
- 측정 전이므로 정확도·비용·평가 완료를 주장하지 않는다.

## E. 후속 결과 기록 양식

|---|---|---|---|---|---|---|---|---|

- **미평가**: 판정을 시도하지 않음.
- **판단 유보**: 시도했으나 증거·해석 부족. 부족한 것을 명시.
- **해당 없음**: 적용하지 않는 이유(예: 녹화 매체라서 1.2.4 대신 1.2.2 대상)를 반드시 기재.

## F. 바로 준비할 자료 (우선순위)

1. W3C 1.2.4·1.2.2 성공 기준과 "live", "captions", "synchronized media" 정의 원문 발췌.
2. 녹화 MP4의 출처 설명(원래 생중계였는지)과 메타데이터·해시.
3. 자막 트랙 원문(타임스탬프 포함)과 원음 대본 또는 전사.
4. 생성 데모의 소스(사전 스크립트인지 실시간 입력인지)와 알림음 이벤트 로그.
5. cases-input.json의 사례별 evidence_type와 자료 한계.
6. 질문: 가정 방송 사례에서 허용 지연·오류 범위를 평가자가 어떻게 정할지, 실제 생중계 시청 환경을 추후 확보할 수 있는지.

개인정보·인증 정보(계정, 토큰, 시청자 실명이 담긴 채팅 캡처 등)가 포함된 자료는 제출하지 말고 가린 뒤 제공하도록 안내한다.
