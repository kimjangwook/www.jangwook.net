# チェックリスト

資料のバージョン: 2026-09-12

記事: [AI検索最適化のためのSEO・アクセシビリティ点検と回答検証](https://jangwook.net/ja/blog/ja/ai-search-seo-accessibility-checklist/)

## ページ検査チェックリスト

次のリストを作業文書にコピーして、ページごとに使えます。チェックは、その項目の検討を終えたことを示します。結果は別途、「問題未検出・修正必要・要検討・該当なし・確認不可」のいずれかで記録し、根拠を残します。「該当なし」や「確認不可」には、理由も記載します。

項目の横にある**自動**はスクリプトや検査ツールで確認する部分、**LLM**は資料を提供して意味を検討する部分、**手動**は運用上の意図や画面・動作を確認する部分です。実際の検査は、前述のツールと手順で進めます。複数の方法が表示されている項目では、それぞれの方法が担当する範囲を併せて確認します。「優先」は初回の点検における提案であり、標準の重大度分類ではありません。

### アクセスと主題

- [ ] **A1. 公開の意図に沿ったURLアクセス** (自動 · 手動 · 優先)

  最終的なHTTPステータスとリダイレクト、認証・CDNの制限を記録し、公開の意図と比較します。非公開ポリシーに基づく制限は失敗として扱いません。

- [ ] **A2. titleと主要な見出しの主題の一致** (自動 · LLM · 優先)

  要素の有無と現在の値を抽出したうえで、同じ主題を説明しているか検討します。共通の単語がないという理由だけで、不一致と判定しません。

- [ ] **A3. 本文の要点を正確に含むdescription** (自動 · LLM)

  欠落の有無と長さを記録し、本文の要点を正確に説明しているか、読んで確認します。特定の文字数を検索表示の絶対的な基準にはしません。

- [ ] **A4. ページの意図に沿ったcanonical・lang・viewport** (自動 · 手動)

  正規URL、実際の言語、モバイル表示の設定を確認します。タグが存在するという事実だけで、値まで正確だと判断しません。

- [ ] **A5. 公開ポリシーに沿ったrobotsメタとレスポンスヘッダー** (自動 · 手動 · 優先)

  noindex・nosnippet・max-snippetとX-Robots-Tagを確認し、公開ポリシーと比較します。意図的に設定した制限は自動で解除しません。

### 構造化データ

- [ ] **B1. ページの目的に応じた構造化データの選定** (自動 · 手動)

  ページに必要な機能と採用した規格を記録します。JSON-LDがないという理由だけで、すべてのページを失敗と判定しません。

- [ ] **B2. JSON-LDの構文と採用した型の必須項目の充足** (自動 · 優先)

  パース結果と@context・@type、その型の必須プロパティを記録します。JSON-LDを使っていないページは、該当なしとして残します。

- [ ] **B3. 表示内容と構造化データの事実の一致** (自動 · LLM · 優先)

  タイトル・日付・価格などの表記と単位を正規化したうえで、値と出典を比較します。文言が完全に同じかどうかと、事実が一致するかどうかは区別します。

- [ ] **B4. ページの実際の目的を反映する型と説明** (LLM · 手動)

  型と説明がページの目的に合っているか検討し、無関係な型や表示されていない事実を勝手に追加しません。日付が画面にないという理由だけで、改ざんだと断定しません。

- [ ] **B5. 重複情報の管理元と修正責任** (自動 · 手動)

  CMS・静的HTML・共通テンプレートのうち、情報が生成される場所と修正担当者を記録します。複数の形式で情報が重複しているという事実だけで、検索上の減点があると主張しません。

### 文書とコンテンツ

- [ ] **C1. 文書の階層を説明する主要な見出しと下位の見出し** (自動 · LLM · 優先)

  h1の数、見出しレベル、視覚的な見出しのマークアップを確認します。検出したパターンが適切かどうかは、文脈とチームの記述ルールを基準に判断します。

- [ ] **C2. 冒頭で把握できるページの目的** (LLM · 優先)

  タイトルと最初の段落から、サービス・対象・目的を説明できるか確認します。理解に必要な読書時間を、固定値として想定しません。

- [ ] **C3. HTMLで表現されたリスト・定義・データ表の関係** (自動 · LLM)

  brで列挙した内容には適切なリストを、キーと値の関係にはdlまたは表を検討します。すべてのコンテンツに同じタグを強制しません。

- [ ] **C4. 理解できる表題とヘッダーの関係** (自動 · 手動)

  captionまたは同等の文脈と、th・scope/headersの関係を確認します。複雑な表は、その構造に合った関連付けがされているか検討します。

- [ ] **C5. 重要な数字とともに残る対象・単位・条件・基準日** (LLM · 優先)

  価格・実績・数量のうち、誤解がユーザーの意思決定に影響する事実を選び、文脈を確認します。文脈が十分な固定的な事実に、不要な日付を求めません。

- [ ] **C6. 機械と人が同じ意味で読む日付** (自動 · LLM)

  timeを使っている場合は、datetime値の有効性を確認し、画面の表示値と比較します。すべての日付にtimeの使用を求めません。

### アクセシビリティと情報伝達

- [ ] **D1. 画像の役割に合ったaltの提供** (自動 · LLM · 優先)

  alt属性の欠落の有無と、説明の品質を分けて確認します。装飾画像の空のaltは適切な場合があり、画像が提供されていなければ、説明の正確性は確認不可として残します。

- [ ] **D2. 画像の重要な情報を伝えるテキスト** (LLM · 手動 · 優先)

  グラフ・料金表・案内画像の数値と関係を、テキストでも理解できるか確認します。画面の画像と説明を併せて比較します。

- [ ] **D3. 文脈から明確にわかるリンクとボタンの目的** (自動 · LLM · 優先)

  「こちら」や「もっと見る」のような文言を、検討候補として抽出します。文言だけで判定せず、アクセシブルな名前と周囲の文脈を併せて確認します。

- [ ] **D4. 主要機能のキーボード操作とフォーカスの確認** (自動 · 手動 · 優先)

  実際にTab・Enterを操作して、メニュー・フォーム・ダイアログの動作とフォーカスを確認します。HTMLテキストだけをレビューした結果で、合格と判定しません。

- [ ] **D5. 利用を助けるコントラスト・フォームラベル・エラー案内** (自動 · 手動 · 優先)

  自動アクセシビリティ検査の結果に、画面の確認と実際の操作の検討を加えます。ツールでの合格結果を、WCAG全体への適合と解釈しません。

- [ ] **D6. 対象の取得経路で確認できる主要コンテンツ** (自動 · LLM · 優先)

  初期HTMLとレンダリング後の文書を区別し、タイトル・本文・主要な事実を比較します。JavaScriptを使っていること自体を失敗の理由にしません。

### サイト運用

- [ ] **E1. サービスと目的ごとのrobots.txtポリシーの検討** (自動 · 手動 · 優先)

  学習・検索などの目的と対象ボット、許可範囲、担当者を記録します。ボットを一律に許可する方法で解決しようとしません。

- [ ] **E2. サイトマップと内部リンクによる主要な公開URLの発見** (自動 · 手動)

  サイトマップに意図した正規URLが含まれているか、内部リンクがあるかを確認します。非公開URLや重複URLまですべて含めるよう求めません。

- [ ] **E3. 内部リンクとアセットの正常な動作** (自動 · 手動)

  ディレクトリ一覧と実際のリンクを照合し、意図的な削除と誤検出を区別します。画像とPDFも実際に開いて、正常に動作することを確認します。

- [ ] **E4. ルールの適用範囲と例外の記録** (自動 · 手動)

  新規サイトと運用中のサイトの区別、検査バージョン、担当者を記録します。保留した項目には、理由と再検討日も残します。

### 抽出評価

- [ ] **F1. 基準となる事実の取得と欠落を区別した測定** (自動 · LLM · 手動)

  人が正解を確定したうえで、モデル・質問・抽出条件を固定して評価します。事実の対象・単位・基準日も採点に含めます。

- [ ] **F2. 文書にない事実が生成されていないかの確認** (自動 · LLM · 手動)

  文書にない情報を質問し、根拠のない回答と、わからないという回答を区別します。同じ条件で繰り返し、結果は実際の引用実績と切り分けて解釈します。

### 点検結果を残す形式

問題が見つかった項目は、位置と根拠、次の対応を併せて記録すると、修正担当者が再確認しやすくなります。自動検査やLLMの指摘は、原文と実際の動作を照合してから記録します。チェックした数だけでは、アクセシビリティ全体への適合や、AI検索で引用されるかどうかを判断できません。
```text
検査URL:
検査日 / 担当者:
検査した資料: 初期HTML / レンダリング後のDOM / 画面 / レスポンスヘッダーなど

項目ID:
結果: 問題未検出 / 修正必要 / 要検討 / 該当なし / 確認不可
確認した位置と原文・値:
判断理由:
修正内容 / 担当者:
修正後の確認方法:
```
