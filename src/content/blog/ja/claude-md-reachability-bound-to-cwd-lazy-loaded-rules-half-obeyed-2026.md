学校で配る物の扱いは、渡す時機で変わる。朝のホームルームで配られたプリントは、全員が読む。同じ内容の紙でも、放課後に廊下で手渡されたら、半分の人は読み飛ばす。中身がまったく同じでも、届いた時機によって扱いが変わる。

AIに仕事のルールを守らせる話も、同じ形をしている。AIコーディング助手は、作業の前に置かれた指示文書を読んでから動く。Claude Codeという道具では、その文書の名前はCLAUDE.mdだ。プログラムと同じ場所に置く markdown という形式で書く。内容はいわば家訓だ。この文書をいくら念入りに置いても、道具が読まなければ意味がない。今回は、どこに置いた文書が読まれ、どこに置いた文書が読まれないのかを、合計60回の試験で確かめた。

## ルール文書を置く場所とセッションを開く場所

まず疑問に思うのは、こういう問いだ。文書を置く場所と、作業を始める場所が、別々に決められるのか。

決められる。フォルダは入れ子になっている。家に見立てれば、玄関の下に廊下、廊下の下に部屋、部屋の下に引き出しがある。文書はこの四つのどこにでも置ける。作業 を始める場所も、ルート（一番上のフォルダ）でも、一番深い引き出しでも選べる。

Claude Codeの規則はこうだ。作業を始めたフォルダから、上に向かって順に親のフォルダを見て、CLAUDE.mdという名前の文書を全部集める。つまり、文書がある場所そのものより、作業をどこで始めたかが先に決まる。ルートの文書は、どこで作業を始めても上方向に見える。しかし中間のフォルダに置いた文書は、作業をその下で始めたときしか上に見えない。

もう一つ、名前が条件になる。読む対象はCLAUDE.mdという名前の文書に決まっていて、AGENTS.mdという別の主流の名前は読まない。公式の説明はこうだ。

> Claude Code reads `CLAUDE.md`, not `AGENTS.md`.
> — [Manage Claude's memory (CLAUDE.md) / Claude Code Docs](https://code.claude.com/docs/en/memory)

AGENTS.mdという名前は、AIに仕事の背景知識を渡すための約束事として広まっている。AGENTS.mdの規格の側は、こう位置づけている。

> AGENTS.md complements this by containing the extra, sometimes detailed context coding agents need.
> — [AGENTS.md](https://agents.md/)

つまり、中身を同じにしても、保存するときの名前を間違えたら最初から届かない。名前の選び方自体が、届くかどうかの条件になっている。

## 測定の手順

測定は、当たりか外れかをはっきりさせる形で行った。文書の中に合言葉を書いておき、AIの応答に合言葉が出たら「届いた」と判定する。合言葉が出なければ「届かなかった」とする。各条件ごとに6回ずつ試した。

場所は四つ用意した。文書をレポジトリ（プログラム一式をしまっておくフォルダ）の上の、管理範囲の外側にある親フォルダ、ルート、中間、一番深いフォルダに置く。作業を開始する場所はルートと一番深いフォルダの二通り。この四か所と二通りの組み合わせで、各条件6回ずつ試した。一番深いフォルダの文書は別の性質があるので、合言葉を「聞いて」と頼む方法と、ファイルを実際に開かせる方法の両方で調べた。

誤判定を防ぐための備えもした。どのローダーの対象にもならない名前の偽の文書(NOTES.md)を用意し、それが読まれなければ「外れ」の判定が正しいことの証拠になる。これが判定の正しさを確かめる基準になる。

## 開いた場所が分けた到達結果

結果は、場所そのものではなく、場所と開始位置の組み合わせで決まった。

ルートの文書は、どこで作業を始めても6回全部届いた。レポの上に置いた文書も、6回全部届いた。驚く点は、gitで管理する領域の外側にある文書まで読まれたことだ。読む範囲に境界線があると説明されている場所は、実際の動きでは境界線になっていなかった。

中間の文書は、二つの結果にきれいに分かれた。作業をルートで始めると、0回だった。同じファイルでも、作業を一番深いフォルダで始めると6回全部届いた。0/6と6/6の間で、文書が動いたのではなく、開始位置が動いた。お知らせは、そのフォルダで作業する人にしか目に入らない。中間フォルダで作業を始めなければ、文書があっても通る道がない。

この結果から、届くかどうかは置き場所ではなく、開始位置から上に見えているかで決まることが分かった。

## 遅れて届いたルール文書が受けた扱い

一番深いフォルダの文書は、開始時には読まれない。そのフォルダのファイルが開かれたときに、初めて読み込まれる。これを遅延読み込みと呼ぶ。届け物を、朝ではなく午後に手渡すことに当たる。

まず、到達そのものは起きた。ファイルを実際に開かせた場合、6回全部で文書に到達した。届いた 以上は確かだ。しかし、その文書の扱いが変わった。6回全部で、この文書は「内容を勝手に差し込まれた疑い」と同じ分類になり、文書に書いた指示に従ったのは3回だけだった。

いっぽう、作業の開始時に読み込まれた文書は、36回全部でルールを守り、疑いとみなされた回数は0回だった。中身はどちらも同じ、ごく短い文書一つぶんだ。だが朝に配られたプリントは全員が読み、放課後にもらった紙は半分の人に読み飛ばされた。この道具は紙を移動していない。それでも紙の身分が変わる。

いわゆるプロンプトインジェクションという言葉は、「勝手に届いた指示に背後から動かされる」という種類の警戒を指す。遅れて届いた文書は、全部がこの警戒の枠に入った。および、従ったのは半分だけだった。この数 字は6回という小さな試行に基づくので、正確な割合としては使えない。ただし、開始時と届いた後で扱いが分かれたという向きそのものは、この結果が示している。

偽の文書(NOTES.md)の結果は0回だった。読まれない文書からの反応が一切出ないことの証拠であり、「届かない」という判定が確かであることを支えている。

## codexが一つもデータを残せなかった理由

実験では、別の道具でも机の上の同じ試しをする予定だった。codexという道具である。しかし、codexのための10通りの条件60回の試行は、全部が利用制限によって終了した。AIが返事を出す前に途切れ、合言葉が出るかどうかを判定するデータが一つも残らなかった。

つまり、道具ごとに読み込み方の規則が違うのかを比べることは、今回のデータからは言えない。codex側の測定は未測定のまま残った。この失敗は、比較をしたい人にとっては、実測に入る前の下調べと利用上限の確保が必要だという教訓として残る。

## 結論



AI道具にルールを守らせたいなら、ルールのファイルをどこに置くかよりも、作業をどのフォルダで始めるかのほうが重要だ。そして、作業の途中に読まれたルールは、初めから読まれたルールほど従われない。だから、必ず守らせたいルールは、開始位置から上に見える場所に置くこと。

<div class="lm-card lm-card--takeaway" data-lm-figure="explain-takeaway" data-lang="ja"><span class="lm-card__title">結論</span><p class="lm-card__takeaway">クロードは起動フォルダとその祖先フォルダの指示は常に読むが、下のサブフォルダの指示はそのフォルダで開くかファイルを読んだときだけ読む。codexは今回の実験でまったく応答せず比較できなかった。</p></div>

読者によって、やるべきことが変わる。もし定型的な反復作業のように、いつも同じフォルダから作業を始めているなら、こうする。ルールのファイルが近くにあっても、作業がそのフォルダのファイルを一度も開かないならルールは届かない。従わせたいルールは、開始位置から上に見える場所へ置く。

逆に、サブフォルダを行ったり来たりして自分で作業する場 合は、こうする。サブフォルダのルール文書はファイルを開いたときに到達するが、信頼性は半分程度しかない。絶対に従わせたいルールは上に置き、サブの 文書は参考資料として読ませることに止める。

自己の判断が覆る条件は、こうだ。作業をどこで始めても同じ場所にあるルール文書がいつも同じように届き、作業途中に届いたルールも、初めから与えたルールと同じように守られる場合、この見立ては誤りだというもの。しかし実際の結果は、開始時に届いた文書は36回全部守られ、途中に届いた文書は6回中3回だけだった。現時点でこの見立ては覆っていない。

## この記事が確認できなかったこと

第一に、codexの全試行が利用制限で止まり、道具ごとの差を比べることはできなかった。第二に、「読み込まれたのに無視した」のか「そもそも読まれなかった」のかを区別する手掛かりを集めていない。第三に、遅れて届いた文書が半数に拒否された理由は、今回の試験では切り分けがつかない。届いた時点が理由なのか、ファイルを開く手順が理由なのかは分かっていない。次に確かめるべきは、同じ合言葉を開始時に渡した場合の動きを別のセルとして入れることである。作業をどのフォルダで始めても同じ文書が同じように届き、途中に届いたルールも初めから与えたルールと同じように守られるなら、この記事の考えは誤りだ。
